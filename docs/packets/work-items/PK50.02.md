# Work item PK50.02 — atomic quest snapshots

Implement the legacy 0x02B1 quest-state list and 0x02B2 mission snapshot as one consistent typed journal state. Preserve IDs, active state, objective counts/types, and raw time fields; reject malformed/trailing/oversized arrays without replacing a valid snapshot. Current blockers are recorded in `../evidence/PK50.02-snapshot-model-boundary.md`.

The [2026-11-05 stronger source/model review](../evidence/REVIEW-2026-11-05.md) resolves the selected snapshot boundary. Use 8-byte prefixes with u32 count@4, 5-byte 02B1 rows and 104-byte 02B2 mission rows. Validate exact count/stride and objective count <=3; bounded names are 24 bytes. Keep timestamps as raw server epoch seconds; local timezone formatting belongs only in presentation. Maintain separate ID-keyed quest-state and mission snapshots, correlate either arrival order without discarding the other snapshot, and swap atomically only after whole-array validation. Reject duplicates with a documented policy and test zero/max count, partial rows, reordered snapshots and unknown quest IDs. No Ref clear-before-parse or floor-division behavior. Allocate bounded model/parser and correlation children before UI work; this model no longer requires another stronger-agent decision. Incremental updates/UI remain PK50.03.
