## Adjudicated implementation design — 2026-11-05

Add a read-only monotonically changing operation generation to `CModeMgr`, incremented by both `Switch` and `Quit`. Snapshot around each real router dispatch. On change, mark an explicit mode-operation outcome in `GameModePacketLoopResult` and stop the batch immediately, before another RecvPacket can turn an accepted handoff into apparent EOF. This also protects ban/map handoffs. Do not derive acceptance from closed socket, cleared pending state, or private-mode reads in tests.

Extract a production-used receive/update preamble called by OnUpdate before subsequent world processing. It executes the real packet loop and decides whether the frame may continue. Latch terminal handling per CGameMode lifetime and reset in OnInit. Ordered decision rules:

1. An already-handled terminal outcome or explicit dispatch mode operation stops the frame; do not apply timeout/fallback or overwrite accepted return/exit status. Valid refusal with an open socket is not terminal.
2. Closed socket with a recorded framing error clears the pending disconnect request, clears return-to-char-select intent, preserves the exact failure status, and requests Login once. It never calls Quit and never fabricates accepted return.
3. Closed socket with ordinary EOF and no explicit dispatch operation performs one-shot unexpected-connection-loss recovery to Login; it does not imply a successful quit/return ACK. Preserve any demonstrably earlier terminal operation rather than overwriting it.
4. Open/no-data continues; an expired pending request uses the existing timeout contract only after the receive batch is genuinely drained. Budget exhaustion is not evidence of drain. Existing accepted ACK plus EOF tests must stay passing.

The headless test invokes this exact preamble and observes the mode-operation generation, status, pending state and can-continue result. OnUpdate must use that return to stop before actor/world/audio work; no fully initialized renderer is required to assert the preamble's state transitions. Keep genuine full-frame/rendered acceptance separate. Do not ask for another stronger-agent design pass unless new contradictory source evidence appears.

## Required behavior

1. Distinguish an open connection with no complete packet from terminal connection loss. Unknown opcode and invalid variable length must close/clear exactly as today, with no suffix dispatch.
2. After terminal receive failure, production map update must stop processing the disconnected world and request a safe Login transition with a specific, durable status. Handle ordinary EOF distinctly and consistently with the existing disconnect contract. Error reporting/cleanup must happen once, including repeated update calls before mode-manager handoff.
3. Reconcile an outstanding ReturnToCharSelect/ExitToWindows request explicitly. A framing failure cannot fabricate successful server acknowledgement or accidentally exit Windows. Preserve already-accepted acknowledgement behavior and existing legitimate timeout semantics. Record the chosen transition matrix before implementation.
4. Clear pending request state and reuse existing session/commerce/window teardown at the correct mode lifecycle boundary; do not invent a second partial teardown path. Reconnect must clear the transport error and permit valid traffic.
