# PK32.05 — legacy mail verification

The selected client uses legacy mail for 20080910. The newer `09F0` family has a separate profile and remains open. The old scope note predates the current model. On the selected wire, `024A` is a new-mail notification and `0255` is a draft staging result. `0245` reports a claim. [Selected wire contract](../contracts/PK32.LEGACY-MAIL-STATE.md)

- `023F` refresh and `0241` read are exercised by `MailInboxProductionReplay`, including the server-open path, fragmented list, bounded fields, and keyed missing-read result.
- `0243` delete and `0273` return use the same replay. It checks literal request bytes and matching result ownership, refusal, timeout, close/reopen and a late unowned reply.
- `0244` claim uses the same replay. It checks partial and two-success delivery signalling, stale selection, capacity refusal, and readback initiated before and after terminal acknowledgement.
- `0247` stage and remove use `MailDraftAttachmentProductionReplay`. It checks exact slot and quantity, wrong-index and refused replies, an unchanged inventory at stage time and a late staging reply to a closed composer. The selected parser rejects Zeny staging. [Selected server branch](PK32.04.md#pk3204-legacy-mail-staging)
- `0246`, `0248`, and `0249` have separate composer, send and result replays. Map-transition replay checks attachment claim and removal ownership across same-connection warp and map-server reconnect.

Run the application packet replay and `python tools/tests/check_commerce.py --mail-only` with the matching MinGW and Qt runtimes and the local asset installation. The focused Vulkan/Qt check draws the composer and drives item drag, quantity entry and removal through the Windows input route with a loopback capture. The acknowledgement is injected through the production router.

The deployment-disabled application and replay targets built, both CTest cases passed, and the focused Vulkan/Qt check captured `4702020003000000` followed by `4702020000000000`. The composer displayed the acknowledged quantity and the inventory retained its original count. The focused check uses the installed assets with an isolated configuration and loopback connection.

Deployed verification still needs character-server delivery, Zeny receipt and inventory deltas, bank and inventory capacity, unread refresh timing, physical inbox interaction, return refusal, and service silence.
