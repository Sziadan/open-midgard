# Work item PK05.02 — fail closed when framing cannot be established

Complexity: **S** (risk classification only; no mandatory model or prior approval). Owner: current implementation agent; PK48 reviews independently after implementation.

## Decision

Keep the active profile's existing fixed/variable size table as the sole source of recognized frame boundaries. When an opcode is absent from that table, its packet length cannot be established. When a table-known variable packet declares a length outside 4–32767, its frame boundary is invalid. In either case, close the transport and clear queued bytes; do not discard two bytes and scan arbitrary payload. The stream provides no safe resynchronization marker or server-defined universal recovery rule.

This conservative failure policy avoids delivering an accidental frame. It is a client recovery choice, not a claimed rAthena protocol response. PK05.03 will make error propagation/cleanup/reporting explicit. Known valid frames continue to use profile-table lengths and retain incomplete prefixes; valid concatenated frames remain aligned.

## Scope and files

- `src/network/Connection.cpp`: replace unknown and malformed-variable rescan with disconnect/return.
- `tools/tests/replay/PacketStreamReplay.cpp`: exercise production receive behavior for coalesced and fragmented unknown/invalid headers with a valid frame suffix.
- `docs/packets/contracts/PK05.UNKNOWN-OPCODE.md`, `docs/packets/evidence/PK05.02-replay.md`, `.jsonl`, and tracker files.
- Do not alter packet registrations, feature handlers, stage-specific PK04 raw AID state, or user-visible UI in this step.

## Acceptance

- Every existing recognized fixed/variable framing case remains aligned.
- Unknown opcode closes without emitting the following valid suffix as a frame.
- Variable lengths below 4 and above `0x7FFF` close without emitting suffix bytes.
- Fragmented unknown and malformed headers remain buffered until enough header bytes arrive, then close deterministically.
- Disconnect clears queued bytes and leaves the connection closed.
- Fresh deploy-off build and focused production replay pass; record executable hash/time and exact JSONL.
- Separate commit: `packet(PK05.02): close on unknown framing boundaries`.

PK05.03 remains responsible for typed protocol-error propagation and reporting semantics. No packet discovery row closes here.
