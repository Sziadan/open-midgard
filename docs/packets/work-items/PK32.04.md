# PK32.04 — legacy delete/return and compose results

## PK32.04-LEGACY-MAIL-REMOVAL

The Qt inbox sends `0243` for an opened message with no remaining attachments, and `0273` to return an opened message to its sender. Both operations require confirmation. The selected 30-byte return frame preserves the original 24 wire bytes from the detail's sender field, as in the reference sender. The selected server uses the sender stored with the message. System mail can be refused by the server.

The client keeps the row until a matching `0257` or `0274` success or an authoritative inbox snapshot. Failed replies leave the message in place. A read cannot overlap a return because missing reads also use `0274`. A pending operation survives inbox close/reopen and a same-connection warp. Connection replacement clears it. The timeout permits refreshing the snapshot but keeps outcome and reply ownership pending until the matching server result or reconnect.

The replay covers exact request bytes, wrong-family and wrong-ID replies, delete denial, return and delete success, late unowned replies, and reopening after timeout. Verify both operations and system-mail refusal against the deployed character server. Attachment staging during compose remains open.

## PK32.04-LEGACY-MAIL-STAGING

The Qt composer uses the existing inventory drag and quantity prompt to stage one item. The eight-byte `0247` carries wire inventory index at offset 2 and quantity at offset 4. The five-byte `0255` result must match the pending index. Staging shows the accepted quantity without modifying inventory. The server performs inventory removal during mail submission. Clear and close send the reference type-zero `0246` draft reset. A generic send refusal can occur before or after the server clears the draft, so remove or reset the previous attachment before resending. Same-connection warps keep server draft ownership, and the next composer opening resets it. While a draft survives a warp, inbox requests that could clear it are blocked.

In the selected rAthena `src/map/clif.cpp`, `server_index` returns unsigned `client_index - 2`. `clif_parse_Mail_setattach` rejects `server_index(idx) >= MAX_INVENTORY` before calling `mail_setitem`. Wire index zero therefore returns silently before reaching the Zeny branch in `src/map/mail.cpp`. The bundled 2011 eAthena reference checks the amount and then accepts index zero, so its Zeny behavior belongs to a different server profile. A server fix and live validation are prerequisites for enabling outgoing Zeny in the selected profile. Receiving Zeny remains owned by the existing claim path.

Replay checks the request bytes, index-zero and stale-item rejection, no inventory mutation at staging, acknowledgement matching, close/reset, and the reset required after a failed send. Verify live inventory consumption, failure refunds, physical inventory drag and installed rendering.
