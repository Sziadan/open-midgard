# Work item PK48.01 — certification review scope

Define the bounded certification work before independent review begins. Do not certify packet parity or close rows in this step.

## Inputs

- `docs/PACKET_IMPLEMENTATION_PLAN.md`: authority hierarchy, selected profile, safe replay/build rules and review gates.
- `docs/packets/work-packages.json`, `state.json`, `coverage.csv`, `finding-ownership.json`, and `ignored-ownership.json`: package dependencies, current progress, and row ownership.
- `docs/packets/contracts/INDEX.md` and each linked canonical contract; package evidence under `docs/packets/evidence/` and current `STATUS.md`/`HANDOFF.md`.
- Runtime source at the recorded baseline and the hash-pinned authoritative rAthena source snapshot/configuration from PK01.02. Ref is behavior reference only.
- Production replay harness and independent byte fixtures. Preserve `tools/tests/replay/PacketStreamReplay.cpp` ownership; do not consume or edit its current uncommitted change without ownership resolution.

## Review scope and evidence

1. Build an inventory of every implementation leaf and its readiness: completed with evidence, explicitly deferred/blocked, or not started. Include PK44–PK47, PK50 and prior feature packages. Treat a completed package label as a pointer to evidence, not proof.
2. For each ready contract, independently derive opcode, direction, selected 20080910 guard, length, offsets, signedness, optional branches, parser/emitter behavior, and lifecycle/reset semantics from authoritative server source. Compare Ref only for original-client behavior.
3. Verify each implementation with an independent byte oracle and production framing/routing/handler path, including malformed, partial, coalesced, error, and lifecycle cases appropriate to the contract. Do not bless self-generated fixtures as independent evidence.
4. Run a fresh deploy-off build and only relevant production replay/UI acceptance paths. Record exact commands, result, source revision/hashes, fixture provenance, and any platform/permission boundary.
5. Reconcile coverage/finding/ignored rows only when the contract, implementation branch, independent bytes, and required lifecycle behavior are evidenced. Keep unsupported variants and unresolved deployment provenance open.

## Result record

For each reviewed unit record: package/step and row IDs; authoritative source revision/hash and config; Ref evidence used; opcode/direction/length/field/branch contract; implementation path and commit; independent fixture provenance; build/replay/UI commands and outcomes; malformed/lifecycle results; remaining uncertainty; row decision with evidence link. Summary counts must distinguish verified, partial, deferred/blocked, and unreviewed. Never claim 100% coverage from aggregate counts.
