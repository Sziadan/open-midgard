## Objective

Arm an expected four-byte raw AID prefix only for the newly connected character server and before sending its first `0x0065`. The production receive path must wait for all four bytes, decode little-endian, compare the full expected account ID, consume them once on match, and then return subsequent opcode-framed packets normally. A mismatch or truncated EOF must close/reset the connection and follow existing LoginMode disconnect cleanup. Account-server and map-server connections retain ordinary packet framing. Remove the fake `0x8482`/`0x8483` receive sizes and their silent LoginMode cases.

## Authoritative source behavior

Selected server `src/char/char_clif.cpp::chclif_parse_reqtoconnect` reads the AID from request `0x0065`, then sends exactly four raw little-endian `account_id` bytes before running/auth checks; later rejection is framed `0x0081`. `PACKET_CA_ENTER` is 17 bytes: opcode u16@0, AID u32@2, login_id1 u32@6, login_id2 u32@10, unused u16@14, sex u8@16. The prefix has no opcode or length.
