## Server contract

- `0x0156` is variable length with 4-byte packet header and 12-byte rows: account ID, character ID, position ID. See `src/map/packets.hpp` `PACKET_ZC_ACK_REQ_CHANGE_MEMBERS` and its emitter in `src/map/clif.cpp` around `clif_guild_memberpositionchanged`.
- `0x0160` carries position ID, mode/permission bits, ranking and pay rate in 16-byte rows. Server `clif_guild_positioninfolist` emits all configured guild positions.
- `0x0166` carries position ID plus 24-byte name in 28-byte rows; server `clif_guild_positionnamelist` emits the list.
- `0x0174` is a 40-byte position update row (position ID, mode, ranking, pay rate, 24-byte name), with a 4-byte variable packet header. `clif_guild_positionchanged` sends the updated position.
- `0x016C` is the selected 43-byte guild membership update. Fields are guild ID at offset 2, emblem version at 6, local permission mode at 10, master flag at 14, inter-server ID at 15, and guild name at 19. Its `mode` comes from the member's current guild position; permission bits in selected rAthena are invite `0x001` and expel `0x010`.

## Client change and verification

`HandleGuildWindowPacket` already refreshes the local title from the local member's position after guild window packets, but it did not refresh `m_localGuild.permissions`. Consequently an incremental `0x0156` rank change or `0x0160`/`0x0174` position-mode update could leave Qt permission gates using the prior rank's permissions even though `0x016C` initially supplied correct local mode. Added `FindLocalPosition` to resolve mode and title from the updated member/position state, and the production handler updates both fields together when both records are known. `GuildWindowTests.cpp` now covers position resolution after member position change and later position permission/name update.

The test fixtures are synthetic field-by-field values based on the server layouts above; they do not use client packet structs as expected-byte generators. This bounded implementation does not add buffering for a member-position update arriving before the corresponding member record, and it does not certify visible Qt interaction or discovery-row closure. PK11.03 covers permission-gated Qt controls; PK11.04 owns broader replay/lifecycle review.
