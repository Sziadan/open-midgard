# PK45.03 — equipment inventory list variants

Date: 2026-11-04. Status: client layouts and inventory/appearance replacement path traced. Selected-server variant use and replay remain open. No rows closed.

## Active variants and fields

The current receive profile maps equipment inventory lists to 0x00A4 basic, 0x01EF timed, and 0x02D0 timed-owned. All are variable-length framed packets; selected entry strides are 20, 24, and 26 bytes. The common record contains item index u16@0, item ID u16@2, item type@4, identified@5, allowed location u16@6, wear location u16@8, damaged@10, refine level@11, and four card slots u16@12..19. Entries are modeled as one item. The 24-byte form adds delete time u32@20; the 26-byte form adds `isYours` u16@24. Item index 0 is rejected.

## Replacement and local appearance

`HandleEquipInventoryList` requires the four-byte list header and an active packet/entry-size profile, then calls `ClearEquipmentInventoryItems`. That session method removes prior inventory rows with nonzero allowed location, while preserving ammunition rows (types 10, 16, 17) because they arrive in the stackable list. The handler processes complete records from offset 4, adds each through `AddInventoryItem` (merging by item index and incrementing count), rebuilds player equipment appearance from the resulting inventory, and syncs appearance to the local actor. Empty equipment lists therefore clear the old equipment rows and rebuild appearance; any trailing partial entry is ignored after the clear.

## Selected server equipment-list fields (2026-11-04)

For the selected 2008 profile the server uses `0x02D0` for variable equipment-list packets (`PACKETVER >= 20080102`). `clif_inventorylist` puts non-stackable/equippable inventory records into this packet family and sends each nonempty group to SELF. The row builder fills client index and item ID/type, identification and damaged flags (for packet versions before 2012), allowed equipment location, current wear-state bits, refine level, card slots, expire date, and bind-on-equip type. At the selected 2008 version, visible sprite number is not included by the later-version branch.

This establishes the selected packet family and server field sources. The client's interpretation of location versus actual worn state, duplicate equipment indices, and appearance replacement still need replay/fixture validation. No discovery row is closed.


## Partial-row rejection and replacement boundary

The equipment-list handler now checks that (packetLength - 4) is an exact multiple of the active row size before calling ClearEquipmentInventoryItems; malformed trailing partial rows return without replacing inventory (src/gamemode/GameModePacket.cpp:2257-2275). A valid four-byte empty list remains accepted, clears equipment rows, and proceeds to appearance rebuild/synchronization. CSession::ClearEquipmentInventoryItems preserves ammo entries with item types 10, 16, and 17 while removing other inventory entries with an equipment destination (src/session/Session.cpp:1497-1509). This avoids partial-prefix replacement on truncated snapshots while preserving ammo and the existing equipment appearance refresh path. Release target open_midgard built after the change; replay cases for partial lengths, empty lists, ammo preservation, and appearance rebuild were not run.
