# PK50.01 — quest journal and mission lifecycle scope

## Legacy candidate contracts

- Current client framing knows 0x02B1 and 0x02B2 as variable length; both route to `HandleIgnorePacket`. 0x02B3/0x02B4/0x02B5/0x02B7 currently have no targeted framing or production handler.
- The selected P01 registry lists candidate 0x02B1/02B2 variable, 0x02B3 length 107, 0x02B4 length 6, 0x02B5 variable, 0x02B7 length 7. It also has 0x02B6 length 7 as client-to-server quest state request/ack (`clif_parse_questStateAck`); this related request must be included in behavior review.
- Available rAthena sender comments define legacy 0x02B1 all-quest list as `{quest ID u32, active u8}` records; 0x02B2 mission list as `{quest ID u32, start time u32, expire time u32, objective count u16, three {mob ID u32, mob count u16, 24-byte name}}` repeated records (104 bytes per mission in that sender). 0x02B3 add-quest is 107 bytes with a similar mission body; 0x02B4 removes one quest ID; 0x02B5 carries repeated mission kill updates; 0x02B7 is 7 bytes with quest ID and active state.
- In that sender, start/expire fields are cast from quest time values to u32; exact epoch/time interpretation and target-2008 profile must be adjudicated before timers or expiry display are implemented.

## Version variants and active source boundary

- The available server source has PACKETVER branches that replace legacy 0x02B1 quest list with 0x097A and then 0x09F8 layouts; 0x08FE and 0x09F9 are newer mission progress/add variants. They cannot be merged into the legacy layout by opcode-family resemblance.
- 0x02B6 is a client request path and 0x02B7 a server active-state result; new/add/remove/progress emitters must be traced so active state and journal ordering are coherent.
- The available sender source is not identity-matched to the deployed 2008 server build. Newer variants are explicitly conditional, not proof that they are active in the target profile.

## Bounded leaves and invariants

1. PK50.02: implement snapshot/list parsing atomically, preserving quest ID, active state, objective counts and objective types. Reject truncated/oversized arrays without replacing the current journal.
2. PK50.03: implement add/remove/status/kill progress updates and Qt journal/actions; handle duplicate/reordered events, unknown IDs, expiry units, map changes, disconnect/reconnect, and local activation requests.
3. PK50.04: verify order, time conversion, duplicate/malformed arrays, completion/rejection and teardown/reconnect through production packet replay and journal UI lifecycle. PK48 remains independent review.

No audit row is closed by this scope checkpoint.
