# PK37.03 trade cancellation

The selected `20080910` server uses nine-byte `01F5` for invitation responses (`src/map/packets.hpp:382–388`). The result byte is followed by the partner ID and level. `trade_tradeack` sends result 4 to both peers on decline. `clif_parse_TradeCancel` routes the two-byte `00ED` request to `trade_tradecancel`. That function sends the two-byte `00EE` response for both pending and active trades. For active trades it first sends the virtual item returns and any Zeny status update (`src/map/trade.cpp:520–578`).

The client keeps ownership of the trade after sending cancel or decline and hides its window. While cancellation is pending it rejects another local trade and keeps the window closed if acceptance crosses the request. `00EE` retires a cancel. A decline can complete on the invitation response or a server cancellation. Send failure keeps the existing trade state. Map teardown clears the pending state through `CloseTransactions`.

The loopback replay covers failed sends, exact decline and cancel requests, duplicate cancellation, crossed acceptance, and the terminal response.
