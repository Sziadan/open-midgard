# PK44.04 — Verify the 0x01DB password-hash request gate

Date: 2026-11-04. Status: default America path and explicit `ForcePasswordHashRequest` branch verified through the production ConnectAccount state.

## Source and client path

The selected login server registers fixed two-byte `0x01DB` and routes it to `logclif_parse_reqkey`, which generates the subsequent hash challenge. The client sends `0x01DB` in `CLoginMode::OnChangeState(ConnectAccount)` when `ForcePasswordHashRequest` is nonzero, or when the `g_passwordEncrypt` service value is nonzero. Otherwise it sends the configured account-login request directly.

## Replay

The ConnectAccount replay uses an isolated temporary INI, an America profile, synthetic credentials, and a localhost account listener. The default `ForcePasswordHashRequest=0` case emits `0x0064`; the explicit `ForcePasswordHashRequest=1` case emits exactly `db 01` and enters the production “waiting for account hash challenge” status. The `0x0200` and `0x0204` cases continue to run alongside these checks. No challenge response is supplied by the mock.

This verifies the configured request gate and serialization only. The Ref request/reachability path, external `passwordencrypt2` value, deployed service profile, and actual server challenge behavior remain unresolved. No discovery rows were closed.
