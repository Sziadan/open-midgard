# PK16.02 — profile and implementation boundary

> Current disposition — 2026-11-05: Selected-source configuration IDs, negative disable-call polarity and 02DA equipment-visibility meaning are resolved in the primary review. Implement confirmed-state parsing first and bounded pending/control behavior next; deployed profile remains a separate acceptance question. See [second review](REVIEW-2026-11-05.md).

## Evidence gathered

- The audited target client has a fixed 10-byte receive length for 0x02D9 and a handler registered as `HandleIgnorePacket`; 0x02DA is fixed at 3 bytes and also ignored. No 0x02D8 client framing entry, request serializer, or setting-control call site was found in the targeted client searches.
- Selected server registry evidence maps 0x02D8 to length 10 and `clif_parse_configuration`, with fields at offsets 2 and 6. P01 identifies server source in an external rAthena checkout, but its `.git` identity is inaccessible here.
- The available server source snapshot dated 2026-10-29 contains a candidate `e_config_type` enum (0 equipment window, 1 call, 2 pet autofeed, 3 homunculus autofeed, 5 disable costumes). Its parser consumes a 32-bit type and boolean, may reject pet/homunculus changes without acknowledgement when unavailable, and otherwise sends 0x02D9 with type/value. The snapshot is not established as the exact 2008 target branch/profile.
- No corresponding local UI model or persisted preference mapping was found for these settings.

## Decision

Do not implement guessed setting IDs, packet sends, or optimistic UI behavior. Exact client/server profile identity, 0x02DA meaning, and real control/request call sites are prerequisites to a reliable implementation. PK16.02 is deferred for stronger source/profile adjudication. PK16.03's social-path audit is independent and may proceed. No audit row closed.
