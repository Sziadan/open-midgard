# PK36.01 storage password applicability

The selected rAthena source at `PACKETVER=20080910` registers `023A` (four bytes), `023B` (36 bytes), and `023C` (six bytes) in `src/map/clif_packetdb.hpp:567–569`. The declarations in `Ref/dhxj/packet.h:8873–8891` agree with the selected server's field offsets.

- `023A` carries a 16-bit info value at offset 2. Values 0, 1, and 8 indicate unset, protected, and penalty states.
- `023B` carries a 16-bit change/check operation at offset 2 (2 or 3), with 16-byte fields at offsets 4 and 20. The field widths give no evidence of the transform used by a server that implements this feature.
- `023C` carries a 16-bit result and 16-bit error count. Values 4–8 cover change success/failure, check success/failure, and penalty.

`src/map/clif.cpp:13745–13792` defines both outbound emitters without any callers under `src`. Its registered `clif_parse_StoragePassword` body has only commented-out code. The ordinary script `openstorage` calls `storage_storageopen`, which checks access, opens storage, and sends inventory lists and counts directly (`src/map/script.cpp:10966`, `src/map/storage.cpp:133–151`). This is an inactive feature family in the selected server source.

Keep the server frames recognized so their bytes can be consumed. The current client has a notice/log fallback. An interactive password flow requires a server with an active challenge emitter and parser plus evidence of the credential transform.
