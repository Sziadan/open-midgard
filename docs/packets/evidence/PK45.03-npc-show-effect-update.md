# PK45.03 — NPC show-effect state update 0x028A

Date: 2026-11-04. Status: fixed framing, field reads and conditional actor/effect behavior traced; effect-state semantics and selected-profile contract remain open. No rows closed.

Opcode 0x028A is registered at fixed size 18 and routed to `HandleNpcShowEfstUpdate`. The handler requires data and at least 18 bytes, then reads actor ID u32@2, incoming effect state u32@6, level u32@10 and show-effect flags u32@14. It resolves the actor via `ResolveSkillPacketActor`; unresolved IDs return. The handler does not validate the packet ID locally.

If level is 99 and the incoming effect state does not contain `kEffectStateSpecialHidingMask`, the actor receives message 126. For the effect launch check, the handler reads the actor's current `m_effectState` (it does not assign the incoming effectState field), and considers the actor hiding when the current state has either `kEffectStateHidingMask` or `kEffectStateBurrowMask`. It launches effect 375 only for PC actors who are not hiding, whose incoming show-effect flags contain `kShowEfstAssumptioMask`, and who do not already have effect 375. No other actor state is changed here; no reply is sent.

## Selected server NPC effect-state update (2026-11-04)

The selected server emits fixed `0x028A` from `clif_changeoption2` only when the actor has a status-change record. It fills actor GID, `sc->option`, computed level, and `sc->opt3`, matching the client's four-u32 field reads. Normal actors are sent in AREA. Disguised actors use AREA_WOS first, then a SELF packet with the disguised GID, then another SELF packet with the real GID and `OPTION_INVISIBLE` state.

This establishes server field provenance and a multi-packet disguise path relevant to the client's current-versus-incoming effect-state behavior.
