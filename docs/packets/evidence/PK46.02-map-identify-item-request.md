# PK46.02 — identify-item selection/cancel request

Date: 2026-11-04. Status: request and selected-server decision paths are source-traced; production sender replays now cover cancel and positive selection. Server result parity and runtime UI behavior remain open. No discovery row is closed.

`UIItemIdentifyWnd::SubmitSelection` sends the selected item index through `GameMsg_RequestIdentifyInventoryItem` and closes the window. `CancelSelection` sends signed index `-1` through the same message and also closes the window. The client sender validates nonnegative indices against the inventory and rejects missing, zero-index, or already-identified items; negative values bypass that local item check and are sent as signed values. It serializes `PACKET_CZ_ITEM_IDENTIFY` and does not wait on a client-side acknowledgement flag.

All configured map gameplay profiles use opcode `0x0178`. The packet is four bytes: opcode u16@0 and signed item index i16@2. The selected 20080910 registry uses `HEADER_CZ_REQ_ITEMIDENTIFY`, `sizeof(PACKET_CZ_REQ_ITEMIDENTIFY)`, and `clif_parse_ItemIdentify`; the final registry records `0x0178`, length 4.

The server ignores the request unless `menuskill_id` is `MC_IDENTIFY`. It converts the signed index through `server_index`; invalid/missing/already-identified items (including the cancel sentinel through that invalid-item path) clear work-in-progress and the menu skill, then return without an identify acknowledgement (`src/map/clif.cpp:13427-13448`). For a valid item, `skill_identify` marks it identified, emits `clif_item_identified`, and then invokes the identify NPC event (`src/map/skill.cpp:10553-10573`). That server file SHA-256 is `F9AAC46FDC14D36F9B018EB3CD52A39C790FE3B23923E657B5F3CA6C3F6F2982`; it was not listed in PK01.02 input hashes, and the server directory has no Git revision metadata. The `PACKET_ZC_ACK_ITEMIDENTIFY` response is a packed 5-byte `0x0179` frame with client index u16@2 and result u8@4 (`src/map/packets.hpp:1127-1132`; this file hash matches PK01.02). The client registers `0x0179` to `HandleItemIdentifyAck`; result 0 marks the matching inventory item identified, refreshes dependent windows, and posts success text, while nonzero posts failure text (`src/gamemode/GameModePacket.cpp:1445-1466`). The request/result path is source-traced, but no independent byte fixture, production replay, or visible-dialog acceptance was run; no discovery row is closed.
