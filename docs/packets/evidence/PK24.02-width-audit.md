# PK24.02 — signed width and resource math audit

## Findings and fix

- 0x00B0/0x00B1 status parameter values enter through `u32`. `CharacterVitals` and the live player HP/SP fields are `u32`; `AddVital` saturates at UINT32_MAX and `VitalBarFill` uses 64-bit math. The legacy selected-character record uses signed 16-bit HP/SP fields capped at 32767; authoritative runtime/session vital state remains full-width. This display cap is retained.
- 0x00BC status-change acknowledgements carry a one-byte resulting primary stat value; the handler reads the wire byte and updates the 8-bit STR/AGI/VIT/INT/DEX/LUK fields. 0x00BE point-cost values are one byte. No widening is inferred for these wire contracts.
- EXP was narrowed: the status handler read packet values as `u32` then cast to signed `int`; session setters also accepted/stored `int` and clamped negatives to zero. Values above INT_MAX could become negative and display as 0%. `CGameActor::m_Exp` used the same signed type.
- Fixed the EXP path end-to-end to retain `u32` in actor/session fields and setters. Added `TryExperiencePercent` with 64-bit multiply/divide and 0..100 cap; zero next-value remains unavailable. The conversion no longer treats a valid high unsigned value as negative.

## Verification

- `python tools/tests/check_high_vitals.py` passed, including UINT32_MAX EXP values, a value above INT_MAX, zero denominator, full-width HP/SP, and existing bar/recovery boundaries.
- `cmake --build --preset build-mingw-qt-x64 --target ro_gamemode -j 6` passed, compiling the changed session and game-mode targets.
