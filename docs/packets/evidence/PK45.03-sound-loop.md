# PK45.03 — sound packet and loop lifecycle

Date: 2026-11-04. Status: fixed framing, action parsing and loop lifecycle traced; sound-name path handling and server semantics remain open. No rows closed.

The size table fixes 0x01D3 (`ZC_SOUND`) at 35 bytes and the router maps it to `HandleSound`. The handler requires at least 35 bytes, reads a NUL-bounded filename from bytes 2–25 (maximum 24), action byte@26, duration u32@27, and actor AID u32@31.

Action 0 plays once: when both actor and local player resolve it passes player-minus-actor X/Z as the relative sound position, otherwise it plays at the origin. Action 1 stores a copied filename, duration, AID and `endTick = now + duration` in `m_playWaveList`, then plays once at the origin. `ProcessPlayWave` revisits each entry when `now >= endTick`, plays relative to the actor if AID and local player resolve (or at origin for AID zero), and advances `endTick` by duration; entries therefore loop until removed. Action 2 removes the first entry with the same filename; it does not match by AID or stop an already playing sample. Unknown actions do nothing. Playback return values are ignored.

Open work: validate action codes, duration units/zero behavior and filename encoding against selected server evidence; inspect `PlayWaveRelative` asset lookup/path normalization before trusting packet names; replay one-shot/loop/stop, duplicate filenames from different actors, missing actors, zero/large durations and malformed/non-NUL names, checking cleanup on map/session teardown. No independent fixture or production replay was performed for this leaf.

## Sound resource lookup follow-up (2026-11-04)

The packet handler passes its NUL-bounded sound name to `PlayWave`. `PlayWave` gates on sound enablement and a nonempty name, then calls `CAudio::PlayWaveRelative`. That function looks up `CWave` with `g_resMgr.GetAs<CWave>(name)` and returns false when the resource or decoded file image is unavailable. The name is passed unchanged to this lookup and later to the audio backend; the BGM-only `NormalizeAudioPath` helper is not called on this SFX path (`src/audio/Wave.cpp:6-17,21-48`; `src/audio/Audio.cpp:192-201`).

This narrows the source behavior: packet data selects a resource by its bounded name, and missing resources fail playback without changing loop state. It does not establish whether the resource manager normalizes keys internally, whether arbitrary path forms can escape the intended resource namespace, or whether the server uses the same filename encoding. Those require resource-manager implementation review and selected-source/capture evidence. No discovery row is closed.
