# PK46.02 — time-sync request profile branches

Date: 2026-11-05. Status: automatic caller/timer, client frame layouts, selected server parser and immediate time-notification response are source-traced. Deployed profile choice and retry/late-response replay remain open; no discovery row is closed.

## Current client path

`SendTimeSyncRequest` is called during map bootstrap and the regular map update loop. Unless forced, it waits for the configured sync interval or a shorter retry interval when a reply is outstanding. It reads the active map gameplay send profile and chooses a frame by `IsLegacyMapGameplaySendProfile`. On either successful or failed send it clears the received-reply tick, updates the request tick, logs the result and returns the transport status.

## Client branch layouts

The legacy branch builds `PACKET_CZ_TICKSEND_LEGACY`: `profile.tickSend` at offset 0 (2 bytes) and client tick at offset 2 (4 bytes), total 6 bytes. The non-legacy branch builds `PACKET_CZ_TICKSEND2`: opcode at offset 0 (2 bytes), filled padding at offset 2 (2 bytes), and client tick at offset 4 (4 bytes), total 8 bytes.

## Selected registry comparison and risk

`Packet.h` maps the legacy tick to `0x007E` and the non-legacy tick to `0x0089`. `PK01.02-server-registry-final.csv` maps `0089` to fixed length 8 and `clif_parse_TickSend`, matching the non-legacy frame. It maps `007e` to length 102 and `clif_parse_UseSkillToPosMoreInfo`, which does not match the six-byte legacy tick frame. The legacy branch cannot be treated as selected-server parity without proving that this profile is unreachable or reconciling the source/profile identity.

## Selected server parser and response continuation

The selected `0x0089` parser reads the client tick from configured offset 4, stores it in `sd->client_tick`, then calls `clif_notify_time(*sd, gettick())` (`src/map/clif.cpp:11201-11207`; selected registry row `PK01.02-server-registry-final.csv:373`). The notifier sends `PACKET_ZC_NOTIFY_TIME` containing the current server tick to that session (`src/map/clif.cpp:11187-11193`). Thus the selected 8-byte `0x0089` client frame is accepted and receives an immediate server-time notification. The legacy 6-byte `0x007E` frame conflicts with selected registration `0x007E` (102-byte `clif_parse_UseSkillToPosMoreInfo`); source traces do not establish which gameplay profile is configured on the deployed client/server pair.

## Stronger review and replay required

Resolve which map gameplay profile is effective in deployment and verify whether retries after failed sends or absent replies create duplicate/late tick behavior. Keep all rows open.
