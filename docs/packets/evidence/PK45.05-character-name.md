# PK45.05 — character-name request/reply isolation

2026-11-05. Dedicated commit: `packet(PK45.05): isolate character name lookup from actors`.

While tracing crafted-item producer IDs for PK09.04, selected server `clif_solved_charname` and `clif_parse_SolveCharName` proved that 0194 carries a character ID. The current misleading `actorNameAckParty` alias routed it through actor creation and both actor-name caches. A real queued/fragmented production regression failed: `character-ID reply overwrote actor-ID cache or request timer`.

The receive profile now names this field `characterNameAck` and dispatches to a separate handler. Its cache/timer namespace cannot mutate visible actors or their affiliation/query state. The new mode resolver sends the source-selected padded 00A2 request (15 bytes, CID at 11), suppresses duplicate pending requests, retries after 2500ms and after a failed send, and returns the exact cached name after the matching reply. Request builders reject zero IDs and undersized buffers without mutation. Other gameplay-profile lookup layouts remain disabled rather than inheriting unaudited bytes.

[Contract](../contracts/PK45.CHARACTER-NAME.md) records all fields, namespace, padding, timers and lifecycle limits. [Selected-header probe](PK45.05-character-name-probe.cpp) independently asserts 0194/30/CID@2/name[24]@6. The earlier final registry's selected SolveCharName entry is reproduced in provenance; its current packetdb and effective config input hashes match the prior pinned source. C2S padding varies with tick and is server-ignored; exact captured bytes are retained, while assertions independently fix opcode/length/CID offset.

Two packet cases cover fragmented reply framing, same-number actor/CID collision, unseen-CID phantom-actor prevention, empty/zero-ID guards, failed send without timer, real SendPacket loopback capture, duplicate suppression, forced timer expiry/retry and cache-hit completion without new requests. Existing real OnInit/OnExit and loaded same-map reuse tests now seed and assert character-name cache/timer teardown. Their normal reconnect/handoff lifetime boundary is retained; no full transport-generation claim is made.

Full configured build/CTest results, new records, source/reference/external/binary hashes and failure output are retained in [provenance](PK45.05-character-name.json). Prior actual item-name/card/quantity/colour/bag/cart and minimap rendering remains required. No new UI consumer is claimed in this dependency leaf. Next connect the resolver to primary crafted/named-pet composition and verify name arrival/replacement in native and Qt UI.

The old PK45.02 name-ack research described the then-current mixed cache path and left request correlation/lifetime open; this checkpoint supersedes its 0194 actor/cache interpretation. Discovery classifications remain UNREVIEWED while broader historical/consumer acceptance is outstanding. No external or Ref source, installed client or live server was changed.
