# PK45.03 — actor walking packet decoder boundary

Date: 2026-11-04. Status: legacy fixed-layout decode path inspected; heuristic shifted-layout selection and all variable move variants need stronger review. No rows closed.

## Legacy branch inspected

The current receive profile maps legacy walking packets to 0x007B and shifted form 0x01DA; the packet-size table gives both a 60-byte base size. `HandleActorMoveSkeleton` first calls `DecodeActorWalkingPacket`, applies decoded runtime actor state when it succeeds, and only then uses a 12-byte fallback that decodes GID plus packed source/destination coordinates.

For the legacy family, the decoder requires at least 60 bytes and constructs a classic candidate using offsets for GID, speed, body/health/effect state, job, appearance, packed source/destination cells, and movement tick. For base 0x007B packets of at least 61 bytes whose byte 2 resembles an object type, it constructs a second shifted candidate and selects between candidates using `ScoreLegacyActorState`; otherwise it uses the classic interpretation. This is not a single fixed offset contract: interpretation can depend on packet length, opcode, a type-byte plausibility check, and a score comparison.

## Why this remains open

This heuristic can distinguish historical layouts, but proving it against the selected server requires exact source/profile identity and representative captures. The base/shifted candidate selection and downstream movement interpolation touch actor spawn state, status, movement tick, and remote/local position synchronization. PK46 separately has conditional movement findings, and PK45.04 requires production replay. Do not simplify the decoder or claim parity from the packet-size table alone. A stronger profile/source audit should verify 0x007B vs 0x01DA offsets, candidate scoring, boundary lengths, and state changes for local and remote actors. No replay was run and no rows are closed.

## Additional movement opcode/profile boundary (2026-11-04)

The client profile also assigns `0x022C`, `0x07F7`, and `0x0856` to the shared `HandleActorMoveSkeleton` decoder. Focused checks of the selected server found only packet-database registrations for these IDs (`0x022C` has 64- and 65-byte branches; `0x07F7` and `0x0856` are variable-length) and no matching S2C emitter in `clif.cpp`. The packet database alone does not establish direction or prove an outgoing actor-move contract.

Keep these as alternate-profile/direction cases, not selected 20080910 server variants, until the client receive profile and server packet-database contexts are reconciled with authoritative captures. The decoder's shifted and variable layouts remain stronger-review items; no discovery row is closed.
