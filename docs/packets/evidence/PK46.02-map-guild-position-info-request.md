The Qt guild action requires a local guild, guild-master status and permission flag `0x02`. It converts position ID and tax to integers and rejects ID outside 0–19 or tax outside 0–50. It builds a zero-filled 44-byte `0x0161` frame with total length u16@2 (=44), position ID u32@4, invite/expel bits u32@8 (bits 0 and 4), position ID again u32@12, tax u32@16, and UTF-8 name at @20 in a 24-byte zero-terminated field. ### Character-service update boundary

The map server sends command 0x303B containing guild ID, position index and the fixed `guild_position` record. The character-service handler loads the guild and rejects a missing guild or index outside `[0, MAX_GUILDPOSITION)`. Otherwise it replaces that position record, broadcasts the updated position to map servers, marks the position modified and sets the guild-position save flag. The receiving map path applies the record, broadcasts to clients, and refreshes guild-member name/title data. This closes the server-side index/update path at source level; it does not replace client replay of ID/tax/name boundaries, permission gating, send failure and eventual visible refresh.

It writes position ID@4, mode@8, a duplicate ID@12, tax@16 and name@20; the zero-initialized packet leaves trailing record bytes clear (`src/qtui/QtUiStateAdapter.cpp:3878-3881`). ## Malformed variable-record length recheck (2026-11-05)

The PK01.02-matching parser loops from the configured first-record offset while `i < declaredLength`, stepping 40 bytes, and does not visibly require `(declaredLength - firstRecordOffset)` to be divisible by 40 before reading the record fields. A partial trailing record may therefore enter the same field-read path as a complete record. Treat this as a malformed-frame review question, not a confirmed vulnerability: packet-dispatch buffer bounds and the impact of incomplete tails need a focused stronger review. No row closed.
