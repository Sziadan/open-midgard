# PK45.03 — equipment request acknowledgment

Date: 2026-11-04. Status: client equip/unequip acknowledgement branches and selected 20080910 unequip result semantics traced; equip-result parity and replay remain open. No rows closed.

The client size table fixes 0x00AA at 7 bytes and routes it to `HandleEquipItemAck`. The handler requires 7 bytes and decodes item index u16@2, wear location u16@4, and result u8@6. It clears `m_waitingWearEquipAck` when the returned index matches. For result 0, index 0, or wear location 0, it logs and returns without changing inventory appearance. For nonzero result with nonzero index/location, it clears any existing inventory wear-location mask at that slot, sets the returned item as worn, rebuilds the player's equipment appearance from inventory, and syncs that appearance to the local actor.

The request path sets `m_waitingWearEquipAck` only after a successful send, so the reply can clear an outstanding request. This pass did not verify the server's result byte convention, request packet selected by the active send profile, equip slot masks, or behavior for late/duplicate/out-of-order replies. Confirm those against the selected server contract and replay success/failure, replacing an occupied slot, and stale item indices. No rows are closed.

## Unequip and ammunition follow-ups

`HandleUnequipItemAck` is the fixed 7-byte 0x00AC reply with the same index@2, wear location@4, result@6 shape. It clears a matching pending takeoff index. Result 0 or index 0 returns without appearance changes; any nonzero result with a nonzero index clears that item's wear location, rebuilds equipment appearance, and syncs it to the local actor. The reported wear-location field is logged but the inventory mutation sets the item's location to zero. As with 0x00AA, the server result convention and intended use of the returned location need source confirmation.

The 4-byte 0x013C ammunition acknowledgment reads item index u16@2, clears the entire pending wear/equip index, clears existing wear mask 0x8000, and assigns that mask to the returned item when nonzero. It has no result field. Verify that this acknowledgment cannot clear an unrelated pending armor/weapon request and confirm the selected server's ammunition index/mask semantics. None of these outcomes has been replayed.


The selected server emits the 7-byte 0x00AC unequip ack with the un-inverted success bool at byte 6 for PACKETVER=20080910. The client treats zero as failure and nonzero as success. See `PK46.02-map-unequip-item-request.md` for server call branches and the index-zero correlation caveat. Equip ack result parity remains open.
