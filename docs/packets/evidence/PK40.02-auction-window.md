# PK40.02 native auction window

Server `025F` opens the native window alongside the initial browse request. The window shows five results per page, category and name filters, a maximum-price query, and the player's own sales and bids. The registration tab lists inventory items and accepts an inventory drag. Registration, bidding, cancellation, and ending a sale use confirmation dialogs owned by the window. Confirmation callbacks check the current mode and revalidate the staged item or listing before sending.

Closing the window retires the search and releases staged selection through the existing request path. A server close and same-map warp delete the managed window and its confirmation dialog. The native window participates in the Qt bridge's pointer routing.

Replay drives the window-manager input path for own bids, item staging, and close, and retains byte coverage for the other transactions. The layout uses existing native controls. Installed-skin geometry and artwork comparison, rendered Qt and native verification, live transactions, and recovery from silent server drops remain open.
