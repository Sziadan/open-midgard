# PK45.03 — party member HP update variants

Date: 2026-11-04. Status: client profile routing, framing, fields and actor propagation traced; selected-profile and replay validation remain open. No rows closed.

The router registers `HandlePartyHpUpdate` under the active receive profile's basic and extended packet IDs. The profile initializer inspected here assigns 0x0106 as the basic ID and 0x080E as the extended ID; the size table fixes them at 10 and 14 bytes respectively. `IsActivePartyHpUpdateExtendedPacket` selects the wide-field branch by comparing against the active profile's extended ID.

Both variants read AID u32@2. The basic variant requires 10 bytes and reads HP and max HP as u16@6 and u16@8 (converted through signed `int`); the extended variant requires 14 bytes and reads each as u32@6 and u32@10. AID zero or a failed `SetPartyMemberHp` mutation stops processing. On mutation, it finds the party member by AID and, when a nonempty character name exists, calls `ApplyCachedPartyHpToVisibleActor` to propagate the cached values to the visible actor. It does not directly refresh party UI in this handler.
