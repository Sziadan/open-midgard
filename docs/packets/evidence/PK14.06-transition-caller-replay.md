# PK14.06 — production map and character lifetime callers

Verified 2026-11-05. This supersedes the earlier generic caller-seam deferrals and completes the scoped marker-lifetime caller checkpoint. Native/Qt rendered acceptance remains PK14.04 work.

## Implementation

`HandleMapChange` still owns parsing, loaded-map branch selection, commerce closure, session map/position update and party-coordinate invalidation. Optional per-mode `MapTransitionServices` replace only loading presentation, transport reconnect and scheduled mode handoff; absent callbacks retain production defaults. The service pointer is borrowed through dispatch and handoff callbacks must schedule, rather than destroy the executing mode inline. No process-wide test override is installed.

Pending disconnect state is cleared in the real server-move handler before invoking the reconnect service, rather than being hidden inside the replaceable transport helper. Reconnect failure reuses ReturnToLogin cleanup and clears stale return-to-character intent. A local same-map warp retains the actual `PrepareSameMapWarpReuse` and real load-end ACK sender.

Fixed an additional character lifetime gap: `CLoginMode::OnNotifyZonesvr` previously changed GID/map before clearing session party coordinates. It now invalidates immediately after validating packet length, before adopting new character/map identity or accepting fresh zone traffic. Existing game/login OnExit invalidation remains safe and membership-preserving.

## Actual replay scope

The additive `MapTransitionLifetimeReplay.inc` uses production framing, receive loop and default router. It asserts the following with independent selected 0x0091/0x0092/0x0071 records:

- Map A to B applies map/coordinates, invalidates marker coordinates, preserves membership, advances the shared position revision/Qt image token, requests loading and schedules the correct map; no reconnect occurs for 0x0091.
- A real CWorld/CPlayer/CView with a value-initialized heap C3dGround supplies the loaded-state fixture. Same-map 0x0091 executes real reuse, clears legacy dots, retains the player/world/view and sends the real two-byte load-end ACK captured through singleton loopback. No loading/reconnect/handoff callback runs.
- Same-name requests while loading select a handoff instead of reuse. A server-move endpoint forces reconnect even when that same map is fully loaded.
- Successful and failed 0x0092 callbacks observe the parsed IP/port and already-invalidated session/request state. Success schedules the target game map; failure schedules Login and clears stale return intent. Both retain party membership and update revision/token.
- Unknown framed input and a short map-handler record cannot mutate map/marker state.
- Actual singleton `PollNetwork -> OnNotifyZonesvr` changes character to both a different map and the same map. Coordinates are invalid **before** LoginMode::OnExit; the subsequent real exit preserves invalidation and membership. No zone server is contacted.

The loaded fixture represents the exact production loaded-state guards and geometry values; it does not load installed map assets or certify a rendered scene. Native and Qt use the shared marker eligibility policy, which is asserted false after each boundary; Qt image-token invalidation is model evidence, not a rendered-frame claim. Reconnect transport is injected for server-move cases, so no selected live zone authentication is claimed.
