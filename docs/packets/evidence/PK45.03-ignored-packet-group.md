# PK45.03 — registered ignored packet group

Date: 2026-11-04. Status: client framing registrations and dispatch target traced; protocol meaning and intended behavior remain unresolved. No rows closed.

The receive router registers the following 18 opcodes to the same empty `HandleIgnorePacket` body: 0x0100, 0x0192, 0x0199, 0x01B0, 0x01D6, 0x01F8, 0x0283, 0x02B1, 0x02B2, 0x02C9, 0x02D3, 0x02D5, 0x02D9, 0x02DA, 0x02DD, 0x02E7, 0x0814 and 0x0816. The client registry assigns fixed sizes to all except 0x02B1, 0x02B2 and 0x02E7, which use variable packet framing.

For this client build, dispatch through this handler performs no game-state mutation and sends no reply. This is only a statement about the current client implementation. It does not establish whether these packets are server notifications, obsolete messages, profile-specific variants, or intentionally ignored protocol events. Their field layouts and semantics require selected-server/source or capture evidence; no independent fixtures or production replays were run for this group.

The individual 0x01B0 framing and dispatch trace is also recorded in `PK45.03-ignored-01b0.md`.

## Selected server cross-check: representative ignored opcodes (2026-11-04)

Focused checks identify three different directions/meanings within this shared empty-handler group. `0x0100` is declared as the client `CZ_REQ_LEAVE_GROUP` request, so it is not a server notification to implement in the receive handler. `0x0199` is the legacy server `ZC_NOTIFY_MAPPROPERTY` packet carrying a u16 map-property value. `0x02C9` is `ZC_PARTY_CONFIG`: one byte for allow/auto-deny party invites, emitted from the character's `disable_partyinvite` state and sent SELF during login.

These examples show the group mixes directions and state notifications. The other registered opcodes still need a per-opcode selected-profile definition/callsite or capture review; a single empty client handler is not enough to classify them. Treat the remainder as a stronger-review batch, and do not implement guessed behavior. No discovery row is closed.

## Additional selected-profile ignored-opcode findings (2026-11-04)

Further focused source checks identify these contracts in the shared empty-handler set:

- `0x01D6` is `ZC_NOTIFY_MAPPROPERTY2`, a one-u16 map-type update sent SELF.
- `0x02B1` and `0x02B2` are variable quest-list/mission-list packets emitted from the character's quest state.
- `0x02D3` is a bound-on-equip notification carrying a client item index u16, sent SELF; its emitter is enabled from packet version 2007-02-27.
- `0x02D9` carries a configuration type and boolean value as two u32 fields; `0x02DA` carries the view-equipment boolean and is sent SELF during login.
- `0x0814`/`0x0816` are buying-store entry/disappearance packets, but their emitters are gated at 2010 packet versions, after the selected 2008 profile.

These source labels help distinguish active server notifications from later-profile registrations, but the full group is not closed: `0x01F8`, `0x0283`, `0x02D5`, `0x02E7`, and any relevant per-opcode client effects still need authoritative profile/capture review. The group's empty handler proves only that this client performs no action for those dispatches. No discovery row is closed.

## Final focused cross-check for remaining ignored opcodes (2026-11-04)

`0x0283` is emitted by the map server during `clif_parse_WantToConnection`: after validating/initializing the connection, the server sends the account ID (with opcode `0x0283` for packet versions from 2007-05-21) and then requests character-server authentication. This is a handoff-stage notification; the client empty handler does not itself complete that server-side authentication exchange.

No literal definition/emitter for `0x01F8`, `0x02D5`, or `0x02E7` was found in the selected map `clif.cpp`, `packets.hpp`, or `packets_struct.hpp` during focused checks. Their meanings/profile ownership remain unresolved; seek matching revision or capture evidence. Together with the earlier identified opcodes, this is a partial source classification only, not closure of all 18 registrations. No discovery row is closed.
