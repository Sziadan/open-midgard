# PK45.03 — automatic spell list

Date: 2026-11-04. Status: handler field access and UI message path traced; packet framing, replacement semantics and selected-profile contract remain unresolved. No rows closed.

The receive router registers opcode 0x01CD to `HandleAutoSpellList`. The handler requires data and at least 30 bytes, then reads seven u32 skill IDs from offsets 2, 6, 10, 14, 18, 22 and 26. If all seven are zero, it returns without opening or updating the window. Otherwise it obtains/reuses `WID_SPELLLISTWND` and sends UI message 31 once for each nonzero skill ID, in packet order.

`UISpellListWnd::SendMsg` handles message 31 by appending the skill ID to `m_spellList`, appending a default `ITEM_INFO`, recalculating the scrollbar and invalidating the window. The packet handler does not clear the existing list first, and the all-zero case does not clear it either. Whether window reuse or another lifecycle step resets the list is not established here. The handler sends no network reply and does not validate the packet ID locally.

The inspected packet-size registry contains no `SetPacketSize(0x01CD, ...)` entry. The 30-byte minimum is consistent with the fields read but does not establish wire framing or prove the registered handler is reachable. Open work: identify authoritative size/direction/profile and server contract; determine list replacement/lifecycle behavior; replay all-zero, mixed and repeated skill IDs. No independent fixture or production replay was performed for this leaf.

## Selected server auto-spell list contract (2026-11-04)

The selected server `clif_autospell` has a pre-2009 fixed packet branch for the 2008 SAK profile: `0x01CD` plus seven 32-bit skill IDs (30 bytes total), sent to SELF. It iterates the classic non-Renewal auto-spell choices and writes a skill ID only when the required auto-spell skill level is met and the character knows that skill; otherwise it writes zero in that slot. The `0x01CD` packet struct is selected for SAK packet versions from 2008-06-18 onward. This matches the client handler's seven-u32 field access and 30-byte minimum.

The client UI path appends nonzero skills, while this emitter can place zeroes between valid choices. Exact correspondence between the selected client binary and server profile, UI behavior for sparse/duplicate lists, and replay fixtures remain open. No discovery row is closed.
