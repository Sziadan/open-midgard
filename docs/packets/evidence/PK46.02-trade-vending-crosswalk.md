# PK46.02 selected trade and vending requests

The MAIN 20080910 registry and production loopback fixtures establish the following selected map C2S identities. Parser descriptions below use the inspected local `clif.cpp` (SHA-256 `76c1c4202040daab90f2e441ffad05d9b9ce612d2a16edba55d2926c83ccbb6e`), which differs from the PK01.02 pin. Packet lengths and registration fields come from the pinned registry.

## PK46.02-TRADE-REQUESTS

- `00E4` sends the four-byte peer account ID at offset 2. The player action sends the six-byte frame. The parser resolves the peer, checks the initiator's action and skill gates and the recipient's auto-rejection or mail state, then dispatches the invitation.
- `00E6` sends the one-byte invitation result at offset 2. Replay captures accept (3) and decline (4), including the waiting state until the server replies.
- `00E8` sends the two-byte index at offset 2 and the four-byte amount at offset 4. The server uses index zero for Zeny and converts other wire indices to inventory slots. Replay checks the pending item offer and the separate Zeny path.
- `00EB`, `00ED`, and `00EF` are two-byte lock, cancel, and commit requests. Replay captures each, including cancellation crossing acceptance and commit waiting for both lock flags. [Trade lifecycle evidence](PK37.03-trade-cancellation.md)

## PK46.02-VENDING-REQUESTS

- `012E` closes active vending. Replay captures the two-byte request from explicit close and sold-out handling.
- `0130` sends the board seller's four-byte account ID at offset 2. Replay captures requests to two vendors and verifies the newer request owns the next matching stock list. The Qt board fixture also records the click-to-send path.
- `0134` uses a two-byte length at offset 2 and a four-byte seller ID at offset 4. The client sends a single row with amount and cart index at offsets 8 and 10. The parser uses the server's remembered vendor instance and clears that selection after purchase processing. Replay captures the 12-byte frame and quote retirement.
- `01B2` uses a two-byte length at offset 2, an 80-byte title at offset 4, a flag at offset 84, and eight-byte rows beginning at offset 85. Each row contains cart index, quantity, and price. Replay starts with the server's setup packet, builds one offer, captures flag 1 and its full row, then captures `012E` followed by the empty 85-byte flag-zero setup cancellation. The client discards a late owner list after that cancellation. [Vending lifecycle evidence](PK37.02-vending-snapshots.md)

The selected registry also accepts legacy `012F`, whose 84-byte header omits the flag. The supported producer uses `01B2` across movement profiles. The later purchase `0801` remains inactive for the selected date. Live buyer, seller, and two-peer trade checks and PK48 independent review remain open. [Vending profile evidence](PK46.02-map-open-vending-alternate-012F.md)
