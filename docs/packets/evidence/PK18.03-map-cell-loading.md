# Dynamic map cell loading and replacement

`CGameMode::OnInit` starts a terrain load for its world, and the map packet loop can receive `0192` before GAT is available. A valid map name, nonnegative cell coordinate, and supported type allow the world to retain the latest update for that coordinate during this interval. GAT binding validates the pending coordinates against the real dimensions and drops entries equal to the base type. The same terrain resource can be bound again during the same world lifetime without losing its overrides. Failed binding or mode exit clears the pending state.

Mode initialization also resets the world bootstrap stage. A real replacement can reopen the same name while the previous bootstrap is still in progress. The fresh mode must reach GAT binding again even if the resource manager already has the asset. The loaded same-map `0091` reuse branch keeps its current world, terrain, and effective cell state.

The lifecycle replay uses the production socket receive and game-mode update loop, a loose 3-by-3 GAT file loaded by the resource manager, and the production mode initialization and exit methods. It checks early placement, restoration before binding, invalid and wrong-map packets, an unfinished same-name replacement using the same cached GAT, and abandonment before binding followed by reentry. The map transition replay also sends `0192` immediately before the real `0091` reuse path and verifies the same world retains the update and sends its load acknowledgement.
