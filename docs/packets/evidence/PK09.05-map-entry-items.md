# PK09.05 — item snapshots at map entry

Verified 2026-11-05. Dedicated checkpoint: `packet(PK09.05): reset item snapshots on map entry`. This report covers the map-entry item lifetime leaf, not the complete item protocol or UI.

## Source decision

The selected server's `clif_inventorylist` and `clif_cartlist` send category lists only when their normal/equipment counts are nonzero. `clif_parse_LoadEndAck` calls these after map entry. No empty equipment packet will arrive to clear a category that has become empty. Existing category replacement alone therefore cannot establish a fresh full snapshot.

Primary `Ref/GameMode.cpp::Initialize` explicitly clears ordinary/equipment inventory, store items and merchant/offer/shop/mirror item lists before its load-end acknowledgement. Its caller is the map initialization path. The new reset is placed in actual `CGameMode::OnInit`, before loading/world bootstrap and acknowledgement processing. Inventory is cleared, storage is closed and cleared, and `ro::commerce::ResetForMapEntry` resets map/server-backed state. Local panel positions and the selected inventory tab survive; panels and pending transactions close. Actor appearance is not erased merely because replacement item lists have not arrived yet.

The earlier production behavior retained inventory rows across this boundary. The new real-OnInit regression fails before repair on that retained row. It sends independent literal 0x02E8/02D0/02E9/02D2 bytes through queued extraction, framing and the default production router, then enters the real mode initialization path. Its second normal-only snapshot represents the server's omission of an empty equipment category. Repeated real initialization checks idempotence without faking a reset callback.

The same-map optimization bypasses OnInit but still sends load-end acknowledgement and receives a new snapshot. A second failing regression demonstrated retained inventory on that path. The handler now calls the shared reset before its real acknowledgement. The existing real-handler/loopback fixture checks old inventory removal, native storage-window/session closure, the unchanged two-byte acknowledgement, and retention of the loaded world/player/view. This closes both initialization entry points without erasing actor appearance merely because item lists have not arrived.

## Limits and continuation

The test uses offline synthetic item/state fixtures and actual map initialization with a null world name. It verifies state and the real production entry point; it does not render item panels, replay a live transport reconnect or certify a deployed profile. Storage and transaction flags are seeded to exercise their map lifetime, not to prove their packet protocols. Actual reconnect/map handlers retain separate PK14.06 evidence. Broad PK09.04 remains open.
