# PK46.03 — login/character outbound evidence crosswalk

Date: 2026-11-04. Status: partial cross-check of existing source-backed send evidence; PK46.03 remains open. No new senders/handlers added and no discovery rows closed.

## Supported request evidence already present

- Login requests: `PK44.LOGIN-REQUESTS.md` records selected-source request layouts/parser branches. `PK44.04-login-request-direction-reconciliation.md` links current-client production captures for 0x01DB, 0x0204, 0x0277, 0x02B0 and 0x01FA; 0x01DD and 0x027C have separate captures. The existing contract/evidence also covers 0x0064 and 0x0200. These prove the captured request bytes and C2S direction for their stated settings/branches, not deployed service/profile intent or a full login UI lifecycle.
- Character select/create: `PK44.04-character-request-directions.md` records current-client 0x0066 select (3 bytes) and 0x0067 create (37 bytes) captures against the selected-source C2S database. `PK44.04-character-select-ui-actions.md` and `PK44.04-character-create-request.md` cover bounded production message/action paths; native Qt delivery/rendering remains open.

- Character-server entry: `PK46.03-character-server-entry-path.md` connects the selected endpoint/authentication gate to active-profile 0x0065 serialization and the existing PK44 capture; response lifecycle and ignored send failure remain open.

## Unsupported or unsafe paths retained open

- Immediate deletion: the occupied-slot UI action can reach the current 0x0068 sender, but the selected 20080910 server expects 0x01FB/56 bytes. See `PK44.CHAR-DELETE.md` and the PK44.04 self-review; do not infer compatibility or change the shared profile without a target-specific packet layout and replay.
- Dynamic login SSO 0x0825: the selected parser is variable length with a 92-byte minimum. `PK44.LOGIN-REQUESTS.md` records a separate security review requirement; no client sender is introduced by PK46.03.
- Rename, scheduled deletion/cancel, and paged character selection remain unproven as current-client actions. Preserve unsupported gates until their request identity, profile, fields and user-facing result path are traced.
- Raw account-ID handshake framing belongs to PK04's raw stream boundary, not an invented opcode or receive handler here.
- Other source/read safety issues, including the 0x08D4 slot-index read, remain under their recorded review owner.
