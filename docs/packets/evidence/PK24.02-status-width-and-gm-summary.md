# PK24.02 signed status values and GM inspection

`0141` now decodes signed base and bonus independently. The live actor total adds them as a widened signed value and then narrows to the actor's nonnegative 16-bit field. The character card retains its byte-sized base field. The selected `00BD` snapshot interprets its combat words as signed and uses the same session setters as incremental `00B0` combat updates. Raw ASPD motion retains its existing display conversion.

`packet_status_resource_widths_checks` frames and routes `0141`, `00BD`, `00BC`, `00BE`, `00B0` and `00B1`. It checks negative and extreme positive stat totals, a signed bonus across snapshot and acknowledgement, signed DEF/MDEF fields, positive status points and unsigned byte costs/results. It also exercises synthetic high-bit HP/SP and independent base/job EXP, including a zero next-EXP denominator. The selected server caps EXP at `INT32_MAX`; those high-bit tests measure the client's storage and arithmetic boundary. [Selected layout](../contracts/PK24.RESOURCE-STATE.md)

`0214` is the inspected character's GM response. The router now calls the existing chat message path with the five signed, formatted lines from `Ref/GameModePacket.cpp::Zc_Ack_Status_GM`. `packet_status_summary_0214_checks` checks the exact lines and colors, and verifies that the inspected stats do not overwrite the local resource, combat, or character state.

The deployment-disabled build passed 181 application checks and 473 standalone checks.

The session now owns the full nonnegative `00B0` status-point value. Native status rendering, Qt projection and stat-cost checks use it. The legacy character card caps its copy at `INT16_MAX`. Character selection seeds the session value and `00BD` replaces it. Replay covers 70,000 points, the signed dword ceiling, and a negative value. It also verifies rejected `00BC` leaves the requested stat alone, and successful `00BC` updates that one stat without refreshing a different stat from its capped card copy. The focused width and GM replay both passed after these changes. Actor and resource-event ordering remain in PK24.03.
