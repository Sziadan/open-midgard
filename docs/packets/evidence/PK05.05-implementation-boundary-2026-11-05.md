## Reviewed contract

Follow the adjudicated design in [REVIEW-2026-11-05](REVIEW-2026-11-05.md) and [work item](../work-items/PK05.05.md): expose a mode-operation generation advanced by `CModeMgr::Switch` and `Quit`, stop packet dispatch as soon as a handler changes it, and route the production receive/update decision through a headless-testable preamble before any world or audio work. Preserve an accepted ACK transition, distinguish framing failure from ordinary EOF and open/no-data, and apply timeout only after a genuine receive drain.

## Why implementation is deferred at this checkpoint

The receive decision is not a local error check. It combines the socket's open state and sticky framing error, global pending disconnect/return intent, mode-manager operations made inside production handlers, durable login status, one-shot handling across `CGameMode` initialization/destruction, and the exact point where `OnUpdate` must stop. The existing replay harness uses global production router/session/socket state and has a large uncommitted structural rewrite (the current diff adds 1,918 lines to `PacketStreamReplay.cpp`). The dispatcher and update source files also carry unrelated uncommitted packet/replay work.

A first integration sketch showed that a closed-socket fallback can be made to compile locally, but it cannot establish the reviewed ACK precedence or status/lifetime assertions without a production-faithful receive seam in the harness. That sketch was removed completely. Adding only the generation signal or fallback without those assertions would leave a partially wired behavior change, so this checkpoint makes no source edits and claims no regression coverage.
