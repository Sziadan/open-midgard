# PK40.02 auction item staging

`024C` sends one inventory item using the selected wire index. `0256` acknowledges the server's staged selection. The pinned `clif_parse_Auction_setitem` replies with the wire index on success and a zero-based slot index on failure. The client accepts either index convention for failure, requires the wire index for success, and checks that the current inventory row still has the requested item ID and a positive quantity.

The server records the stage in `sd->auction` and removes the item only when registration is sent to the char server. That deletion uses `pc_delitem` flag 1, suppressing the ordinary deletion notice. The client reserves one unit on a matching `0256`, as the reference does. `024B` retires the selection and the server returns the unit through the ordinary item pickup acknowledgement. Search and own-list requests run the same server cancellation path. Late success still reserves the unit so the following return balances it, while the retired selection stays cleared.

Replay exercises the eight-byte stage request, raw-index failure, mismatched and duplicate success, single-unit reservation, the four-byte cancel request, and a late acknowledgement after search. Both cancellation paths verify the ordinary pickup return restores the inventory quantity. The visible stage controls and registration, bid, and stop request owners remain open. Stage requests that the server drops silently require a recovery boundary before another request can use the same slot.
