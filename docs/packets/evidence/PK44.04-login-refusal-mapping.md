# PK44.04 — Correct login refusal result messages

Date: 2026-11-04. Status: bounded production-helper correction verified; PK44.04 remains in progress.

## Source contract

The selected rAthena `PACKET_AC_REFUSE_LOGIN` layout is 23 bytes: opcode `0x006A` at offsets 0–1, one-byte error at offset 2, and 20 unblock-time bytes at offsets 3–22. In `src/login/loginclif.cpp`, `logclif_auth_failed` zero-initializes the packet, assigns the error value, and copies an empty string into `unblock_time` before sending. Its result comments define codes 0–4 as unregistered ID, incorrect password, expired ID, rejected from server, and blocked by the GM team.

Server source hashes at replay time:

- `src/login/loginclif.cpp`: `A0EEA56F5A41286674AE27CAAD5B57E192B298E20C0FDDC38F015B0C2ECE5E3F`
- `src/common/packets.hpp`: `07B47B66A41ED05433F852E399BA1D714BA728074F76633AD77BC2F7720D79EF`

## Change and replay

`CLoginMode::OnRefuseLogin` now calls the shared `FormatLoginRefusalMessage` helper. Codes 0–4 display the selected server meanings. Code 5 and code 6 behavior is preserved; unknown results preserve their numeric value. The replay constructs 23-byte packets with zeroed block-date bytes and codes 0–4, then exercises the exact helper called by the handler. It also checks code 6's empty-date fallback and generic unknown-code handling. This isolates message selection; the modal dialog itself and full LoginMode packet-loop/UI lifecycle are not exercised.
