# PK46.02 — guild information request 0x014F

Date: 2026-11-04. Status: UI trigger, five request subtype values, six-byte frame, selected server response groups and client guild-window routing traced. Production ordering/replay remains open. No row closed.

Opening `UIGuildWnd` calls `Refresh`. It first sends a two-byte `0x014D` permissions request, then returns if the local guild ID is zero. Otherwise it emits five `0x014F` requests, with subtype byte @2 ranging from 0 through 4 and zero padding at @3–5; each frame is six bytes. The widget ignores each `SendPacket` result and has no per-subtype retry in this method. `SetShow` refreshes only on a hidden-to-visible transition.

The selected registry assignment snapshot identifies length 6 and `clif_parse_GuildRequestInfo` with subtype at offset 2 (`PK01.02-server-registry-assignments.txt:132`). The selected parser reads a 32-bit value at offset 2, returns if the session has neither a guild nor battleground group, and dispatches as follows: type 0 sends guild basic info, alliance/opposition info and castle list; type 1 sends position names and member list; type 2 sends position names and position metadata; type 3 sends guild skills; type 4 sends the expulsion list. Unknown values are logged and receive no response. The client writes the subtype as one byte with three zero padding bytes, so its normal values map to the parser's 32-bit read; nonzero padding changes the dispatched value and is not separately validated.

For the selected 20080910 branch, the expected response groups are 0x0150/0x014C plus castle data for type 0; 0x0166/0x0154 for type 1; 0x0166/0x0160 for type 2; 0x0162 for type 3; and 0x0163 for type 4. The client registers these packet IDs to `HandleGuildWindowPacket`, except the dedicated 0x0162 skill handler. Missing guild data often causes individual emitters to return silently. Responses are not correlated with a specific one of the five `Refresh` sends; this is a state refresh, not a request-token protocol.

Replay opening without a guild, all five subtypes, nonzero padding, partial send failure, reopen, out-of-order/duplicate responses, missing guild data and UI reset behavior before closure. Primary ownership remains PK50; no production replay and no row closed.
