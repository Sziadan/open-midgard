# PK46.02 — selected map-request opcode mention census

Date: 2026-11-04. Status: bounded documentation coverage check only; no discovery rows closed.

## Method and result

Read `docs/packets/evidence/PK01.02-server-registry-final.csv` and counted distinct opcode values whose final selected row has a non-empty parser. The normalized set contains 177 unique accepted parser opcodes. Read the 96 existing `PK46.02*.md` evidence notes and searched for each exact `0xNNNN` token. Every one of the 177 registry opcodes appears explicitly in at least one note.

## Limits

This census proves that every accepted opcode is named in the package notes. It does not prove that each occurrence refers to the selected server registration, that every profile serializer and raw buffer field was compared, or that every Qt/user action and reply path was traced. PK46.02 remains `IN_PROGRESS`; the required per-request comparison across all 177 accepted map requests and discovery-row review remain open.

The result is reproducible with a script that normalizes final-registry opcodes to four lowercase hex digits, keeps rows with a parser, and checks each `0xNNNN` token against the package evidence text. It is an inventory guard, not protocol validation.
