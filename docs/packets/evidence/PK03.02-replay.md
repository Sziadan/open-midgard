# PK03.02 — Production receive/framing replay

Date: 2026-11-03
Status: completed for bounded production transport framing and boundary decoding.

## Implementation and method

Added opt-in CMake option `RO_BUILD_PACKET_REPLAY_TESTS` (default OFF), `packet_stream_replay_checks`, and a 30-second CTest timeout. `CRagConnection::RecvPacket(std::vector<u8>&)` is fed over a local TCP loopback; the harness connects through production `CConnection::Connect`, uses bounded send/read/accept deadlines, and inspects the protected production queue from a test subclass. The exact `TryReadPacket` boundary decoder used by `GameMode.cpp` is moved unchanged from `GameModePacket.cpp` into `src/gamemode/PacketStreamDecoder.cpp`, allowing the test to compile that production decoder without pulling in the full app's unrelated startup globals. `ro_gamemode` also builds with the moved source. This exercises packet-boundary decoding, **not** `CGameModePacketRouter::Dispatch` or feature handlers.

The fixed structural sample is the synthetic bytes `6c0000` (SHA-256 `a8649967f8ca13630d18e21c07eaad14b309a54534f1cd9f633b692c3b2f341f`): the selected client size table reports fixed length 3 and the active map registry has 0x006C length 3 (`clif_packetdb.hpp:18`). Its application semantics/stage-direction are deliberately not asserted. The variable framing sample is synthetic 0x0069 length 6 bytes `690006001122` (SHA-256 `d5eb153194bad9d1ab1c303bb77da191fedc51db5728e646153b92cf302df42b`). These are local framing probes, not approved feature fixtures.

The harness waits until each intended prefix reaches the application queue before sending its suffix; it pumps until complete frames arrive, captures kernel-pending bytes for the coalesced case, and applies bounded deadlines. Every record asserts actual bytes/queue expectations and derives connection state from `IsOpen()`. It writes per-case JSONL with source baseline, fixture ID/hash, actual input chunks, invocation count, expected/actual packet bytes, connection state, queue remainder, classification and outcome. The preserved 28 records are in `PK03.02-replay.jsonl`.

Cases cover every split of the 3-byte fixed sample and 6-byte variable sample; two coalesced fixed frames; variable then adjacent fixed frame; empty, partial fixed-header and partial variable-body EOF; and production disconnect/reconnect queue reset. Unknown opcode and undersized/oversized variable-length scanning are separately labelled `baseline_behavior_to_revisit_in_PK05`; they document current destructive resynchronization, not an approved recovery contract.

## Findings, pending cases and limits

An initial prototype attempted to use server S2C 0x01F2 as a fixed receive fixture; it failed because the active client receive size table returns unknown for 0x01F2. `GronPacket.cpp` has no active `SetPacketSize(0x01F2, ...)` entry even though the server emits the 20-byte guild status. This is routed to PK06; the generic framing test uses 0x006C instead and does not close that packet row.

Raw account echo remains PK04; stage/profile enforcement remains PK05/PK44; `CGameModePacketRouter::Dispatch` and feature handlers/UI replay remain open for later PK03/feature leaves. The legacy `RecvPacket(char*)` wrapper has no capacity parameter and is not invoked with a guessed buffer. Unknown/malformed recovery assertions only characterize current code and must be revised with PK05. No deployed-server parity or gameplay behavior is certified.
