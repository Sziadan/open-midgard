# PK46.02 — NPC next-dialog request 0x00B9

Date: 2026-11-05. Status: dialog action, NPC ID guard, fixed serialization, selected server continuation gates, and client next/text response handling are source-traced. The source confirms no local rollback on send failure; recovery behavior and production replay remain open. No discovery row is closed.

## User action to sender

`UISayDialogWnd` sends `GameMsg_RequestNpcNext` when the player activates the dialog's Next action by keyboard or button. Before sending, the UI sets its clear-on-next-text flag and clears the current action. `GameMode` dispatches to `RequestNpcNext`, which rejects NPC ID zero, writes the packet, sends `sizeof(packet)`, and returns the send result. The UI does not restore the cleared action if sending fails.

## Client layout and profile

`PACKET_CZ_NPC_NEXT_CLICK` contains opcode `0x00B9` at offset 0 (2 bytes) and NPC ID at offset 2 (4 bytes), for six bytes total. The sender uses `PacketProfile::LegacyNpcScriptSend::kNextClick`, which resolves to `0x00B9`.

## Selected registry comparison

`PK01.02-server-registry-final.csv` maps opcode `00b9` to fixed length 6 and `clif_parse_NpcNextClicked`. Client opcode and total length agree with the selected final registry. The parser refreshes NPC-next idle time when configured and calls `npc_scriptcont` with the supplied NPC ID and `closing=false`. The continuation enforces secure NPC timeout, requires ID equality with the active dialog NPC, checks proximity/visibility (except item-script fake NPCs), rejects an active progressbar, and requires script state. STOP resumes the script as RUN; RERUNLINE preserves its state for input/menu/select continuation; unexpected states end with a logged error. `run_script_main` produces the next script action/output. Invalid or stale requests return without a generic response.

## Next-action send failure behavior

`RequestNpcNext` rejects NPC ID zero, sends the fixed request, and returns the transport result (`src/gamemode/GameMode.cpp:6212-6227`). Both keyboard and click routes set `m_clearOnNextText` and call `ClearAction` before dispatching. The keyboard route propagates the send result; the click route ignores it. Neither path restores the cleared action/flag when sending fails (`src/ui/UISayDialogWnd.cpp:392-399,468-475`). This is source-confirmed local state loss; replay is still needed to verify user-visible recovery and subsequent script behavior.

## Client continuation receive path follow-up

The client frames `0x00B5` as six bytes and routes it to `HandleNpcDialogNext` (`src/network/GronPacket.cpp:99`, `src/gamemode/GameModePacket.cpp:8879`). The handler reads the NPC ID at offset 2, remembers the conversation, hides any menu/input window, and calls `UISayDialogWnd::ShowNext`, which records the ID and restores the Next action (`GameModePacket.cpp:3434-3453`, `src/ui/UISayDialogWnd.cpp:334-342`). Variable-length `0x00B4` text is routed to `HandleNpcDialogText`; `AppendText` clears previous dialog lines only when the UI's clear-on-next-text flag is set, then appends the new text (`GronPacket.cpp:98`, `GameModePacket.cpp:8878,3419-3432`, `UISayDialogWnd.cpp:322-332`). These later server packets drive the client continuation; they are not a generic success acknowledgement, so a silent rejection or lost request can still leave the UI cleared. Production timing and recovery replay remain open.

## Keyboard and mouse send-failure state (2026-11-05)

The selected `UISayDialogWnd` path mutates dialog state before dispatch: keyboard Next sets `m_clearOnNextText`, calls `ClearAction`, then returns the `SendMsg` result; mouse Next does the same state changes but discards the send result. `RequestNpcNext` returns false for a zero NPC ID and otherwise returns `CRagConnection::SendPacket` success. This establishes the source-level failure boundary, but does not prove whether the changed dialog state is intentional or recoverable after a failed send. Keep retry/stale-ID/script-timeout and visible-response behavior with PK25 owner review; do not treat this as a confirmed defect.
