# PK25.02 — dialogue input and handoff audit

## Menu and conversation branches

- Server 0x00B8 accepts choices 1–254 and cancel 255; zero is invalid. Current `SplitNpcMenuOptions` advances the choice ordinal for every colon-separated slot even when a slot is empty, which preserves the server index. UI selection sends the recorded choice; default choices are index+1. Cancel closes windows and sends 255. `RequestNpcMenuSelection` rejects zero and accepts 255. These paths align with the candidate server contract.
- 0x00B5 next and 0x00B6 close use the stored NPC conversation ID. Number input 0x0143 carries a u32. Input requests clear/hide sibling dialog/menu controls as they open, but end-to-end submit/reject and stale-conversation behavior need runtime coverage.

## String limit finding

- Current string submit builds a variable 0x01D5 frame from all bytes up to u16 packet length; the UI hides before sending and has no packet-specific input length limit.
- The available server parser copies only up to `CHATBOX_SIZE` (71 including terminator), with `CHATBOX_SIZE` defined as 70+1. A longer submitted string is silently truncated server-side. This is a candidate limit from the available server snapshot; target 2008 profile equivalence still needs confirmation before enforcing it or claiming parity.
- If the send path is bounded, UI validation must occur before hiding the input and must count bytes in the actual packet encoding, not Unicode code points.

## Shop handoff boundary

Buy/sell list and cancel requests are separate packet family functions guarded by `NpcShopMode`; they are not script menu choices. PK25.04 should verify returning from NPC text/menu to shop and shop close/cancel without mixing state or sending the wrong family.

The later PK46.02 production-send replay exercises `0146` close, `00B9` next, `0143` number, `01D5` string and `00B8` menu bytes. PK37.09 covers shop transaction packets and offline cancellation. These checks leave actual dialog control submit, retry after a failed send, cancel 255 side effects, and text/menu-to-shop transitions open. See [sender evidence](PK46.02-production-replay-2026-11-05.md).

In the selected local server source, `clif_parse_NpcStringInput` limits the copy to `CHATBOX_SIZE` under the 20080910 branch. The old branch counts the supplied terminator and permits 70 encoded text bytes. Verify the corresponding original client edit control and send routine before wiring the client limit and preserving retry state.
