# PK45.03 — party member added variants

Date: 2026-11-04. Status: client profile routing, fields and state/UI effects traced; selected 20080910 emitter fields are traced; alternate-profile semantics and replay remain open. No rows closed.

The active receive profile assigns basic party-member-added opcode 0x0104 and extended opcode 0x01E9. Both route to `HandlePartyMemberAdded`; the packet size table fixes them at 79 and 81 bytes. The handler rejects packets that are not one of the active profile IDs or are shorter than 79 bytes.

The shared payload reads AID u32@2, role u32@6, state byte@14, party name[24]@15, character name[24]@39, and map name[16]@63. If an existing member with the same AID is found, its cached HP/maxHP values are copied to the replacement record. For the active extended opcode and length at least 81, bytes 79 and 80 update item collection and division booleans. It then adds the member, marks the local player party master when AID matches and role is zero, applies cached HP to a visible actor by AID/name, and refreshes party UI.

Open work: validate the alternate 0x0104 profile and the UI use of trailing share flags; replay join, offline, and replacement cases.

## Selected 20080910 emitter comparison (2026-11-04)

With the effective `PACKETVER=20080910`, `packets_struct.hpp` selects `partymemberinfo = 0x01E9` and the legacy `PACKET_ZC_ADD_MEMBER_TO_GROUP` layout (no GID/class/base-level additions). Its packed fields are: packet type u16@0; AID u32@2; leader u32@6; x/y i16@10/@12; offline u8@14; party name[24]@15; player name[24]@39; map name[16]@63; sharePickup u8@79; shareLoot u8@80. Total length is 81 bytes.

`clif_party_member_info` sets leader to 0 for the party leader and 1 for another member, sets offline to 0 when online and 1 otherwise, fills the three names/locations, sets the two sharing flags, and sends to `PARTY`. These offsets and encodings match the client's shared `0x01E9` handler through map name. The handler ignores x/y and the two trailing sharing bytes. In this selected profile the server emits `0x01E9`; `0x0104` is not the active variant.

The `clif.cpp` and `packets_struct.hpp` file hashes match PK01.02's pinned evidence. Remaining review is whether the UI should consume sharePickup/shareLoot from this packet, alternate-profile `0x0104` behavior, and replay of join/offline/replacement order. No discovery row is closed.
