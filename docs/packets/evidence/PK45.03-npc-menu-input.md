# PK45.03 — NPC menu prompt and selection leaf

Date: 2026-11-04. Status: client receive, parsing, UI selection, and send layout traced. Server menu ordinal and cancel semantics, oversized menu behavior, and UI replay remain open. No rows closed.

## Receive and option mapping

The current packet-size profile marks server packet 0x00B7 variable length, and the receive router registers it to `HandleNpcDialogMenu`. The handler requires at least 8 bytes, reads the NPC ID as u32 at offset 4, and extracts the NUL-terminated menu string beginning at offset 8. It splits the string on `:`. Non-empty options are shown in order while their original one-based ordinal is retained, including gaps caused by empty segments. This keeps displayed entries mapped to their source menu positions.

## Selection reply

`UINpcMenuWnd` retains the per-option choice values and submits the selected value with the originating NPC ID. The client uses fixed 7-byte `PACKET_CZ_NPC_SELECTMENU` (0x00B8): opcode@0, NPC ID u32@2, choice u8@6. The send path rejects NPC ID 0 and choice 0. A choice of 0xFF closes all NPC dialog windows and resets conversation state after sending; other choices only hide the menu before sending.

## Remaining validation boundary

The client parser only assigns visible choices through 0xFE; later entries are omitted, while 0xFF is reserved by the client as cancel. The pinned server source contract for the menu string, maximum choice ordinal, and cancel value is not revalidated in this checkout. Confirm those semantics against the exact selected server emitter and parser before treating ordinal mapping or cancel as parity. Empty segments are hidden but their ordinals are preserved. No malformed/oversized packet, 254/255-option boundary, cancel path, or end-to-end script interaction was replayed. No rows are closed.


## Selected 20080910 server menu and reply contract (2026-11-04)

`clif_scriptmenu` sends 0x00B7 as a variable-length packet with packet type, total length, NPC ID, and a NUL-terminated menu string; it routes the packet to `SELF` (`src/map/packets.hpp:753–759`, `src/map/clif.cpp:2628–2648`). The selected 20080910 client size table and `HandleNpcDialogMenu` variable framing match this header and payload model.

The selected script `menu` builtin skips empty option strings and adds the number of colon-delimited choices to `sd->npc_menu`; it emits the script menu through `clif_scriptmenu`. The server warns when the count reaches 255, because the client wire choice is a byte, with 0 unused and 255 reserved for cancel. It reports excess choices but does not cap the count (`src/map/script.cpp:5125–5172`). The client only makes options through 254 selectable, so scripts with more choices can display entries that cannot be represented safely in the reply byte; this remains a source-level edge, not a parity claim.

The selected server registry parses 0x00B8 as a 7-byte `clif_parse_NpcSelectMenu` request with NPC ID u32@2 and selection u8@6 (`clif_packetdb.hpp:62`). The parser rejects selection 0 and any selection above `sd->npc_menu`, except 0xFF; accepted values are stored and passed to `npc_scriptcont` (`src/map/clif.cpp:13317–13340`). In the script menu continuation, 0xFF clears menu/input state and ends the menu; a valid ordinal selects its corresponding label. This matches the client’s one-based choice values and cancel byte.

Source contract and route are now traced. Repeated-menu replacement, empty delimiter behavior, and the >254 option warning/overflow boundary still need production replay/UI verification. No discovery row is closed.


## Additional repeated-prompt client behavior

A repeated 0x00B7 uses the existing WID_NPCMENUWND when present; UIWindowMgr::MakeWindow removes it from the child ordering, marks it visible, and returns that same instance (src/ui/UIWindowMgr.cpp:960-967). The receive handler then calls SetMenu with the new NPC ID, visible option strings, and choice ordinals (src/gamemode/GameModePacket.cpp:3451-3476). UINpcMenuWnd::SetMenu overwrites the stored NPC ID, options, and option-choice map before showing and invalidating the window (src/ui/UINpcMenuWnd.cpp:327-340). Thus client source supports replacement of a currently displayed menu on a new menu packet. It does not prove server behavior for malformed delimiters or menus exceeding 254 choices; those remain open pending selected-server parser source or runtime evidence.
