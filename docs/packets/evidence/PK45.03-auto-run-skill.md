# PK45.03 — automatic skill request

Date: 2026-11-04. Status: fixed framing, handler gate and outgoing request path traced; selected-profile semantics and replay remain open. No rows closed.

Opcode 0x0147 has a fixed 39-byte registry size and routes to `HandleAutoRunSkill`. The handler requires data and at least 39 bytes, reads skill ID u16@2, and returns for every value except `kSkillMerchantIdentify`. For that skill it calls `SendIdentifySkillUseRequest`; the helper's boolean result is ignored by the receive handler.

The helper targets the session character GID when nonzero, otherwise the account AID, and returns without sending if both are zero. It selects an outgoing use-skill-to-ID packet struct from the active map gameplay send profile (PacketVer22 versus the other profile branch), setting the profile's packet type, skill level 1, Merchant Identify skill ID and selected target GID before sending the struct bytes. No state update is made by the receive handler itself.

Open work: confirm that 0x0147 is the intended server-to-client auto-run skill packet and that only Merchant Identify should trigger this request; validate the 39-byte layout, target fallback and outgoing profile variants against the selected server/profile; replay zero GID, GID/AID fallback and send failure. Coverage routing for 0x0147 remains provisional. No independent fixture or production replay was performed for this leaf.

## Selected server 0x0147 direction and layout (2026-11-04)

The selected server defines `0x0147` as `ZC_AUTORUN_SKILL` and documents it as a notification of an auto-casted skill. Its `clif_item_skill` emitter sends a fixed 39-byte record to SELF: skill ID u16, skill type u32, level/SP/range u16 each, name[24], and upgradable byte (set false). This confirms the opcode's server-to-client direction, fixed layout, and metadata population for this source tree.

The client-side trace says its `HandleAutoRunSkill` path filters for Merchant Identify and sends an outgoing skill-use request. That does not by itself establish that the server's notification emitter is the trigger for that client request, or that both trees represent the same profile/revision. Treat the cross-direction semantic pairing as unresolved; inspect the exact client binary behavior and server callsite/replay before asserting a round trip. This is a stronger-review item; no discovery row is closed.
