# PK44.04 — Qt character-widget event-dispatch boundary

Date: 2026-11-04. The production widget action handlers are replayed headlessly; native Qt delivery remains an integration boundary.

## Source trace

`QtPlatformWindow.cpp` wraps native Qt pointer events in legacy Win32 message values and calls the application window procedure. `QtUiSpikeBridge.cpp` then routes those messages through global `g_windowMgr` state, front-menu/modal checks, popup/chat focus handling and a retained pointer-capture target before calling the character widgets. The window is a Vulkan-surface `QWindow`; the application initializes this bridge from its main-window startup path.

The existing character action checks extract and compile production widget handler bodies and drive their coordinates directly. A `QGuiApplication` alone cannot exercise the actual Qt-to-window-procedure-to-live-manager route: that requires constructing the platform window and initialized application UI state, including the global manager and its mode/widget ownership. The repository's separate Qt chat test also uses a render-control scene and native window setup specific to that subsystem; it is not a ready character-menu harness.

## Boundary

Do not treat the source-body checks as native Qt event, live `CModeMgr`, socket-send-from-widget or rendering verification. A purpose-built initialized bridge integration harness remains possible but is a broader application lifecycle task than the bounded handler replay; this gap is recorded and does not stop independent packet work. Existing character-select and character-create action evidence remains valid within its narrower scope.
