# PK46.03 immediate character deletion

The selected 20080910 character server uses `01FB` with a 56-byte packed request. The PacketVer23 character profile now sends that layout. PacketVer22 retains the existing `0068` 46-byte client layout. Its peer compatibility remains unverified. The request carries the confirmed CID and configured key, with the rest of the fixed field zero-filled.

The occupied-slot action requires confirmation naming the character, with No as the default on Windows. The login mode checks slot, index and CID again after confirmation and allows one pending deletion. The `006F` success and `0070` refusal apply only during the pending deletion submode. Success removes the matching local character once. Refusal preserves the list and carries the status message into character selection, including the party or guild restriction. Disconnect retires pending ownership.

The production replay uses isolated PacketVer23 and PacketVer22 processes and a local mock character server. Each fixture supplies its own expected wire bytes. It verifies cancellation, unsolicited results, duplicate send prevention, refusal, successful retry, and preservation of the other character. Replay supplies a deterministic confirmation response. Live deletion and the scheduled deletion family remain open.
