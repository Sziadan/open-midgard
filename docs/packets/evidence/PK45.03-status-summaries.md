# PK45.03 — initial and current status summaries

Date: 2026-11-04. Status: fixed layouts, session/character mappings and actor synchronization traced; selected-profile semantics and replay remain open. No rows closed.

The router maps 0x00BD to `HandleInitialStatusSummary` (fixed 44 bytes) and 0x0214 to `HandleStatusSummary` (fixed 42 bytes). Both reject shorter packets, parse six base stats and six stat-point costs as interleaved bytes, parse fourteen combat values as little-endian u16 fields, apply them, sync local primary actor stats, and invalidate status windows.

For 0x00BD, status points are u16@2; base STR/AGI/VIT/INT/DEX/LUK are bytes @4,6,8,10,12,14 and the respective costs are @5,7,9,11,13,15. For 0x0214, there is no status-point update; base stats are @2,4,6,8,10,12 and costs @3,5,7,9,11,13. In both formats, a selected character receives base stats capped at 255; cost values are stored nonnegative in session state.

The fourteen combat u16 values are attack, refine attack, MATK max/min, item DEF/bonus DEF, MDEF/bonus MDEF, HIT, FLEE/bonus FLEE, CRITICAL, ASPD and bonus ASPD. All are clamped nonnegative before session storage. The initial 0x00BD parser converts its ASPD field at @40 from raw motion to display ASPD; 0x0214 reads the field at @38 directly as display ASPD. Both sync the local player's six primary stats from character base plus session bonuses.

Open work: establish the effective profile and confirm both format layouts/ASPD units against server emitters; verify whether the two parsers should accept extra trailing bytes; replay initial/current summaries with and without a selected character/player, boundary values, and profile transitions, checking costs, points, combat fields, actor values and UI invalidation. No independent fixtures or production replays were performed for these leaves.

## Selected server initial-summary emission (2026-11-04)

The pinned server `clif_initialstatus` emits the 44-byte `0x00BD` packet to SELF with status points (clamped to INT16_MAX), six base stats and six `pc_need_status_point` costs, followed by fourteen combat summary fields. Base stats are capped to u8; combat fields are filled from attack/defense/magic/hit/flee/critical/ASPD status values, with non-renewal plus-MDEF clamped at zero for Frenzy. After that packet it sends individual updates for each attribute, attack range and ASPD. This explains the client's initial summary plus later parameter-update sequence and why `0x00BD` contains both base stats and costs.

The pinned selected server tree has no corresponding `0x0214` status-summary struct/emitter; only `0x00BD` is defined as `ZC_STATUS` in its packet structures. Treat the client's 0x0214 branch as a compatibility path until its profile/source is identified, rather than assuming it is active for PACKETVER 20080910. Exact stat-cost formula, full signedness/range behavior, level-up presentation and replay remain open; no discovery row is closed.
