# PK29.02 mercenary contract end

Selected rAthena `mercenary_delete` sends owner-only `0291` message 1266 for expiry or 1267 for death, before removing the actor. The client uses these notices to retire the mercenary's identity, status, targets, skill list and controls, while still displaying the localized message. It also cancels a pending mercenary skill selection. Other skill selections and the homunculus state are independent.

The production replay covers both terminal notices after `007C` and `029B` establish an active mercenary. It also verifies that an ordinary out-of-sight `0080` keeps the contract active. The selected server uses that removal packet for movement visibility as well as contract end. Six focused application checks and all 473 standalone checks passed.

The selected server handles command 2 in `clif_parse_mercenary_action` by calling `mercenary_delete(sd->md, 2)`. It sends no dismissal acknowledgment. The confirmed status-window action submits `029F 02` and retires the contract after the send is accepted. The replay checks the three wire bytes, complete local cleanup, and state retention when the connection rejects the send.

On owner death, selected `status_damage` calls `pc_dead`, which deletes the mercenary with reason 3. The resulting mercenary out-of-sight removal precedes the player's death notification. The replay sends those `0080` packets in order, checks that the first keeps the contract active, and verifies that the player's reason-1 notification retires it without clearing the homunculus. Live contract transitions remain unverified.
