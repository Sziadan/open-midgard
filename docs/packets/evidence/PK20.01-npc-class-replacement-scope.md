# PK20.01 — NPC class/resource replacement scope

## Selected contracts

- Current client fixed framing is 11 bytes for both opcodes. 0x01B0 is registered to the empty `HandleIgnorePacket`; 0x01D7 uses `HandleActorSpriteChange`.
- The local rAthena tree selects `PACKETVER 20080910` in `src/custom/defines_pre.hpp:12–13`. Its unguarded `src/map/clif_packetdb.hpp:201` registration and packed `PACKET_ZC_NPCSPRITE_CHANGE` in `src/map/packets.hpp:1456–1462` agree on 11 bytes: u16 opcode at 0, u32 GID at 2, u8 unused type at 6, and u32 class ID at 7. The local source has no verifiable commit identity.
- `src/map/clif.cpp::clif_class_change` rejects player-class IDs and emits type 0. Monster class change and homunculus evolution and mutation use the default area broadcast anchored on the changed actor. Script `classchange` uses that area route by default and selects a single attached player for `BC_SELF`. These scopes govern delivery on the server.
- `Ref/GameModePacket.cpp::Zc_NpcSpriteChange` (0x5A6980) looks up the GID in the current world, applies the class through the existing actor's virtual setter, and ignores byte 6. A missing actor has no side effects. `Ref/Npc.cpp::CNpc::SetSprJob` selects NPC, monster, homunculus or mercenary resources by class and refreshes the shadow scale.
- Existing 0x01D7 handler decodes the same 11-byte shape but interprets byte 6 as a look selector (base/hair/weapon/accessories/palettes) and updates appearance fields. It is not a substitute for 0x01B0's NPC class resource replacement.

## Bounded leaves and branches

1. PK20.02: add a distinct 0x01B0 handler for an existing actor in the current world. Unknown GIDs leave actor membership, position and deferred state untouched. Apply the [in-place representation contract](../contracts/PK20.NPC-CLASS-LIFETIME.md) without reclassifying an actor's identity from the new appearance.
2. PK20.03: verify resource ownership, GR2/sprite reload and cache invalidation, picking, effects, repeated changes, missing actors, and visible→invisible→visible transitions. Ensure replaced resources and actor children are released once and stale picking references cannot survive.
3. PK20.04: production 0x01B0 framed replay plus render/picking/resource teardown tests. Acceptance cases also include map teardown and repeated class changes. PK48 remains independent review.

Exercise `01D7` as a regression control. This scope checkpoint leaves implementation and acceptance open.
