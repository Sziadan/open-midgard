# PK20.01 — NPC class/resource replacement scope

## Candidate contracts

- Current client fixed framing is 11 bytes for both opcodes. 0x01B0 is registered to the empty `HandleIgnorePacket`; 0x01D7 uses `HandleActorSpriteChange`.
- The available rAthena packet structure for 0x01B0 is packed: u16 opcode, u32 GID, u8 `type` (documented unused and sent as 0), u32 class ID. Sender `clif_class_change` rejects player-class IDs, then broadcasts the class ID for a block-list actor; observed callsites include mob and homunculus class changes. Snapshot commit identity is unavailable, so target-2008 profile equivalence remains a gate.
- Existing 0x01D7 handler decodes the same 11-byte shape but interprets byte 6 as a look selector (base/hair/weapon/accessories/palettes) and updates appearance fields. It is not a substitute for 0x01B0's NPC class resource replacement.

## Bounded leaves and branches

1. PK20.02: add a distinct 0x01B0 handler. Resolve by GID/AID policy only from source-backed identifiers; update NPC/servant class and reconstruct the correct sprite/model representation without guessing special class exceptions. Handle missing actors using the existing deferred actor lifecycle if appropriate; avoid treating player IDs as NPCs solely by class value.
2. PK20.03: verify resource ownership, GR2/sprite reload and cache invalidation, picking, effects, repeated changes, missing actors, and visible→invisible→visible transitions. Ensure replaced resources and actor children are released once and stale picking references cannot survive.
3. PK20.04: production 0x01B0 framed replay plus render/picking/resource teardown tests. Acceptance cases also include map teardown and repeated class changes. PK48 remains independent review.

0x01D7 look variants are a neighboring contract, not alternate 0x01B0 layouts. The separate 0x01B0 `type` byte is currently documented unused; do not reinterpret it without target-profile evidence. No audit row is closed by this scope checkpoint.
