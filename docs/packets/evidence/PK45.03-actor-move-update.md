# PK45.03 — 0x0086 actor movement update

Date: 2026-11-04. Status: client 0x0086 compatibility path traced; selected server profile uses 0x02EC instead. Short-handler behavior and runtime interpolation remain open. No rows closed.

## Current packet contract

The client packet-size table fixes 0x0086 at 16 bytes, and the router registers it to `HandleActorMoveUpdate`. The handler checks for at least 12 bytes, reads GID u32@2, decodes packed source/destination position from bytes 6–11, and reads movement start time u32@12 only when length is at least 16. For lengths 12–15 it substitutes the current session server time. A nonzero movement tick updates the session's server-time estimate.

The handler ensures an actor shell, conditionally seeds player appearance for likely player IDs with missing appearance data, records the destination and actor tick, updates local-player position/chase source when applicable, and calls `UpdateRuntimeActorPosition` with source, destination, start time, and packed cell directions.

## Boundary needing review

The client declares 0x0086 fixed at 16 bytes but the direct handler guard accepts 12 bytes. This is a local framing/guard mismatch for the 0x0086 compatibility path; the selected 20080910 server does not use 0x0086. Preserve the mismatch for parser hardening review and do not use it to infer active-profile movement behavior.


## Selected server profile reconciliation (2026-11-04)

The pinned 20080910 server's `unit_walkingType` resolves to 0x02EC (`src/map/packets_struct.hpp:91–100`): the branches select 0x007B before packet version 4, 0x01DA before 7, 0x022C before 20080102, and 0x02EC from 20080102 through 20091102. `clif_set_unit_walking` builds `packet_unit_walking` with this selected type and sends it (`src/map/clif.cpp:1369–1452`). The inventory attributes the 67-byte 0x02EC form to this emitter, and the detailed selected wire trace is in [PK45.02-server-walking-20080910.md](PK45.02-server-walking-20080910.md).


The legacy 0x007B branch is selected only below packet version 4; it is not emitted by the pinned 20080910 profile. The current inventory records a 60-byte client frame, but no matching historical server wire layout is yet cataloged here, so AUDIT-0x007B remains open and should not be treated as the 0x02EC contract.

Thus 0x0086's 16-byte `HandleActorMoveUpdate` branch is not the selected server's walking packet for PACKETVER=20080910; it must remain a separate compatibility/legacy client contract. Do not merge its compact fields with 0x02EC's walking-skeleton fields. Normal framing declares 0x0086 fixed at 16 bytes, while the handler's 12-byte lower bound remains an implementation inconsistency for direct or bypassed dispatch. Short-packet behavior, parser hardening, and visual interpolation still need targeted review/replay. No discovery row is closed.


## Packet-stream short-frame resolution

The production packet-stream decoder initializes fixed packets with packetSize = knownSize, then rejects the frame when vailableBytes < packetSize before populating the PacketView (src/gamemode/PacketStreamDecoder.cpp:16-31). With the active client table’s 16-byte 0x0086 size, a 12-15 byte stream frame cannot be dispatched to HandleActorMoveUpdate; the handler’s 12-byte guard is only reachable via a direct/non-stream invocation or a different size table. This resolves the production stream rejection question from code. It does not establish runtime movement timing or alternate-profile behavior; those remain for PK45.04/runtime review.
