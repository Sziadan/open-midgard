# PK43.03 early party booking and store search

The client exposes the selected booking actions through `/partybooking register <level> <map ID> [up to six job IDs]` and `/partybooking delete`. This is a port command. The reference search found no original producer or map ID picker. The command takes a numeric server map ID, positive signed 16-bit level, and job IDs 0–254 or -1. Omitted jobs use -1. It uses the selected packetver23 map sender and the 18-byte `0802` and four-byte `0806` frames.

The client serializes one registration until the four-byte `0803` result arrives. It displays distinct feedback for success, failure, already registered, and unknown results. It ignores unsolicited results. An ordinary map transition preserves the outstanding request on the same connection. Server move and gameplay exit clear it. A successful local delete write displays that the request was sent and explains the absence of confirmation. The selected server's delete acknowledgement and booking broadcasts have zero registered length.

The eight-byte `0804` and four-byte `0808` entries lack parsers. The registered `0805` result has no reachable selected search caller. The later store-search feature is disabled at startup for MAIN 20080910, including discovery rows `0837` and `083A`. [Selected inventory](PK43.01-selected-store-booking-inventory.md)

The deploy-off MinGW build passed full packet replay, focused chat submission and world-entry handoff checks. Replay verifies outbound bytes over loopback, wildcard defaults, input validation, map-loading rejection, success and duplicate results, unsolicited replies, pending registration across an ordinary map change, reconnect cleanup, and deletion feedback. Live acceptance still needs registration, deletion and re-registration on the same character.
