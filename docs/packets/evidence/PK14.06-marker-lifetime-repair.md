## Changes made

- Added session-owned `InvalidatePartyPositions`, a monotonically changing marker revision, and shared `IsPartyMemberOnMap` / `IsPartyMarkerEligible` policy. Map names compare after the existing party normalization and ASCII case folding. Eligibility requires a valid nonnegative position, a nonzero AID, online state (`state == 0` from the selected server's 2008 `offline` byte), and a match with the current minimap map.
- Full roster replacement, position updates, party clearing and lifecycle invalidation advance the marker revision. Invalidating positions zeros coordinates and leaves party membership/options intact.
- The actual map-change session transition invalidates coordinates before updating the current map, including same-map warp reuse and server-move failure. `CGameMode::OnInit/OnExit` and `CLoginMode::OnExit` also invalidate markers at game/login/character lifetime boundaries.
- `HandlePartyPosition` ignores unavailable members, offline or wrong-map members, and invalid non-sentinel coordinates. A valid `(-1,-1)` sentinel still removes an existing marker.
- Both native minimap drawing and the Qt display-data path now call the same session eligibility policy. The minimap visual token includes the session marker revision and hashes only eligible marker data.
