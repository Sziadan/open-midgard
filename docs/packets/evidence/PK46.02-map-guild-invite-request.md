## 2026-11-04 — selected server invite and reply continuation

The selected 0x0168 parser reads the target AID from `PACKET_CZ_REQ_JOIN_GUILD` and calls `guild_invite` with the current authenticated session as inviter; the additional inviter account/character IDs in the client frame are not used by this parser. The server then rechecks guild membership and `GUILD_PERM_INVITE`, blocks guild modification on a guild-locked map, enforces instance invitation configuration, recipient `@noask` and clan restrictions, checks recipient session activity and existing guild/GvG2 state, and rejects a full guild. Missing/offline targets return without a response. Accepted invitations store pending guild ID and inviter AID on the recipient and send the invite prompt; a later invitation can replace these pending values.

Several failures have specific inviter acknowledgements (busy/pending-state conflict, disconnected target, already guilded/GvG2 target, full guild); permission, instance, clan and locked-map paths return silently or display a direct message. The parser itself has no distance check, so standard UI visibility/reachability remains important to assess.

The 0x016B reply parser passes guild ID and answer to `guild_reply_invite`. It rejects a reply whose guild ID does not match the recipient's pending invite. Reject clears both pending fields and notifies the inviter if still online. Accept rechecks that the target is not already in a guild, that the guild still exists and is not instance-blocked, and that a free member slot remains; then it creates a guild member and submits `intif_guild_addmember`. The asynchronous guild-member update is the actual membership change; this function does not optimistically set the recipient's guild ID. No production replay was run; no row closed.

## Client invitation-result receive path follow-up

The client frames `0x0169` as three bytes (`src/network/GronPacket.cpp:204`) and routes it through `Commerce::Receive` (`src/gamemode/GameModePacket.cpp:8939-8943`). The result byte at offset 2 maps 2 to “accepted”, 3 to “guild is full”, 0 to “already belongs to a guild”, and every other value to “declined” (`src/gamemode/Commerce.cpp:84`). This only records a system message; it does not apply guild membership. The selected server reply path delegates accepted membership asynchronously to the guild service, so membership notifications, not this invitation-result byte, must update the local guild state. Treat the message as result feedback, not proof of completed membership; production accept/reject and update-order replay remain open.
