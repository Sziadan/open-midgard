# PK45.03 — normal inventory list variants

Date: 2026-11-04. Status: client variant selection, item fields, and replacement behavior traced. Selected-server variant use and malformed-length policy remain open. No rows closed.

## Active client variants

The current receive profile maps normal inventory list packets to 0x00A3 (basic), 0x01EE (card slots), and 0x02E8 (timed). All three are variable-length framed packets. The client selects entry strides of 10, 18, and 22 bytes respectively.

`BuildNormalInventoryItem` decodes each entry as item index u16@0, item ID u16@2, item type byte@4, identified byte@5, amount u16@6, and allowed location u16@8. Item types 10, 16, and 17 are assigned ammunition wear mask 0x8000. The 18-byte form adds four card slots u16@10..16; the 22-byte form adds deletion time u32@18. Entries with item index 0 are rejected. Accepted entries are stored through `CSession::SetInventoryItem`, which merges duplicate item indices by accumulating counts.

## Replacement and malformed boundaries

`HandleNormalInventoryList` requires the 4-byte packet header, validates the ID and entry-size profile, then clears inventory before replacing it. A payload of exactly zero bytes clears the inventory, supporting an empty stackable-item list. A nonzero payload shorter than one entry returns without clearing, preserving stale inventory. For larger payloads, it clears and processes only complete strides; trailing bytes smaller than an entry are ignored. The packet framing layer only identifies these packets as variable length, so this handler itself does not reject a remainder or the nonempty short payload.

The valid-server meaning of empty lists, entry ordering/duplicate rules, item-type force-to-ammo mapping, and timed/card format applicability under the selected 2008 source were not confirmed here. Verify the selected emitter and replay empty list, partial record, malformed trailing bytes, duplicate indices, and each variant before closing. No rows are closed.

## Selected server inventory-list selection (2026-11-04)

For the selected 2008 packet version, the server's packet-type selection resolves normal inventory to `0x02E8` (the `PACKETVER >= 20080102` branch) and equipment inventory to `0x02D0`. `clif_inventorylist` iterates inventory slots, skips empty/invalid item records, sends stackable items in the normal list and non-stackable items in the separate equipment list, with each variable packet sent SELF. It sends a final partial packet for each nonempty group. If an ammo slot is active, it separately emits the arrow-equip update.

This explains why the client supports legacy `0x00A3`, `0x01EE`, and selected-profile `0x02E8` normal-list variants, while equipment rows are handled by a distinct packet family. Exact selected-client field/value parity, empty-list behavior, inventory ordering, and malformed-length acceptance remain unverified by replay. No discovery row is closed.


## Partial-row rejection boundary

The normal inventory-list handler now rejects a non-integral row payload before clearing prior inventory; header-only empty lists retain their existing clear behavior. This prevents a truncated variable-length snapshot with one or more complete rows plus a partial tail from replacing state with only its prefix (src/gamemode/GameModePacket.cpp:2219-2244). The Release open_midgard target built successfully after this change. Runtime/replay coverage of partial rows and empty-list semantics remains outstanding.
