# PK44.04 — Capture the character-server entry request

Date: 2026-11-04. Status: production `ConnectChar` request send and local connection transition verified; raw server echo handling remains a separate open boundary.

## Source contract

On a selected character-server endpoint, `CLoginMode::OnChangeState(ConnectChar)` opens the connection and sends a fixed 17-byte `PACKET_CA_ENTER` (`0x0065`): opcode@0, account ID@2, login ID 1@6, login ID 2@10, unused `u16@14`, and sex@16. The authoritative selected-source handshake contract says the server then echoes the raw four-byte account ID before framed character-server traffic. That raw echo is not an opcode and remains owned by the separate receive-state boundary.

## Replay

The replay seeds a synthetic selected char-server endpoint and session tuple, then drives the production `OnChangeState(ConnectChar)` path to a local listener. The captured 17 bytes matched the independent field fixture `65004433221188776655ccbbaa99000001`; the client entered its production “waiting for character list” status. The local listener intentionally sends no response. The client socket is closed after capture.

This verifies outbound request construction and the connection transition only. It does not exercise the server's raw four-byte echo or prove that subsequent framed receive traffic remains aligned. No discovery rows were closed.
