## Selected-server parser and cart-state path — PACKETVER 20080910

The selected registry assigns fixed four-byte `0x01AF` to `clif_parse_ChangeCart`, reading a 16-bit type at offset 2. The parser requires `MC_CHANGECART`; under the source's `RENEWAL` branch it also rejects an active NPC or progress state with `MSI_BUSY`. It admits types 1–5 only when the configured level thresholds pass (type 1 has no additional threshold; types 2/3/4/5 require base levels above 40/65/80/90 respectively), then calls `pc_setcart`. Other values receive no dedicated rejection response.

`pc_setcart` independently rejects a type outside 0..MAX_CARTS and requires `MC_PUSHCART` for nonzero types. At selected `PACKETVER 20080910`, `NEW_CARTS` is not defined: `mmo.hpp` enables it only from 20120201. Therefore the selected source takes the legacy option-bit path, where `pc_setcart` calls `pc_setoption` and `clif_changeoption`; when cart state changes from off to on, that path also sends the cart list/status and applies the speed penalty. The selected `config/core.hpp` includes `renewal.hpp`, which defines `RENEWAL`, so the parser's renewal NPC/progress busy gate is active under that config. `pc_setcart`'s return value is ignored by the parser. The profile/client path sends type `optionIndex + 1`, so successful state is communicated by option/cart updates rather than a dedicated change-cart ack.
