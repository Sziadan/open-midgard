# PK46.02 — SendEmotion registry request 0x01A9

Date: 2026-11-05. Status: current player-emotion action and both selected server handlers are source-traced; 0x01A9 is semantically a pet-emotion request, not a profile variant of the current player emote. Pet-action reachability and replay remain open; no row closed.

`CGameMode` resolves the chat command through `ResolveEmotionCommand`, applies a one-second local throttle, then sends `{ 0xBF, 0x00, emotion }` (three bytes) at `src/gamemode/GameMode.cpp:10913-10920`. The selected registry assigns three-byte `0x00BF` to `clif_parse_Emotion` (field position 2), while the separate six-byte `0x01A9` registration is `clif_parse_SendEmotion`. No `0x01A9` sender was found in the current source search.

The server handlers confirm distinct semantics: `clif_parse_Emotion` validates the player emoticon enum, applies the basic-skill and one-per-second gates, and processes the player emotion (`src/map/clif.cpp:11623`). The separate fixed six-byte `0x01A9` parser only acts when the session has a pet object; it reads a u32 at the registered offset 2 and calls `clif_pet_emotion` (`src/map/clif_packetdb.hpp:196`; `src/map/clif.cpp:14759-14762`). Therefore the selected registration is a pet-emotion action, not an alternate profile encoding of the current player-emotion chat command.

Stronger review should determine whether any supported current-client action can send the pet-emotion request and assign/retain its discovery ownership accordingly. The text-command player action still returns false on send failure without setting its throttle tick. No row closed.
