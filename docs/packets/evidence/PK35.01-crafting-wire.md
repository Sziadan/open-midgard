# PK35.01 selected crafting wire contracts

The selected rAthena source sets `PACKETVER=20080910`. The packed [server header probe](PK35.01-crafting-probe.cpp) checks the sizes below. S2C variable lengths include the entire header. The later refine UI is guarded in `clif_packetdb.hpp` and does not apply to this profile.

## Refine and production

- `0188` S2C is eight bytes. It carries a 16-bit result at offset 2, the local inventory client index at 4, and the resulting refine value at 6. `clif_refine` sends success (0), break failure (1), and downgrade (2) in selected NPC script paths. Ref `Zc_ack_itemrefining` displays messages and effects for 0 and 1 and updates the existing item refine value. Script `successrefitem`, `failedrefitem`, and `downrefitem` separately send the actual removal, add, and equip operations. The result receiver must never create or delete an item.
- `018D` S2C is a four-byte header followed by eight-byte rows of product ID and three 16-bit material words. `clif_skill_produce_mix_list` currently writes zero in those material words and sends a header-only list when no products qualify. `018E` C2S is ten bytes, with product ID at 2 and three material words at 4. `clif_parse_ProduceMix` checks the menu skill and trade state, revalidates the recipe, and clears the menu after processing. `018F` S2C is six bytes with a 16-bit result and product ID. `clif_produceeffect` sends it independently of inventory mutation. Source production branches use values 0 through 7. Verify each reachable result and Ref presentation before wiring notices.
- `0221` S2C is the weapon-refine skill list, with a four-byte header and 13-byte rows. Each row holds a 16-bit client inventory index, a 16-bit item ID, an eight-bit refine level, and four 16-bit card words. `clif_item_refine_list` filters identified, unequipped weapons by skill level and available material. `0222` C2S is six bytes, with a 32-bit client index at 2. `clif_parse_WeaponRefine` requires `WS_WEAPONREFINE`, rejects trade, converts the index, and clears the menu. `0223` S2C is eight bytes, with a 32-bit result at 2 and a 16-bit item ID at 6. The skill uses 0 for success, 1 for failure, 2 for insufficient skill, and 3 for missing material. Normal inventory updates own all changes.

## Repair

`clif_item_repair_list` sends `01FC` to the caster when the target has a broken, non-hatched-egg item. Rows are 13 bytes after the four-byte header, with the target's raw zero-based slot, item ID, refine byte, and four card words. The row index can be zero. The `01FD` request is 15 bytes and carries the selected row. The parser uses its index, requires `BS_REPAIRWEAPON`, and clears the menu after the skill call. The `FFFF` index cancels. No eligible items produces a skill failure instead of an empty list.

`01FE` is a five-byte result containing a 16-bit index at 2 and a one-byte result at 4, with 0 success and 1 failure. `clif_item_repaireffect` encodes the index as a client inventory index. The caster can be repairing someone else's item. Trace target versus caster acknowledgement and equipment refresh before applying any local mutation. Ref creates `WID_ITEMREPAIRWND` from the list. Source anchors are `clif_parse_RepairItem`, `skill_repairweapon`, and `skills/merchant/weaponrepair.cpp`.

## Cooking

`025A` S2C is a six-byte header with a 16-bit make type at 4, followed by two-byte product IDs. `025B` C2S is six bytes with make type and selected product at offsets 2 and 4. The cooking script calls `clif_cooking_list` with type 1. Other call sites exist for later skills and require their own applicability evidence. The parser checks trade state and current recipe eligibility before production, then clears the menu. Keep empty-list behavior and cancellation distinct from material consumption. Ref `Zc_MakingItemList` uses its existing making-arrow window with the first payload word as the mode.

## Implementation order

Implement `0188` first, with literal replay for success, break, downgrade, unknown result, and a missing index followed by actual inventory updates. Then add the `018D/018E/018F` and `0221/0222/0223` selection and reply paths. Repair and cooking follow under PK35.03 and PK35.04. Exercise malformed lengths, cancellation, menu replacement, map teardown, and successful request bytes for each list. Preserve the player skill tree. Live and independent review remain open.
