## Implementation and replay

`HandlePartyList` now rejects short, partial/trailing, over-capacity, duplicate-AID, zero-AID, empty-name, and invalid leader/offline records before changing session/UI state. It decodes all rows first, then calls `CSession::ReplacePartyRoster`, which builds a replacement list before swapping it into place. The replacement preserves cached HP by AID and carries coordinates only when AID and normalized map match and both snapshots say online. Party options absent from this roster are retained. Removed members disappear; a changed AID with a reused name cannot inherit a marker.

The replay covers full production framing/router handling of `0x0107 -> 0x00FB`, roster reordering and leadership change, marker and HP preservation, party options, malformed trailing row atomicity, the 13-member source limit, changed map, online-to-offline transition, changed AID with reused name, member removal, and the `(-1,-1)` position sentinel.
