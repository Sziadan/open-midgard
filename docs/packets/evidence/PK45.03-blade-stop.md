# PK45.03 — blade-stop effect 0x01D1

Date: 2026-11-04. Status: fixed framing and literal actor visual mutations traced; AID resolution and animation semantics need stronger review. No rows closed.

Opcode 0x01D1 is registered at fixed size 14 and routes to `HandleBladeStop`. The handler returns unless packet data exists, length is at least 14, and a world is available. It resolves source AID u32@2 and target AID u32@6 through `ResolveSkillPacketActor`, then reads a u32 mode flag@10.

When the flag is nonzero, no changes occur unless both actors resolve. For both actors, the source receives forced animation parameters `(96,4,4,96,4,1,0x5F5E0FF,0)`, fixed-ARGB is enabled and ARGB is set to (64,64,64); the target is motion-frozen and receives the same fixed-ARGB/gray treatment. When the flag is zero, the source independently receives forced animation `(96,4,4,96,4,1,1,0)`, fixed-ARGB is disabled and ARGB restored to (255,255,255); the target independently has motion freeze/fixed-ARGB cleared and ARGB restored to white. No reply or logical combat-state update occurs in this handler.

Defer meaning of the forced-animation parameters, flag lifecycle and actor-resolution rules to stronger review. Confirm AID identity, packet contract and state cleanup/reordering against the selected server/profile; replay unresolved actors and both flag branches. No independent fixture or production replay was performed for this leaf.

## Selected server blade-stop packet (2026-11-04)

The selected server confirms `0x01D1` as a fixed 14-byte `ZC_BLADESTOP` record: source block ID, target block ID, and a 32-bit active flag (`0` inactive, `1` active). `clif_bladestop` copies `src.id`, the supplied target ID, and the flag, then broadcasts in AREA scope. This supports the client handler's three-u32 layout and shows that the packet is an area event rather than a SELF-only notification.

The client handler's actor lookup/visual mutations still need replay validation, including whether its lookup keys correspond to the server's block IDs and how inactive events behave when one actor is absent. The animation parameter interpretation remains a stronger-review item; no row is closed.
