# PK45.03 — show image notification 0x0145

Date: 2026-11-04. Status: handler field extraction and game-mode cutin state update traced; legacy framing/profile support remains unverified; selected server uses 0x01B3. No rows closed.

The receive router registers opcode 0x0145 to `HandleShowImage`, but the inspected packet-size registry has no `SetPacketSize(0x0145, ...)` entry. The handler requires data and at least 19 bytes, copies 16 bytes from offset 2 into a NUL-terminated local image name, and reads image type at offset 18. Type byte 255 maps to -1. It sends game-mode message 113, which synchronously copies the name and type into `m_showImageInfo`.

`UpdateShowImageInfo` appends `.bmp` unless the resulting name already contains lowercase `.bmp` or uppercase `.BMP`. The mode's cutin state adapter/bridge later consumes this name and type for image presentation. The handler does not validate the packet ID, image-name encoding, path, or asset existence, and does not send a network reply.

Open work: source the historical 0x0145 frame size and confirm whether the active client can frame this handler; compare its type/encoding contract against the selected 0x01B3 variant; check filename/path handling and replay type 255, full-width names, and missing assets.


## Selected server profile cross-check (2026-11-04)

The pinned server clif_cutin emitter uses 0x01B3 with a 64-byte image field and one-byte type, sent to SELF; see PK45.03-show-image2.md. This pass found no matching 0x0145 definition in the pinned server packet structures, and the current client packet-size table has no 0x0145 entry even though a receive handler is registered. Classify 0x0145 as a legacy S2C client path only; selected-server reachability and framing are unproven.
