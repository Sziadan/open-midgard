`UIChooseWnd` sends `GameMsg_RequestReturnToSavePoint` from its return-to-save-point menu entry. The handler creates `PACKET_CZ_RESTART` with type byte zero and sends it directly; the menu closes only when the send succeeds. This path does not establish a client-side pending-disconnect action.

The packet is three bytes: opcode u16@0 (`0x00B2`) and type u8@2 (`0` for save-point respawn). The selected 20080910 registry records length 3 and `clif_parse_Restart`, with type at byte 2. The server's type-zero branch calls `pc_respawn(sd, CLR_OUTSIGHT)` (`src/map/clif.cpp:11837-11857`). `pc_respawn` does nothing unless the character is dead; battleground members may be handled by `bg_member_respawn`, otherwise the server stands the character and moves it to the saved map/coordinates. A failed map move sends a resurrection notification instead (`src/map/pc.cpp:9651-9663`). Type one is a separate character-select request path and is not covered by this leaf.
