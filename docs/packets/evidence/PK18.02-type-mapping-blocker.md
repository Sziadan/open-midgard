# PK18.02 — cell type mapping blocker

The update cannot be implemented reliably from current evidence:

- The client framing proves only 24-byte packet size and currently ignores the packet.
- The available sender snapshot writes a type field supplied by a caller. Its Ice Wall path sends literal wire value 5, while the internal `cell_t::CELL_ICEWALL` enum ordinal is 9. A map-cell permission path forwards a type supplied by the client. The packet type is therefore not safely derived from the internal enum.
- The repo has no matching Ref packet/type table or identity-matched 2008 sender/profile. Mapping type values to walkable/shootable/water flags, visuals, valid range, or permission behavior would be guesswork.
- No production dynamic cell overlay exists to update; implementing collision, pathfinding, and rendering would require agreeing on a shared authoritative cell model and map reload lifecycle first.

Do not add a guessed switch or mutate static GAT/base map data. PK18.02 requires stronger source/profile adjudication and design for a separate dynamic overlay. PK18.03/04 depend on a correct implementation and remain deferred; no discovery rows closed.
