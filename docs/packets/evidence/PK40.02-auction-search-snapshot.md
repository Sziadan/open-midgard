# PK40.02 auction search snapshot

The `025F` window command establishes or retires the map mode's auction search state. `0252` applies only while that state is open. It validates the 12-byte header, declared length, and exact count of 83-byte rows before replacing the current page. The decoder preserves bounded names, item and card IDs, item flags, prices, and the unsigned expiry timestamp. Empty results clear the current rows. Same-map reuse and mode teardown reset the search state.

The selected `clif_Auction_results` supplies the row layout. The reference `Zc_Auction_Windows` sends the initial search through mode message 220 and then opens the window. `Ref/dhxj/UI/UIAuction.cpp` shows that browsing starts at page one with search type 6. The pinned `mapif_parse_Auction_requestlist` uses type 6 for own sales and type 7 for own bids, and type 5 compares price. Its type 4 text filter accepts all names when the string is empty. Before wiring the initial browse, verify that behavior through the selected server and capture the request for both the general list and the separate `025C` own-list command.

Production replay verifies an open and close, a full row with a 24-byte seller name and high-bit values, empty replacement, malformed count and partial row rejection, and late pages while closed. The same-map warp fixture checks snapshot retirement. Window presentation, outbound requests, and correlation of a late response across a close and reopen remain open.
