# PK40.02 auction search snapshot

The `025F` window command establishes or retires the map mode's auction search state. `0252` applies only while that state is open. It validates the 12-byte header, declared length, and exact count of 83-byte rows before replacing the current page. The decoder preserves bounded names, item and card IDs, item flags, prices, and the unsigned expiry timestamp. Empty results clear the current rows. Same-map reuse and mode teardown reset the search state.

The selected `clif_Auction_results` supplies the row layout. The reference `Zc_Auction_Windows` sends the initial search through mode message 220 and then opens the window. `Ref/dhxj/UI/UIAuction.cpp` shows that browsing starts at page one with search type 6. The pinned `mapif_parse_Auction_requestlist` uses type 6 for own sales and type 7 for own bids, and type 5 compares maximum price. Its type 4 text filter accepts all names when the string is empty. The client uses that empty-name query for its initial `0251` browse and `025C` for the two own-list filters. An auction win refreshes the last query when the window is open and no reply is pending.

Production replay captures general browse, own bids, a price query with a page number, and the win refresh. It verifies a full row with a 24-byte seller name and high-bit values, empty replacement, malformed count and partial row rejection, and late pages while closed. Since `0252` carries no request identity, the client keeps one request in flight. On close it retires that request and discards the next valid page before sending the reopened session's initial browse. Same-map reuse preserves this drain while clearing the visible state. The same-map warp fixture checks snapshot retirement.

`intif_Auction_requestlist` can return without sending to the char server. A valid reply can also be lost when the character session disappears. A retired request with no reply therefore still blocks subsequent browsing on that mode. A reliable recovery boundary needs to account for delayed inter-server responses. Both search parsers also cancel the server-side staged item before querying, which the future staging controls must reflect. Live server verification and window presentation remain open.
