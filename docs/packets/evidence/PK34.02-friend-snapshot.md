# Atomic friend snapshots

The selected rAthena `clif_friendslist_send` sends `0201` after character authentication. `PACKET_ZC_FRIENDS_LIST` has an inclusive 16-bit length and a four-byte header. The selected 20080910 row is 32 bytes with account ID at offset 0, character ID at offset 4, and a 24-byte name at offset 8. Later versions can omit the name. The sender stops at the first zero character ID or at `MAX_FRIENDS` (40), then sends separate `0206` online notifications. The character server loads rows without an explicit sort, so the client preserves the wire order.

The receiver validates the length and row count, rejects incomplete rows, zero identities, missing names, duplicate character IDs, and repeated names, and builds the roster before swapping it into the session. Multiple characters can share an account ID. The swap initializes the rows offline, refreshes the messenger, and clears selection so an old row index cannot select a different friend. A valid header-only snapshot clears the roster.

Production replay covers a partial tail, an invalid final row, duplicate character ID, valid replacement, subsequent presence, empty replacement, and the 40-row boundary. This checkpoint covers the friend slice of PK34. Inventory, equipment, cart, and storage validation and replacement remain open.
