# PK46.02 — NPC numeric-input response 0x0143

Date: 2026-11-05. Status: numeric submit path, fixed serialization and selected server storage are source-traced, including unsigned-to-signed boundary behavior. Script interpretation and runtime boundary/send-failure replay remain open. No discovery row is closed.

## User action to sender

`UINpcInputWnd` snapshots the NPC ID and input text, hides the input window, and dispatches `GameMsg_RequestNpcInputNumber` using `strtoul(textCopy.c_str(), nullptr, 10)`. `GameMode` rejects NPC ID zero, writes the provided value into the numeric-input packet, sends `sizeof(packet)`, and returns the send result. The sender does not validate the NPC value or reverse the UI hide if the send fails. The UI conversion supplies no end pointer or explicit `errno` check on this NPC-number path.

## Client layout and profile

`PACKET_CZ_NPC_INPUT_NUMBER` contains opcode `0x0143` (offset 0, 2 bytes), NPC ID (offset 2, 4 bytes), and value (offset 6, 4 bytes), for ten bytes total. The sender selects `LegacyNpcScriptSend::kInputNumber` (`0x0143`).

## Selected registry comparison

`PK01.02-server-registry-final.csv` maps opcode `0143` to fixed length 10 and `clif_parse_NpcAmountInput`. The selected parser assigns the packet's signed `int32` value directly to `sd->npc_amount`, refreshes NPC-input idle time when configured, and resumes `npc_scriptcont` with the packet NPC ID. The UI configures number mode with edit type 1 and a 10-character maximum (`UINpcInputWnd.cpp:346-368`). Submission calls `std::strtoul(textCopy.c_str(), nullptr, 10)` without checking an end pointer or conversion error, then sends the resulting value through a `u32` field (`UINpcInputWnd.cpp:414-444`, `GameMode.cpp:6231-6240`, `Packet.h:580-585`). The selected server packet declares that same 32-bit slot as signed `int32` (`src/map/packets.hpp:1829-1834`) and assigns it directly to `sd->npc_amount` before continuing the script (`src/map/clif.cpp:13358-13372`). This establishes the representational mismatch for out-of-range values, not the intended script domain or whether edit-control filtering excludes them. The shared continuation enforces active NPC ID, secure timeout, proximity/visibility, no active progressbar, and script-state checks; rejected/stale input is silent and has no generic reply. The prompt/layout and unsigned-client/signed-server domain are detailed in [PK45.03](PK45.03-npc-number-input.md).

## Numeric conversion and signed server boundary

The UI calls `std::strtoul(textCopy.c_str(), nullptr, 10)` without checking an end pointer or `errno` (`src/ui/UINpcInputWnd.cpp:443`). No digits therefore convert to zero; a leading minus is accepted by the unsigned conversion (`-1` becomes an all-ones unsigned value), and the result is narrowed into the packet's `u32 Value` at offset 6 (`src/gamemode/GameMode.cpp:6237-6243`; `src/network/Packet.h:580-584`). The selected server assigns that field to `sd->npc_amount`, which is `int32` (`src/map/clif.cpp:13365`; `src/map/pc.hpp:506`). Consequently the 32-bit bit pattern `0xFFFFFFFF` arrives as -1 on the pinned server build; values with bit 31 set likewise enter the signed domain. Overflow is not explicitly rejected before narrowing.

## Remaining evidence and ownership

Replay zero, INT32_MAX, INT32_MAX+1, UINT32_MAX, invalid/empty text, active/stale NPC ID, timeout/progressbar, cancel, send failure and next script output. Values above INT32_MAX may become negative in the signed server field; intended script semantics need a stronger review before any clamp or normalization. Verify response/reopen lifecycle before closure. Preserve existing primary ownership and leave the discovery row open.
