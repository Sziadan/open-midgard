# PK45.03 — actor appearance and font updates

Date: 2026-11-04. Status: client layouts and state assignments traced. Selected-server emitter reachability/fields are traced; resource/render parity remains open. No rows closed.

## Font packet

The client size table fixes 0x02EF at 8 bytes and routes it to `HandleActorFont`. The handler requires 8 bytes, reads identifier u32@2 and font ID u16@6 (AID in the selected server emitter), records the actor tick, ensures a runtime actor, and assigns `m_charfont`. This handler does not itself invalidate a billboard. The field is also populated by actor spawn decoding and reset during other actor initialization paths; text/font rendering behavior was not verified here.

## Sprite/look packet

The client size table fixes 0x01D7 at 11 bytes and routes it to `HandleActorSpriteChange`. The handler reads GID u32@2, look type u8@6, and value u32@7; GID 0 and unknown look types are ignored. Supported type assignments include base/job (0), hair (1), weapon+shield packed into low/high 16 bits (2), head-bottom/top/mid accessories (3/4/5), hair/clothes palettes (6/7), shield (8), and robe (12). Most supported types update actor fields and mark the billboard dirty. Base/job changes also update session/selected-character job and relay the job to a matching skill unit; other local-PC updates synchronize session appearance fields. Robe type 12 currently only marks the billboard dirty and stores no value in the actor/session fields.

## Review boundary

The client branches and side effects are now enumerated, but this does not prove which look types/values the selected server emits, whether the robe value is consumed through another resource path, or whether font changes need explicit billboard invalidation. These handlers depend on actor spawn/resource loading and sprite catalog mappings. A stronger source/profile and visual replay should verify each look type, unknown values, local session persistence, and skill-unit interaction before closure. No rows are closed.

## Selected 20080910 font emitter follow-up (2026-11-04)

The pinned server `clif_font` is enabled when `PACKETVER >= 20080102`, which includes the effective 20080910 profile. It builds an 8-byte packet with opcode `0x02EF`, `sd->id` (account ID) u32@2, and `sd->status.font` u16@6, then sends to `AREA`. This confirms the client field is an actor/account identifier rather than a character GID, and the size/offsets match the client handler. The exact `clif.cpp` hash matches PK01.02's pinned source evidence.

The server packet reaches nearby recipients; the client records the font ID for the actor but resource lookup, unsupported font behavior, and visible refresh/render parity remain open for client-side review/replay. No discovery row is closed.
