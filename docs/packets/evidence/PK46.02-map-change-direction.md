# PK46.02 — change-direction request mismatch

Date: 2026-11-04. Status: source-backed selected-server/client profile mismatch; no runtime change and no discovery row closed.

## Request path

`src/main/WinMain.cpp` forwards the right-button input as a GameMode message. `CGameMode::OnMessage` calls `TryRequestChangeDirFromScreenPoint`; that resolves the hovered cell and calls `SendChangeDirRequestPacket(headDir, dir)`.

## Client serialization

For PacketVer22/PacketVer23, `MapSendProfile` selects opcode `0x0085`. `PACKET_CZ_CHANGE_DIRECTION2` is 11 bytes: opcode at 0, five padding bytes at 2..6, `HeadDir` at 7..8, padding at 9, and `Dir` at 10. The sender assigns both fields and sends `sizeof(packet)`.

## Selected server parser

PK01.02 pins effective `PACKETVER=20080910`. The applicable `src/map/clif_packetdb.hpp` registration (line 829, under `PACKETVER >= 20070108`) is `parseable_packet(0x0085,14,clif_parse_ChangeDir,10,13)`; selected 2008 non-renewal sections do not replace it. `clif_parse_ChangeDir` reads bytes at the registered positions and passes `dir, headdir` to `pc_setdir`.

## Result and limits

Under PacketVer22/23, the client/server opcode matches but total length differs (11 vs 14) and both field positions differ (client 7/10 vs server 10/13). Do not treat this as parity. Resolving it safely requires a selected 2008 outbound profile/layout and a production replay before changing shared PacketVer22/23 behavior. The configured deployed profile and any service-specific variant remain unproven. This is one traced request; PK46.02's full 177-request inventory remains open.
