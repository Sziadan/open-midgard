# PK42.01 selected instance contract

MAIN 20080910 uses `02CB`/65, `02CC`/4, `02CD`/71, `02CE`/10, and the C2S `02CF`/6 command. The 65- and 71-byte assignments in the 20071023 block override the earlier 20- and 26-byte definitions. The four server emitters are compiled from PACKETVER 20071128. [Effective registry](PK01.02-server-registry-final.csv)

- `02CB` starts a named reservation with a 61-byte name at offset 2 and signed queue position at 63. `02CC` updates the signed position at 2. The server sends `0xFFFF` on failed map creation and when destroying an idle reservation. The original client closes the window and shows message 1345 for a negative position update.
- `02CD` replaces the named snapshot. The unsigned 32-bit values at 63 and 67 are absolute Unix seconds for instance expiration and the idle or entry deadline. Zero at 67 means the idle timer is off. The original client distinguishes waiting, ready with idle deadline, and active without idle deadline. The receiver never converts these wire values into elapsed client ticks.
- `02CE` contains the unsigned type at 2 and idle deadline at 6. Type 0 updates that deadline, including clearing it when the idle timer stops. Types 1, 2, and 3 close the window and use messages 1346–1348 for lifetime expiry, idle expiry, and removal. Type 4 closes it silently. The selected enum declares 4 and the checked destroy and subscription paths use 1–3 and the negative queue sentinel. Unknown results have no assigned behavior in the port.
- The original client button in `Ref/UIFrameWnd3.cpp` sends command 0 while waiting and 1 while ready. Its header also defines 2 as force destroy. The selected server accepts command **3** only. It rejects trading, dead characters, and actors on instance maps, then checks the active instance owner mode, party leader or guild master, and the instance's destroyable flag. Keep the sender for the UI checkpoint and require explicit destruction confirmation. Creation and entry remain server script operations.

`instance_getsd` selects SELF, PARTY, GUILD, or CLAN recipients and has no recipient for ownerless instances. The frames carry neither the server instance ID nor its owner mode. The original client presents one current snapshot. Named frames replace it and unnamed updates apply to that slot. The selected server may publish several named instances during an info refresh, so a client-side list or exact instance correlation cannot be inferred. Confirm overlap behavior live before enabling destructive actions on ambiguous state.

The selected login path calls `clif_instance_info` from `pc.cpp` while the map is loading. Ordinary map movement can change the idle timer without retiring the reservation. Preserve the current snapshot across same-map reuse and check ordinary map transitions and server reconnect separately when wiring the window. Do not infer expiry or clear server state solely because a countdown reaches zero.

Primary client anchors are `Ref/GameModePacket.cpp` at the four `Zc_MemorialDungeon_*` handlers and `Ref/UIFrameWnd3.cpp::UIMemorialDunWnd::RefreshInfo`. The selected server's `instance.cpp` and `clif.cpp` hashes are `CBCC5F16A1F2B2670C976CD83DD257BA14E09849FEAF6F454ED8E2ED41C60311` and `76C1C4202040DAAB90F2E441FFAD05D9B9CE612D2A16EDBA55D2926C83CCBB6E`.
