## User action to sender

The helper rejects missing world/view state and view rotation, requires a hovered NPC-like actor, and calls `RequestNpcContact` with that actor's GID. ## 2026-11-04 — selected server contact continuation

The selected parser reads the `PACKET_CZ_CONTACTNPC` target AID and does not inspect the client contact-type byte. It rejects dead players, players who cannot act, an already-active NPC dialog, disabled NPC work-in-progress, and mail-writing state. For mob/player targets it routes the click into the attack request path. For NPCs it rejects floating NPCs, blocks the contact while a disallowed skill timer is active, ignores an NPC with an active progress bar, then calls `npc_click`.

`npc_click` verifies the target is a real NPC and within same-map `AREA_SIZE+1` coordinate bounds (except classless or authorized fake NPCs), and rejects hidden/disabled/dynamically hidden targets and `PCBLOCK_NPCCLICK`. It then dispatches by NPC subtype, such as shop UI or script dialogue. There is no generic contact acknowledgement; the subsequent UI/script response depends on subtype. This means the client-supplied `type=1` is not authoritative for server behavior in the selected branch.
