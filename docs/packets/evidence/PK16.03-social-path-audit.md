# PK16.03 — social path audit

## Friends

- 0x0201 uses variable framing. `HandleFriendsList` accepts any length >=4, clears the current friend roster before validating records, and computes entry count by integer division of the remaining bytes by 32. A trailing partial record is silently ignored after prior state has been destroyed. This is a concrete malformed-snapshot atomicity risk; PK34 owns its remediation and tests. Do not duplicate the fix here.
- 0x0206 requires 11 bytes and updates a friend only when both AID/GID match an existing record.
- 0x0209 requires 36 bytes. Nonzero result returns silently; success upserts the parsed friend and refreshes UI. This path has no visible failure notice.
- 0x020A requires 10 bytes and deletes by GID; absent entries are silently ignored.
- 0x0207 requires 34 bytes and records an incoming friend request as system chat text. The response/decision UI and request lifecycle are not established by this handler alone.

## Whispers and delivery notices

- 0x0097 variable inbound whisper stores sender/message and records it as whisper chat. 0x0098 is fixed at 3 bytes; `HandleAckWhisper` maps status 0 to a local `(To target) message` echo and every nonzero status to the generic `Whisper delivery failed.` system notice.
- `GameMode::GameMsg_SubmitChat` stores the last outbound target/text after a successful send, but `HandleWhisper` also overwrites those same `m_lastWhisperName` / `m_lastWhisper` fields for inbound messages. Since 0x0098 carries only a status byte, an incoming whisper before the ack can replace the text echoed for the outbound send. The pending single-slot state also cannot correlate multiple outstanding sends. Record as an implementation risk; protocol-level correlation/queue behavior needs a focused replay and review before changing it.

## Block lists and user counts

- The selected server registry contains C2S ignore commands 0x00CF (single PM ignore), 0x00D0 (ignore all), and 0x00D3 (ignore-list request). These are client requests, not evidence of the server's effective blocked set or a client-visible snapshot.
- Current client framing knows 0x00D2 (4 bytes) and 0x00D7 (variable), but the packet router has no dedicated 0x00D2/0x00D7 handler. Their exact target-profile semantics and user-count behavior remain unadjudicated; do not infer from the opcode/length alone.
- No incoming block-list snapshot or user-count state is represented by the inspected friend/whisper handlers. Exact source-profile behavior is an open gate.

## Failure notices and limits

Concrete silent outcomes include nonzero 0x0209 friend-add result, missing 0x020A friend delete, and all unhandled social responses. The generic 0x0098 whisper error does not distinguish recipient absence, refusal, or other server status. The 0x02D8–0x02DA configuration profile blocker is documented in PK16.02; 0x02C8/0x02C9 party invitation settings also cross PK15 ownership.

This is a source audit, not an end-to-end parity claim. The selected historical registry and available external server snapshot do not establish an identity-matched 2008 profile for all these paths. No coverage row is closed.
