# PK45.03 — guild position name list

Date: 2026-11-04. Status: variable framing, row alignment and position-map mutation traced; selected-server semantics and replay remain open. No rows closed.

Opcode 0x0166 is variable-length and routed through `HandleGuildWindowPacket` to `ro::guild::ReadWindowPacket`. The parser selects a 28-byte stride, requires at least the four-byte packet header, and rejects the whole packet before mutation when `(size - 4)` is not divisible by 28. Each row begins at offset 4 and contains position ID u32@0 plus bounded name[24]@4.

Each row creates or updates `state.positions[id]`, assigning the ID and name. Existing mode/tax fields are preserved for an existing position; a new entry keeps their default values. The position map is not cleared by this branch. After parsing, the outer guild-window handler recomputes local member position-derived permissions/title if a matching position exists.

Open work: validate stride, field meanings and whether this is a full or delta list against the selected server; check stale position retention and order/duplicate behavior; replay empty, aligned, partial, duplicate and unknown-ID rows and verify UI/permission consequences. No independent fixture or production replay was performed for this leaf.

## Selected server position-name emitter follow-up (2026-11-04)

The pinned `clif_guild_positionnamelist` emits `0x0166` only for a session with a guild. It serializes all 20 `MAX_GUILDPOSITION` slots in order as ID u32 plus name[24], yielding a 564-byte frame (four-byte header plus 20×28-byte rows). Thus the client’s 28-byte row stride and ID/name interpretation match the selected server, and every valid server frame supplies the full position-ID domain even when individual names are empty. The client overwrites names for those IDs while preserving locally held mode/tax fields, which are supplied separately by the position-info packet.

This resolves selected-profile framing and semantics from pinned source. Replay, malformed/custom-profile lengths, and UI refresh remain open. No discovery row is closed.
