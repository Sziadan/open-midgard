# PK45.03 — accept-enter legacy and selected 2008 variant

Date: 2026-11-04. Status: client handlers and selected server packet-version branch traced; world-load lifecycle and production replay remain open. No rows closed.

## Client registration and state transition

The client registers `0x0073` to `HandleAcceptEnter` and `0x02EB` to `HandleAcceptEnter2`. Its packet-size table sets them to 11 and 13 bytes respectively. Both handlers consume the server tick and packed x/y/direction fields, update session time and position, derive the `.rsw` world name from the current map, then switch to world mode. The extended handler intentionally ignores the extra fields after the shared position core.

## Selected server profile

The selected server's `PACKETVER=20080910` branch does not emit legacy `0x0073`: `ZC_ACCEPT_ENTER` selects `0x02EB` from packet versions `>=20080102` and `<20141022` (or `>=20160330`). The 13-byte record is opcode, start tick, packed position/direction, x/y size bytes, and font u16. The emitter fills current tick, character position/direction, size 5/5, and character font, then sends SELF. The older pre-2008 branch selects `0x0073` and omits the font field.

This resolves the discovery row's historical-vs-selected distinction: `0x0073` is a valid legacy client handler/packet variant but absent from the selected server's final 20080910 branch; `0x02EB` is the selected server packet. Validate map-load timing and the 13-byte production capture before treating this lifecycle as complete. No discovery row is closed.
