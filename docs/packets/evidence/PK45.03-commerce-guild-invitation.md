# PK45.03 — guild invitation prompt/result flow 0x016A / 0x0169

Date: 2026-11-04. Status: receive fields, prompt UI and client response construction traced; server contract and replay remain open. No rows closed.

Both opcodes route through the commerce receive handler. 0x016A has fixed size 30. It requires at least 30 bytes, sets `promptKind="guild"`, reads prompt ID u32@2 and bounded name[24]@6. The Qt commerce snapshot exposes `promptKind` and `promptName`; the QML shows a prompt with Accept/Decline buttons and sends commerce action `prompt` with amount 1/0. The action path builds a 10-byte opcode 0x016B packet with the prompt ID u32@2 and decision u32@6. It clears `promptKind` only after send succeeds.

Opcode 0x0169 has fixed size 3 and reads result byte@2. Values 2, 3 and 0 produce the notices “Guild invitation accepted”, “guild is full” failure, and “already belongs to a guild”; all other values map to a declined notice. The branch returns success after posting the note and does not otherwise mutate guild state.

Open work: confirm prompt ID/name, decision polarity, result code meanings and whether 0x0169 is a response to 0x016B under the selected server/profile; validate packet direction/size and replay accept/decline, send failure and each result. Coverage remains provisional/unresolved. No independent fixture or production replay was performed for this leaf.

## Selected server guild-invitation contract (2026-11-04)

The pinned server `clif_guild_invite` emitter confirms incoming `0x016A` is guild ID u32@2 plus guild name[24]@6, sent to SELF. The response packet `0x016B` is a separate client-to-server parser contract: guild ID u32 and answer u32, where 0 refuses and 1 accepts; it calls `guild_reply_invite`. The server result ack `0x0169` is a three-byte SELF packet with documented result codes 0=already in guild, 1=rejected, 2=accepted, 3=guild full. These meanings match the client’s explicit message mapping. This also confirms the result is the reply outcome to the 0x016B response, not an ack for the outbound 0x0168 invitation request.

This resolves selected-profile fields, decision polarity, result polarity and SELF recipients from pinned sources. The business logic that validates the guild ID/current invitation and chooses result codes is in unpinned guild code; expiry/replacement and accept/decline replay remain open. No discovery row is closed.
