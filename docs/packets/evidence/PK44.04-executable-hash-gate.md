# PK44.04 — Verify the optional 0x0204 executable-hash request

Date: 2026-11-04. Status: default omission and synthetic override send verified through the production ConnectAccount state path.

## Source and client path

The selected login server accepts fixed 18-byte `0x0204` (`u16 opcode` plus 16 digest bytes) and copies the digest into session hash state. In the client, `CLoginMode::OnChangeState(ConnectAccount)` calls `SendExeHashCheck` after the optional `0x0200` keepalive and before the account login request. `ShouldSendExeHash` enables the send for Korea/Indonesia services or when either `Login.ClientHashOverrideMd5` or `Login.ClientHashSourceExe` is configured. Payload resolution prefers a valid 32-hex-character MD5 override, then a configured source executable; stock/service-specific branches are separate.

## Replay

The existing local-mock ConnectAccount replay uses an isolated temporary `open-midgard.ini`, an America service profile, and no real credentials or server. With neither hash source configured, the captured account stream omits `0x0204` (for both `SendConnectInfoChanged` off and on). With `ClientHashOverrideMd5=00112233445566778899aabbccddeeff`, it captures exactly `04 02 00 11 22 33 44 55 66 77 88 99 aa bb cc dd ee ff` before the 55-byte `0x0064` login packet. The optional `0x0200` remains before the hash request when enabled by its separate setting. The temporary settings directory is removed after replay.

This verifies the configured synthetic override branch and default America/no-source omission. It does not establish the deployed service profile, external clientinfo intent, source-executable hashing, Korea/Indonesia built-in hash behavior, or server-side authentication policy. No discovery rows were closed.
