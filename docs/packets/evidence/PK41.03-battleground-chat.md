# PK41.03 selected battleground chat

`/battlechat` and its existing aliases reach source talk type 185, toggle the session flag and display message 1365 or 1366 with the original notice color. The existing kind-0 route uses operation 271 while the flag is set. The selected `02DB` frame contains the four-byte header, the formatted `name : message`, and a NUL. Kind 50 retains its room-input routing. The client clears the flag at a valid map change, including same-map reuse, and at mode teardown.

`02DC` reads AID at offset 4 and the formatted NUL-terminated body at offset 32. The selected server limits the body field to 256 bytes including NUL. The receiver checks declared length and termination before producing any side effects. It honors the AID exclusion list and uses source notice type 1 for ordinary team lines. Either no-talk setting suppresses that notice. A specific-name color uses source type 0 and bypasses those settings. Bubble dispatch and autosave follow independently for accepted messages. A zero-AID server notice has no actor bubble.

Source anchors are `Ref/GameMode.cpp` at `TT_BATTLECHAT_ON_OFF`, `Ref/GameModePacket.cpp::Zc_Battlefield_Chat`, and the selected server's `clif_parse_BattleChat`, `clif_bg_message` and `bg_send_message`. The server validates chat text and uses membership to select recipients. The leave notice originates in `bg_team_leave`. Live acceptance still needs a team session with an ordinary speaker, an ignored speaker, and a same-map leave.

The deploy-off MinGW build passed the full packet replay, chat submission, chat notice and world-entry handoff targets. Replay captures the outbound frame after the real command, checks localization and room routing, verifies both no-talk branches and specific-name color, compares the saved log bytes, drains invalid frames, and checks chat mode at same-map reuse.
