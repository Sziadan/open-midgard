# PK21.01 Selected NPC progress contract

The local rAthena `PACKETVER 20080910` packet table registers fixed `02F0` at 10 bytes and `02F1` and `02F2` at two bytes. The `progressbar` script builtin records the NPC and deadline, sets `WIP_DISABLE_ALL`, and emits `02F0` with color at offset 2 and seconds at offset 6. `clif_parse_progressbar` ignores a reply with no active script. It clears the stored progress and server input restriction before continuing the script. An early reply closes the script, with a close button if a message is open. Sources are `src/map/clif_packetdb.hpp:973–975`, `script.cpp::BUILDIN_FUNC(progressbar)`, and `clif.cpp::clif_parse_progressbar`.

The original `Zc_Progress` ignores the color, sends player message 82 with milliseconds and marks the local gauge as reply-bearing. `Zc_Progress_Cancel` sends message 83. Actor message 83 deletes the gauge and sends literal `F1 02` for a reply-bearing local gauge. The gauge expiry path also sends message 83, so both expiry and a server `02F2` acknowledge once. An idle abort has no reply. Sources are `Ref/GameModePacket.cpp:24303–24327` and `Ref/GameActor.cpp:3800–3845,7945–7966`.

The selected server emits `02F2` for the first walk or item-use attempt and on damage. The original progress handlers leave ordinary input flags alone. Keep the existing dialogue gates and server-authoritative abort behavior. Avoid binding script acknowledgements to ordinary skill gauge cleanup. A map change or disconnect disposes of the old gauge and deadline without replying in another session.
