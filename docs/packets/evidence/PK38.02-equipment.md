# PK38.02 equipment requests and replies

The selected rAthena `clif_parse_EquipItem` reads six-byte `00A9` with inventory index and position. `clif_parse_UnequipItem` reads the index from four-byte `00AB`. `client_index` adds two to the server inventory index. `pc_equipitem` first unequips overlapping occupants. It then sends `00AA` with the selected position for ordinary equipment or `013C` for ammunition. The selected `00AA` enum emits success 1 and failure 0. The client also preserves the legacy result-2 failure notice. `pc_unequipitem` emits `00AC` with the old wear mask on success and a zero mask on failure. Both acknowledgements are seven bytes.

Equipment drags carry their item ID to the sender, which checks that the same item still occupies a valid inventory slot. Unequip requests require a worn item. The client applies the confirmed wear state, refreshes dependent windows, and clears pending equipment indices on map change. A successful unequip must describe the row's current wear mask. `00AA` and `00AC` contain no item ID, which limits correlation after a slot is reused.

`013C` carries the ammunition slot alone. The selected server's index conversion maps the internal empty index `-1` to wire index 1. The receiver supports that sentinel and keeps zero for older clients' fixtures. A nonempty index must identify an ammunition-capable row before the receiver changes the equipped stack. Only an acknowledgement for the requested slot clears a pending wear request. Login sends the normal list before the ammo acknowledgement and the equipment list after it.

Production replay captures the equip and unequip requests and checks failed sends, stale drags, and server-confirmed state. The acknowledgement replay covers conflicting equipment slots, empty and missing ammunition slots, unrelated pending requests, and success and rejection. Live equipped appearance and storage transfers remain open.
