## Current client path

The leader-only party-window disband action sends `GameMsg_RequestPartyDisband`. After checking that the local session has party members and the client is party master, `RequestDisbandParty` iterates the current party list, skipping zero account IDs and the local account ID. It calls `RequestRemovePartyMember` for each remaining entry before requesting party leave. The member helper rejects an invalid ID/name or non-master state, normalizes the character name, copies it into the fixed packet, and sends. Each per-member send result contributes to the aggregate disband return value; no server acknowledgement is awaited between sends.

The selected parser passes packet AID/name directly to `party_removemember` (`src/map/clif.cpp:13922-13930`). The server rejects party-locked maps, missing party state and configured instance expulsion blocks; it verifies the requester is a current member and party leader, then locates the target by matching both account ID and fixed-width name before sending `PARTY_MEMBER_WITHDRAW_EXPEL` to the character service (`src/map/party.cpp:699-730`). There is no explicit requester-equals-target rejection in this function. The current client disband loop skips members with the local AID, so its normal path does not send a self-expel (`src/gamemode/GameMode.cpp:6636-6650`). The client name normalizer trims ASCII whitespace and truncates to 23 bytes, making deployed name encoding/truncation part of the AID/name match review (`src/gamemode/GameMode.cpp:6491-6504`).
