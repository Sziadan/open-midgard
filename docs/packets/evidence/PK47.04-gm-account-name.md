## PK47.04-GM-ACCOUNT-NAME-REPLY

The selected rAthena registry assigns map C2S `01DF` six bytes and map S2C `01E0` thirty bytes. The request carries the account ID at offset 2. The response echoes it and writes a 24-byte account-name field at offset 6. The implementation of `clif_parse_GMReqAccountName` in `src/map/clif.cpp:15091` calls `clif_account_name` with an empty name. The interserver lookup inside that handler is commented out.

In `HighPriest.exe.c:339492`, building the GM player menu calls `GetChatProhibittedCnt`. That function counts the actor's records for the current server and can queue message 180, which writes `01DF`. `ProcessAssignAID` retries outstanding requests after one second. `Zc_Ack_AccountName` records the returned string by AID and retires the assignment, including for a blank name.

The rebuilt GM player menu starts the lookup for eligible targets. Pending requests are keyed by AID and paced at the selected interval. A matching blank reply completes the request, and an unsolicited or duplicate reply has no effect. Pending and completed state have map-mode ownership and are cleared on warp and when the GM menu eligibility is lost.

The selected `ProcessAssignAID` copies received names into matching history rows. `UIProhibitListWnd::OnDraw` at `HighPriest.exe.c:154954` filters by server and AID and prints the raw account-name field, so an empty result renders a blank value.
