# PK45.02 — actor name acknowledgment leaf

**0194 interpretation superseded by [PK45.05](PK45.05-character-name.md):** this is a character-ID lookup response; the mixed actor-cache handler below describes the historical implementation, now repaired. Selected request/cache/lifecycle proofs are complete in that bounded checkpoint; special-item UI and broader actor-name/profile review remain open.

Date: 2026-11-04. Status: selected-source layouts and current receive/cache path traced for the legacy 0x0095/0x0194/0x0195 variants. No production replay or UI rendering acceptance in this leaf; no rows closed.

## Selected server behavior

PK01.02 pins effective `PACKETVER=20080910`. In `src/map/packets_struct.hpp`, the non-newer `PACKET_ZC_ACK_REQNAMEALL` is 102 bytes: opcode@0, GID@2, name[24]@6, party[24]@30, guild[24]@54, position[24]@78; its header is 0x0195. `PACKET_ZC_ACK_REQNAMEALL_NPC` is 30 bytes: opcode@0, GID@2, name[24]@6; its header is 0x0095. Newer title-id layouts are outside the selected profile.

The server name refresh emitter (`clif_name` in `clif.cpp`) sends the full 0x0195 record for players, including name and available party/guild/position fields. Homunculi, mercenaries, pets, NPCs and elementals use the 0x0095 record. This preserves the selected source's distinction between player affiliation data and non-player name data.

## Current client receive path

`MapSendProfile.cpp` selects 0x0095/0x0194/0x0195 as basic/party/full name responses. `GameModePacket.cpp` registers all three with `HandleActorNameAck`. For the two selected variants traced here, the handler requires at least 30 bytes, reads GID@2 and name@6, and stores the name in both actor-name maps. For active full 0x0195 with length >=102 it also reads party@30, guild@54, and position@78 (stored by the client as `guildTitle`), updates local guild cache for the local character, clears the outstanding name-request timer, and applies cached party HP when a name now matches.

## Limits

The selected source traces 0x0195 for full player name/party/guild data, 0x0095 for basic non-player names, and 0x0194 for name-by-GID responses. The current client profile labels 0x0194 actorNameAckParty, but its packet carries no party field. Request trigger/correlation, stale-name invalidation, disconnect/map-change cleanup, malformed-length behavior, and production replay remain open.


## Selected 0x0194 name-by-GID response (2026-11-04)

The pinned server defines PACKET_ZC_ACK_REQNAME_BYGID below PACKETVER 20180221 as opcode 0x0194 with a 30-byte frame: packet type, character ID u32, and name[24]. The selected 20080910 profile uses this branch. clif_solved_charname fills the ID/name and sends the packet to SELF. The client receive profile assigns 0x0194 to its actorNameAckParty alias but routes it to the common name handler, which reads only the ID and name and clears other cached affiliation fields; there is no party payload in this variant. This confirms S2C map-stage ownership for AUDIT-0x0194.
