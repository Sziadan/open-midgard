# PK45.03 — use-item acknowledgements 0x00A8 / 0x01C8

Date: 2026-11-04. Status: both client layouts and server emitter fields/routing traced; selected compile-time variant and replay remain open. No rows closed.

The client packet table defines a 7-byte basic `0x00A8` acknowledgement and a 13-byte extended `0x01C8` acknowledgement. `HandleUseItemAck` reads client item index, remaining amount, and result; `HandleUseItemAck2` also reads item ID and actor ID. Both clear the pending-use flag and update the last-card index. On success they subtract the inferred consumed amount from session inventory. The extended handler additionally launches the item-specific potion effect using item and actor IDs.

The selected server's `clif_useitemack` writes the inventory index translated to client index, amount, and result. The extended struct branch also writes client item ID and actor ID. Failed uses are sent SELF; successful uses are broadcast AREA. The server chooses `0x00A8` versus `0x01C8` through a compile-time packet branch; the effective branch for the selected 20080910 configuration must be confirmed from the exact compiler defines before fixing a golden packet contract.

Replay should cover success/failure, remaining amount versus actual inventory deltas, actor identity/disguise, pending-ACK timeout, and potion effects. No discovery row is closed.
