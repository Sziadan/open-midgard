# PK46.03 scheduled deletion transport

PacketVer23 now has login-mode send and receive paths for `0827` through `082C`. Replies require the expected operation and CID. A reservation success stores the absolute deadline. Result 0 marks a character as already queued and retains any known deadline. Result 0 supplies no date, and the selected character list omits the deletion-date field, so a fresh connection cannot reconstruct the deadline. Cancellation clears the queued state after success. Confirmation success uses the immediate deletion path's character-list update, and failures keep the record.

The scheduled transport is exercised through a mock character server. The character-selection Delete button still opens immediate deletion. The next checkpoint is the scheduled UI, including a birth-date prompt, cancellation when the reservation was made before reconnect, and clear status for an unknown deadline. Retain the server as the authority on whether the delay has elapsed. The server checks the supplied birth date on the scheduled path, independently of the immediate-delete option in the configuration.
