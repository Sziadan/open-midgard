# PK18.01 — dynamic map cell scope

## Candidate wire contract

- The audited client has static 0x0192 framing at 24 bytes and currently routes it to `HandleIgnorePacket`.
- The historical packet catalog names 0x0192 `ZC_UPDATE_MAPINFO`; the selected P01 registry does not include an identity-adjudicated row for this opcode.
- The available rAthena snapshot defines a packed 24-byte structure: packet id (s16), X (s16), Y (s16), type (s16), map name (16 bytes), total 24. `clif_changemapcell` populates these fields and sends to an explicit target or same-map recipients. Coordinates are server map-cell units; map identity is part of the packet.
- Source calls include an Ice Wall placement/removal update (hard-coded type 5 in the send path) and a permission-gated map-cell command that sends the requested type to same-map users. The snapshot also has a FIXME that the map-change command's state is forgotten when players leave the map.

## Unresolved type and profile gates

- The server snapshot's internal `cell_t` enum is not the packet's proven wire enum: its `CELL_ICEWALL` ordinal differs from the hard-coded wire value 5. Do not use internal enum ordinals as client terrain values.
- The repository has no matching `Ref` packet/type definition, selected target-profile registry row, or verified 2008 branch identity for this sender snapshot. The exact type-to-walkable/shootable/water/render semantics and valid type range remain unproven.
- Sender targets include explicit recipient and same-map distribution; local ownership also changes based on the packet's 16-byte map name. Parsing must reject malformed lengths, invalid/out-of-bounds coordinates, unknown/mismatched map names, and unsupported cell types atomically.
- No additional 0x0192 wire-length branch is established in the current client profile. Treat future/historical variants as inactive until source-backed evidence says otherwise. 0x0199/0x01D6/0x02E7 are separate PK19 work.

## Bounded leaves and acceptance checks

1. PK18.02: only after adjudicating the target wire type mapping, decode one exact variant and update both world collision/pathfinding and rendered cell state. Cover supported/unsupported types and coordinate/map rejection.
2. PK18.03: own the dynamic overlay separately from base map data; clear it on disconnect/map replacement and reapply valid same-map deltas after map load. Test leave/re-enter and map reload so stale changes cannot leak across maps.
3. PK18.04: production 0x0192 framing replay plus walking/pathfinding/render checks and teardown/reload lifecycle checks. PK48 remains an independent review.

No audit row is closed by this scope checkpoint.
