# PK18.01 dynamic map cell scope

The selected local rAthena MAIN 20080910 map server emits fixed-size `0192` (`ZC_UPDATE_MAPINFO`). The packed definition at `src/map/packets.hpp:1782` and the `clif_changemapcell` emitter at `src/map/clif.cpp:5363` establish 24 bytes. The frame has signed little-endian X at offset 2, Y at 4, and GAT type at 6. The map field at 8 is 16 bytes and is written by `mapindex_getmapname_ext`. Coordinates address GAT cells directly. This server-to-client emitter does not require a client request registry entry.

`map_gat2cell` at `src/map/map.cpp:3280` defines the wire types. Types 0, 2, 4, and 6 are walkable, shootable and dry. Type 1 is blocked for walking and shooting. Type 3 is walkable, shootable and water. Type 5 is unwalkable, shootable and dry. `map_setgatcell` applies these traits. Preserve the raw type and use the applicable trait at each consumer. The server's internal cell query enum has different values.

Ice Wall sets type 5 and sends to the area at `src/map/skill.cpp:11719`. Removal restores the saved GAT type and broadcasts to the map at `:11781`. Area-entry and area-exit visibility paths also send player-specific updates at `src/map/clif.cpp:5505` and `:5539`. Scripted invisible walls use the same emitter in `src/map/map.cpp`. Existing walls are sent to a player by `map_iwall_get` at `:3520` from map-load acknowledgement at `src/map/clif.cpp:11089`. The GM sender at `:15110` also uses the same frame. These branches explain repeated updates and restorations without a new skill-unit creation.

Primary `Ref/GameModePacket.cpp:1649` dispatches case 402 to the GAT cell setter. The selected `Zc_update_mapinfo` at `0x5A4440` independently confirms signed reads at 2, 4, and 6, width and height checks, and the final write at `0x5A4496` to the flag in `cells[x + y * width]`. This receiver does not read the map name, mutate the GAT heights, update GND surfaces, or construct an Ice Wall visual. The Ice Wall skill unit comes from the separate skill-entry path in the same server area function. The selected ground tile vertices at `Ref/3dGround.cpp:7` use the existing GAT heights. Client-side visible cell state includes the walkable hover highlight in `src/gamemode/View.cpp:1002`, which currently reads the base flag. The extra path block array in `Ref/dhxj/GameModePacket.cpp:5795` is outside the selected client contract.

## Implementation and acceptance

- PK18.02 owns the fixed receiver, world-scoped effective cell type, movement, skill approach, and rendered hover consumers. Keep base GAT data immutable because it comes from the resource cache. Use the existing normalized map identity to reject an empty or mismatched map field as a port guard. Reject malformed lengths, unsupported types, and out-of-range coordinates before changing effective cells. A repeat must be idempotent. A restoration matching base GAT may erase the override. Retain GAT heights and GND geometry.
- PK18.03 owns loading and teardown. Network dispatch runs before advancing map loading, so account for matching updates arriving before the base GAT is bound. Validate coordinates once dimensions are available. Loaded same-map warp reuse retains the current world; real world replacement and disconnect discard that world's overrides. Reapply early updates only to their owning map instance. The server can send new updates after load acknowledgement. Test early updates, same-map reuse, replacement, leave and re-entry.
- PK18.04 owns integrated verification. Replay `0192` through framing and routing, verify walk/shot distinctions, path detours and restoration, and check the actual rendered hover consumer with the wall unit path exercised separately. Verify representative assets and same-map/replacement lifecycles. PK48 performs independent review.

This source scope leaves runtime and live acceptance open. Map properties `0199`, `01D6` and `02E7` remain in PK19.
