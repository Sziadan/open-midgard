## 2026-11-04 — selected server-side semantics

Guild chat 0x017E passes through `clif_process_message`, so it enforces the authenticated speaker-name prefix, NUL/length rules, at-command handling, mute/chat-delay gates and then routes to `guild_send_message` (or battleground chat when `bg_id` is active). The client source search still found no explicit guild-chat send path; server support alone does not establish a current UI affordance.

Alliance request 0x0170 requires the requester's server-side guild-master flag and is blocked on guild-lock maps. The parser reads the target AID; the client-supplied inviter IDs are not used. `guild_reqalliance` also checks War of Emperium, online target membership, optional target-guild-master policy, same-guild relation, alliance capacity, existing pending request and duplicate alliance; target `@noask` is handled before dispatch. Accepted requests set pending guild/account IDs and send an invite prompt. Reply 0x0172 is a separate response path.

Opposition request 0x0180 and relationship deletion 0x0183 also require guild-master status and obey guild-lock checks. Opposition rejects same-guild/capacity/duplicate relationships, prevents alliance-to-opposition changes during WoE, and delegates relationship writes through the character-service interface. Deletion passes guild ID/relation to the character service and is blocked during WoE. These are source paths only; no client control was found in the bounded UI search.
