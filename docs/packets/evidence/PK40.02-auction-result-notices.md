# PK40.02 auction result notices

The selected `clif_Auction_message` sends the three-byte `0250` result. `clif_Auction_close` reserves the four-byte `025E` length and writes `025D` into the frame. The client receive table now uses four bytes for `025D`. The future outbound stop request must serialize six bytes explicitly, with a 32-bit auction ID. [Selected source inventory](PK40.01-selected-commerce-inventory.md)

The receive handlers follow `Ref/GameModePacket.cpp::Zc_Auction_Result` and `Zc_Auction_My_Sell_Stop`. The ten auction result codes and three close result codes use their reference message IDs and notice colors. The notices reach system chat even without an auction window. Unknown results leave chat alone. Code 6 also triggers a search refresh in the reference. Wire that refresh, the add-request wait state, and the window's result refresh through the auction lifecycle when it is implemented.
