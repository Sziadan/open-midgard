# PK20.02 — class resource rebuild blocker

Source review confirms the wire distinction and available server sender, but not a safe local replacement operation:

- 0x01D7's existing `HandleActorSpriteChange` changes `m_job` for a base-look update and marks appearance/billboard state dirty. It does not establish that class-specific NPC model, GR2/sprite resources, picking proxies, effects, or child objects are rebuilt/released.
- The current actor model includes a `CGameActor` base and `CPc` specialization. Runtime actor promotion/upgrades already preserve selected effect pointers and reparent message effects, so replacing the actor object risks ownership and double-release errors.
- PK20 acceptance requires visible/invisible transitions, missing/repeated changes, resource release, picking/effects, and map teardown. No focused actor recreation API/test or proof of all owned resources was identified in this bounded review.

Do not copy the 0x01D7 handler or only assign `m_job` as a purported implementation. A reliable change needs an actor/resource lifecycle design, target-profile confirmation for 0x01B0, then production replay and render/picking tests. PK20.03/04 remain dependent. No audit row is closed; continue an independent package meanwhile.
