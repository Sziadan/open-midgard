# Dynamic map cell updates in a loaded world

The production `0192` route checks the 24-byte frame and compares the bounded map field with the current world name using the existing map normalization. A valid update changes one effective GAT type in the owning world. It leaves the cached GAT resource, its heights, and the GND geometry intact. Repeating a type keeps the same effective state. A value matching the base GAT removes its override.

The client pathfinder, movement selection, three skill-approach paths, and the rendered hover tile use the same world walkability query. Types 0, 2, 3, 4, and 6 pass that query, including when those types are present in the base GAT. Types 1 and 5 block movement. The effective cell retains the distinct wire type 5, whose shootability is authoritative on the server. The client has no corresponding GAT shot query to update. The separate skill-unit path still owns the Ice Wall visual.

Production stream replay covers fixed framing, case and extension normalization, repeated type 5, wrong and empty map names, signed and out-of-range coordinates, unsupported type, shared base GAT isolation, direct path, detour, and restoration. The targeted-skill source check verifies that the initial cell and ordered fallback both use the shared effective walkability query.

The deployment-disabled build passed all 164 application checks and 473 standalone checks. On this host the test process needed the build directory on `PATH` to resolve the MinGW runtime DLLs for executables in subdirectories. The player skill tree files and installed OldRO executable matched the prior checkpoint.
