# PK45.03 — guild summary updates 0x0150 / 0x01B6

Date: 2026-11-04. Status: fixed framing, shared summary fields and local-guild synchronization traced; server variant semantics remain open. No rows closed.

Opcodes 0x0150 and 0x01B6 have fixed sizes 110 and 114 respectively and route through `HandleGuildWindowPacket`. `ReadWindowPacket` requires at least the corresponding size, then reads guild ID u32@2, level u32@6, online u32@10, capacity u32@14, average level u32@18, exp u32@22, next exp u32@26, emblem version u32@42, name[24]@46, master[24]@70 and territory[16]@94. It writes the summary into `state`, marks it loaded and returns success. Bytes 30–41 are skipped by this parser; for 0x01B6 bytes 110–113 are also not read here.

After successful parsing, the outer handler sets `m_localGuild.characterId` from the session GID and copies guild ID, name and emblem version from the parsed summary. It then recomputes local position-derived permissions/title if a matching position is available. The outer sync is only performed after the shared parser accepts the packet.

Open work: confirm whether 0x0150 and 0x01B6 are profile-specific variants and establish meanings of skipped bytes, size difference, field units and text encoding against the selected server. Replay both sizes, too-short packets, text boundaries and local guild synchronization. Coverage routing remains provisional/unresolved. No independent fixture or production replay was performed for this leaf.

## Selected server summary variant follow-up (2026-11-04)

Pinned `PACKET_ZC_GUILD_INFO` definitions resolve the profile ambiguity: for PACKETVER 20080910 the active legacy branch uses opcode `0x01B6` and the 114-byte layout, in this order: header, eleven 32-bit guild fields through emblem version, guild name[24], master name[24], manage-land/map text, and zeny u32. The `0x0150` header is annotated as belonging to older versions and is not the selected profile's active opcode. Newer profile branches change the opcode and eventually replace or extend master identity fields, so those must not be projected onto this 2008 client/server pairing.

The pinned `clif_guild_basicinfo` emitter returns without sending if no guild exists; otherwise it sends SELF and fills guild ID, level, connected/capacity/average member counts, capped experience values, emblem ID, guild/master names, map text, and zeny. Point, honor, and virtue are explicitly zeroed as unused legacy fields. This resolves selected-profile variant and several previously unknown field meanings; the older `0x0150` branch, text encoding/edge boundaries, and runtime synchronization remain open. No discovery row is closed.
