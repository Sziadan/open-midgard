# PK05.05 — terminal map receive/update handling

Implementation verified, 2026-11-05. This replaces the earlier implementation-seam deferral with the production preamble specified in the stronger review. The dedicated checkpoint is `packet(PK05.05): leave map on terminal receive failure`; no rendered acceptance is implied.

## Production transition contract

- A handler that invokes `CModeMgr::Switch` or `Quit` changes an explicit operation generation. The packet loop reports `modeOperationRequested` and stops immediately, without probing EOF or consuming a following frame. This protects accepted return/exit acknowledgements, bans and map handoffs.
- `CGameMode::ProcessNetworkUpdate` is the exact receive/decision preamble called first by `OnUpdate`, before deferred actor work, bootstrap/time-sync, world or audio work. It receives through the real packet loop/router. A terminal latch belongs to the mode instance and resets on `OnInit`; an already scheduled operation observed since construction/initialization also stops the frame.
- A mode-operation result wins over socket state and timeout. Its existing pending action, status and return intent are preserved. Repeated calls stop without issuing another operation or consuming a replacement status.
- Closed connection with `UnknownOpcode`: clear pending action and return intent, queue `Login error: server sent an unknown packet; connection closed.`, and request Login exactly once.
- Closed connection with `InvalidVariableLength`: same cleanup, queue `Login error: server sent a malformed variable-length packet; connection closed.`, and request Login exactly once. Transport still discards malformed suffix bytes without resynchronizing.
- Closed connection without a framing error: clear pending action and return intent, queue `Login: connection to map server lost.`, and request Login exactly once. Ordinary EOF is not a successful disconnect acknowledgement.
- An open idle or partially received connection continues the frame. Refusal with an open socket remains nonterminal. Timeout fallback is allowed only after a genuine drained receive attempt and retains its existing status/return-intent contract; exhausting the packet budget does not imply drain.
- Reconnection clears the transport's sticky receive error in existing `OnConnect`. A terminated map instance remains latched; initialization/new mode starts a fresh network lifetime.

The mode-operation getters expose read-only diagnostics; tests do not infer acceptance from socket closure or mutate private mode-manager state. Return-to-Login reuses the existing helper and mode lifecycle for cleanup, rather than constructing a second world teardown path.
