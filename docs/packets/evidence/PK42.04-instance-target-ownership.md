# PK42.04 instance command target ownership

## PK42.04-INSTANCE-COMMAND

The selected `02CF` is a six-byte C2S frame whose sole accepted command is the 32-bit value 3 at offset 2. `clif_parse_MemorialDungeonCommand` rejects trading, death and use from inside an instance map. `instance_destroy_command` uses the sender's current `instance_mode`, then looks up the current character, party or guild slot. It checks party leader or guild master as applicable, and checks the instance's destroyable flag. The command carries no target. The parser and owner checks return silently on rejection.

The display can differ from the command target even when the client has received a single valid snapshot. `instance_reqinfo` sets `instance_mode` only on the caller, but its named `02CB` and `02CD` emitters broadcast to the owner scope. When a member joins an existing party or guild with an instance, the request for that member can replace other members' displayed snapshot without updating their command selector. The keep and idle timer paths likewise emit named `02CD` without setting recipient selectors. Leaving an instance can set the selector in `pc.cpp` independently of which named snapshot was last displayed.

For example, a guild master with a personal instance can see the guild instance after another guild member requests its info. If the master's selector still points to the personal instance, confirming destruction from that window targets the personal instance. Neither the current displayed name, a confirmation captured before the latest packet, nor party leadership can establish the server's target. Preserve the read-only window. A targeted action requires an authoritative target contract or a separately established deployment invariant that guarantees one possible instance. Validate any such change with overlapping personal, party and guild ownership and silent rejection before connecting it.

Source anchors are `instance.cpp::instance_create`, `instance_reqinfo`, `instance_destroy_command`, `instance_startkeeptimer` and `instance_startidletimer`; `clif.cpp::clif_instance_status` and `clif_parse_MemorialDungeonCommand`; and `pc.cpp` at the map-exit timer and selector update. The outbound inventory classifies the accepted wire direction as C2S. Production replay with a connected peer verifies that the status window's close and Alt+B reopen actions send no bytes. The command remains unavailable until the client can identify the server's destruction target.
