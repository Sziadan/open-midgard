## Authoritative wire contract

`CLoginMode::OnChangeState(LoginSubMode_ConnectChar)` connects to the selected character server and sends `PACKET_CA_ENTER` (`0x0065`, 17 bytes). `PACKET_CA_ENTER` offsets are opcode u16@0, AID u32@2, login_id1 u32@6, login_id2 u32@10, unused u16@14, sex u8@16. The char server's `chclif_parse_reqtoconnect` reads this request; in `src/char/char_clif.cpp` it queues the authenticated session's `account_id` as exactly four raw little-endian bytes before it can reject for shutdown, missing login-server/auth record or authentication failure. This prefix has no opcode, length field, or `PACKETVER` variant in the selected source. Rejections that follow use framed `0x0081` after the raw prefix.

Current receive behavior is incorrect for this stage: `CRagConnection::RecvPacket` always interprets the first two queued bytes as an opcode and removes two bytes for unknown IDs. `GronPacket.cpp` additionally gives fake `0x8482` and `0x8483` entries size four, and `CLoginMode::PollNetwork` silently ignores both. Those special cases neither check the full AID nor cover other IDs. An AID whose low word equals any registered fixed or variable opcode may be falsely delivered to a feature handler; other IDs can desynchronize the following stream.

## Bounded implementation leaves

**PK04.02 — model protocol state and remove fake opcodes.** Add an opt-in raw-four-byte expectation to the production Ragnarok receive path, armed for the new character-server connection before normal reply processing. Keep account-server and map-server framing unchanged. Consume no bytes as a packet until the prefix is present; compare all four decoded little-endian bytes with the AID used in `0x0065`; clear the expectation exactly once on match; reject/close the connection on mismatch. Remove only the fake `0x8482`/`0x8483` packet-size entries and their no-op login dispatch cases. Ensure a new connection and disconnect cannot inherit an armed prefix.

**PK04.03 — production replay.** Exercise the actual `ConnectChar -> send 0x0065 -> receive raw prefix -> framed response` path. Cover AID `0x12345678`; low words colliding with an active fixed opcode and a variable-length opcode; all four prefix split boundaries; fragmented prefix followed by framed `0x0081` in one queue; coalesced prefix plus complete response; full-value mismatch; EOF with 0–3 prefix bytes; immediate reconnect to an account server; and repeated polling after successful consumption. Assert no frame is dispatched before all four bytes match, the framed suffix is preserved byte-for-byte, mismatch returns to stable login/connection failure behavior, and reconnect resets policy.

Independent raw fixtures are literal little-endian byte vectors. For `0x12345678`, expect `78 56 34 12`; a candidate collision AID `0xA1B2006C` begins `6C 00 B2 A1`, which currently resembles fixed opcode `0x006C`; use `0xA1B20069` to collide with variable opcode `0x0069`. Select additional collision IDs from the active table at test time only to choose a case; keep expected bytes literal and do not use packet structs to generate them.
