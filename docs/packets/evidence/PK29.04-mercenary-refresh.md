# PK29.04 mercenary refresh

Selected rAthena `mercenary_recv_data` sends actor spawn, `029B` identity, and the `029D` skill list in order. The map-entry and refresh paths in `clif.cpp` also send identity followed by the list. Same-GID identity refresh retains the actor job, target, pending selection and open status window. The skill cache is rebuilt from the following `029D`. A new GID retires the previous contract state. If the actor entry has not arrived yet, the new snapshot waits for an actor job before the status window can open. `CompanionIdentityReplay` exercises these cases and a zero-GID snapshot.

The selected server registers `029E` at 11 bytes, but no sender was found in the map server. The selected refresh paths use `029D`, so `029E` remains a compatibility receiver without selected-server emission evidence. `029F` option 1 also has no server response. The info window uses the cached status. Live verification and independent PK48 review remain open.
