## User action to sender

`UIJoinPartyAcceptWnd::SubmitReply` snapshots the party ID, clears the prompt state, hides the window and invalidates it before validating the ID or sending. It dispatches `GameMsg_RequestPartyInviteReply` with accept/reject as a boolean. `GameMode` calls `ReplyPartyInvite`, which rejects party ID zero, writes `Flag=1` for accept or `0` for reject, sends the full structure and returns the transport result. The cleared prompt is not restored if send fails.

## Client layout and profile

`PACKET_CZ_JOIN_GROUP` contains opcode `0x00FF` at offset 0 (2 bytes), party ID at offset 2 (4 bytes), and flag at offset 6 (4 bytes), for ten bytes total. `ActivePartySend::kReplyPartyInvite` aliases the legacy party opcode `0x00FF`.

## Selected registry comparison

## Selected server reply semantics

The selected parser reads the ten-byte request and passes its party ID and 32-bit flag to `party_reply_invite` (`src/map/clif.cpp:13879-13887`). The server accepts only `flag == 1`, and only when the invitee is not already creating or joining a party. A mismatched party ID clears both stored invite fields as a forged reply; an invitee already in a party also clears them and returns without notifying the inviter (`src/map/party.cpp:571-585`). For acceptance, it checks the target party for the configured instance-invite restriction, sets `party_joining`, fills a member record and sends `intif_party_addmember`; the invite state is not cleared in this branch before that asynchronous request (`src/map/party.cpp:587-603`). Rejection or other failure clears both invite fields and sends a rejected reply to the inviter if that account is online (`src/map/party.cpp:606-616`). This resolves the parser flag contract but leaves stale prompts, async add-member failure cleanup and membership notification ordering for replay/stronger review.

## Character-service add-member callback

`intif.cpp` dispatches the character-service add-member result to `party_member_added` with party ID, account ID, character ID and success/failure flag (`src/map/intif.cpp:1586`). The callback validates the live session identity and `party_joining`; if the player logged off before a successful add, it requests a compensating leave. Otherwise it resolves the inviter, clears `party_joining` and both pending invite fields, and if the party is missing requests cleanup leave (`src/map/party.cpp:642-663`). A failed add notifies the inviter that the party is full when the inviter is still online. Success sets the invitee party ID, sends member/option/party information, then notifies the inviter that the invitation was accepted (`src/map/party.cpp:666-680`). This closes the source-side callback/result trace; ordering against stale prompts, disband and client UI restoration still needs replay.
