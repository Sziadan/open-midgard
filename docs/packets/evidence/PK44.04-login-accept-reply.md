# PK44.04 — Replay 0x0069 login acceptance

Date: 2026-11-04. Status: bounded production framing, routing, handler and accepted-endpoint socket transition replay verified; visible UI remains open.

## Fixture and production entry

The fixture is an independent 111-byte selected-source frame: a 47-byte `AC_ACCEPT_LOGIN` prefix and two 32-byte character-server records. The records carry distinct synthetic IPv4/port/name/user-count/type/new-flag values (`192.168.1.10:6121`, `char-main`; `203.0.113.7:6122`, `char-backup`). Expected values are written as byte literals in the replay rather than generated from the client packet struct.

The replay sends the frame through `CRagConnection::RecvPacket -> CLoginMode::PollNetwork -> OnAcceptLogin` and checks the parsed session fields, sex normalization to 1, all fields in both server records, retention of both records, automatic selection of index 0, transition to `LoginSubMode_ConnectChar`, acceptance status, and reset of the account-login handshake fields. An integrated variant points the accepted first server record to a local mock char server, then invokes the production ConnectChar transition. The mock receives the connection and exact 17-byte `0x0065` `CA_ENTER` frame; the client enters its character-list wait status. A second production-framed 80-byte response (47-byte prefix, one complete record, and one trailing byte) is rejected; the handler clears server-list state, returns to Login, resets handshake state, and preserves previously accepted credentials. A third frame with 101 complete records is rejected against the client's fixed 100-entry capacity instead of silently truncating the advertised list. All results are recorded in `PK44.04-login-accept-reply.jsonl`.
