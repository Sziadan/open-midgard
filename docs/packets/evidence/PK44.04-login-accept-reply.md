# PK44.04 — Replay 0x0069 login acceptance

Date: 2026-11-04. Status: bounded production framing, routing and handler replay verified; socket connect and visible UI remain open.

## Fixture and production entry

The fixture is an independent 111-byte selected-source frame: a 47-byte `AC_ACCEPT_LOGIN` prefix and two 32-byte character-server records. The records carry distinct synthetic IPv4/port/name/user-count/type/new-flag values (`192.168.1.10:6121`, `char-main`; `203.0.113.7:6122`, `char-backup`). Expected values are written as byte literals in the replay rather than generated from the client packet struct.

The replay sends the frame through `CRagConnection::RecvPacket -> CLoginMode::PollNetwork -> OnAcceptLogin` and checks the parsed session fields, sex normalization to 1, all fields in both server records, retention of both records, automatic selection of index 0, transition to `LoginSubMode_ConnectChar`, acceptance status, and reset of the account-login handshake fields. A second production-framed 80-byte response (47-byte prefix, one complete record, and one trailing byte) is rejected; the handler clears server-list state, returns to Login, resets handshake state, and preserves previously accepted credentials. A third frame with 101 complete records is rejected against the client's fixed 100-entry capacity instead of silently truncating the advertised list. Both malformed-input results are recorded in `PK44.04-login-accept-reply.jsonl`.

## Build and verification

```text
cmake --build build-mingw-preset --target packet_stream_replay_checks open_midgard --parallel 4
ctest --test-dir build-mingw-preset -R "^packet_stream_replay_checks$" --verbose
```

`packet_stream_replay_checks` rebuilt successfully with `RO_BUILD_PACKET_REPLAY_TESTS=ON` and `RO_ENABLE_DEV_DEPLOY=OFF`. Focused CTest passed 1/1 in 2.66 seconds with local-loopback permission. The 111-byte valid two-record production frame, 80-byte partial-record rejection, and 3279-byte over-capacity rejection are preserved in `PK44.04-login-accept-reply.jsonl`. No deployment or live account/server was used.

The replay verifies selected-source multi-server parsing and client-side rejection of partial or over-capacity arrays, not a selected-server maximum count (the 100-entry limit comes from client storage). It does not execute the subsequent `ConnectChar` socket transition, Qt rendering, or visible acceptance flow. No discovery row is closed; PK44.04 remains in progress.
