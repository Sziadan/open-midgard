# PK45.03 — reconcile 0x0189 map-info meaning

Date: 2026-11-04. Status: selected-source type meaning corrected in the current client; focused gamemode build passed. No discovery rows closed.

## Conflict and authority

The earlier PK25.03 implementation followed the Ref 2008 client's wording for 0x0189 type 1 and displayed “Teleport is possible in this area.” The selected rAthena source is authoritative for server semantics. Its PACKET_ZC_NOTIFY_MAPINFO is a fixed 4-byte packet with a u16 type at offset 2. The e_notify_mapinfo_result enum assigns type 1 to NOTIFY_MAPINFO_CANT_MEMO. The caller in pc.cpp sends it when MF_NOMEMO or MF_NOWARPTO prevents memorizing a saved point; the server comment names the message “Saved point cannot be memorized.”

## Correction

HandleNotifyMapInfo still requires exactly 4 bytes and preserves type 0 (teleport restriction), type 2 (skill restriction), and type 3 (item restriction; clears m_waitingUseItemAck). Type 1 now displays “Saved point cannot be memorized.” The prior message incorrectly told the player teleport was possible.

The server packet carries no display color. The existing client color choice remains in place; visual color parity is not claimed.
