# PK45.03 — party options, member removal, and positions

Date: 2026-11-04. Status: client framing and state/UI effects traced; selected-server semantics and replay remain open. No rows closed.

The receive router maps 0x0101 to `HandlePartyOptionChanged`, 0x0105 to `HandlePartyMemberRemoved`, and 0x0107 to `HandlePartyPosition`. The packet size table fixes these at 6, 31, and 10 bytes.

`HandlePartyOptionChanged` requires 6 bytes and reads an EXP option u32@2. Value 2 reports a system error and does not update EXP sharing; other values set `m_partyExpShare` to nonzero. For packets at least 8 bytes it also reads item collection/division booleans at bytes 6 and 7, then always refreshes the party UI. However, the live size table declares 0x0101 fixed at 6, so the optional branch is unreachable through ordinary packet framing unless another framing path supplies a longer view. Confirm the selected packet variant before changing either framing or parser behavior.

`HandlePartyMemberRemoved` requires 31 bytes, extracts fixed name[24]@6, and ignores empty names. Result byte@30 values 2 and 3 produce map restriction messages and return without mutation. Other values delete the named member; if that name is the local player or result bit 0x10 is set, it clears the party. Bit 0x10 additionally records a disband message. The handler then refreshes the party UI. Confirm result-code semantics and whether clearing the whole party on bit 0x10 is correct for every variant.

`HandlePartyPosition` accepts only exactly 10 bytes, reads AID u32@2 and signed X/Y u16@6/@8, and updates the matching party member position. It does not refresh the party UI directly.

Open work: derive the effective 20080910 server registration and emitters for all three opcodes, resolve the 0x0101 length mismatch and result code meanings, then replay valid and malformed option/removal/position packets while observing party state and UI. The server reference path `src/map/clif_packetdb.hpp` is not present in this checkout, and no independent fixture or runtime replay was available here. No rows are closed.

## Selected server party options/removal/position emitters (2026-11-04)

For packet versions before 2009-06-03, `clif_party_option` uses `0x0101` and writes the EXP-share option as a 32-bit value in the six-byte packet. With `flag == 0` it sends to PARTY; otherwise it sends SELF. `clif_party_withdraw` emits `0x0105` with the member account ID, fixed character name, and result byte, using its caller-provided target. `clif_party_xy` emits `0x0107` with account ID and x/y to same-map party members; the single-recipient helper uses SELF. The removal helper sets x and y to -1 to remove the map position marker.

These server fields align with the client's three packet sizes and positions. The option's flag/result meanings and member-removal result-code UI mapping should still be validated against the selected binary and replay, especially the 0101 client branch that reports value 2. No discovery row is closed.
