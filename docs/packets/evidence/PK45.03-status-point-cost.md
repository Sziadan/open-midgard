# PK45.03 — status-point cost update

Date: 2026-11-04. Status: client framing and session/UI effects traced; server semantics and replay remain open. No rows closed.

The receive router maps 0x00BE to `HandleStatusPointCostUpdate`; the size table fixes it at 5 bytes. The handler reads status type u16@2 and cost byte@4, calls `UpdateStatusPointCost`, then invalidates status windows.

The helper maps types 32–37 to the STR, AGI, VIT, INT, DEX, and LUK cost fields (`m_standardStr` through `m_standardLuk`). It clamps the value to a minimum of zero, which is redundant for the current unsigned byte input. Unknown types do not mutate a cost field but still lead the handler to invalidate status windows.

## Selected server status-cost update (2026-11-04)

The pinned `clif_zc_status_change` emitter confirms `0x00BE` as status ID u16 plus value u8, sent to SELF. Its `SP_USTR` through `SP_ULUK` status-update callsite sends the matching status ID and the result of `pc_need_status_point` for the corresponding base stat, so values 32–37 are next-stat point costs, not stat values or remaining point totals. This matches the client’s STR/AGI/VIT/INT/DEX/LUK cost-field mapping and byte-sized value.
