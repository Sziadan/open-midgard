# PK46.02 selected party and guild requests

The pinned MAIN 20080910 registry establishes the lengths and C2S identities. Parser observations use the inspected local server tree. Its `clif.cpp` SHA-256 is `76c1c4202040daab90f2e441ffad05d9b9ce612d2a16edba55d2926c83ccbb6e`, which differs from the PK01.02 pin.

## PK46.02-PARTY-MEMBERSHIP-REQUESTS

- `00F9` creates a party using a 24-byte name at offset 2. Replay checks the 26-byte frame and name handling.
- `00FC` invites by target account ID at offset 2 in six bytes. `00FF` answers with a party ID and four-byte flag at offsets 2 and 6. Production replay captures invite, accept, and decline.
- `0100` leaves with a two-byte opcode. `0103` removes a member using a four-byte account ID and a 24-byte character name at offsets 2 and 6. The disband fixture captures ordered removal and leave requests.

`0102` remains open for item-option behavior. The map parser reads four bytes from offset 2 and passes the current server item option for this opcode. The inspected map-to-character handoff in `intif_party_changeoption` writes experience and item options as separate 16-bit words, so the upper half of the client's combined value is discarded before `mapif_parse_PartyChangeOption` receives it. The existing replay captures the client serialization. It does not establish that the UI's requested item option takes effect. Party alternatives `01E8`, `02C4`, and `02C7`, and the invitation preference request `02C8`, retain their review status.

## PK46.02-GUILD-MEMBERSHIP-REQUESTS

- `014D` is the two-byte permissions query. `014F` sends a four-byte information subtype at offset 2. The guild window refresh fixture captures the permissions-only request without a guild and the full refresh with types 0–4 for an existing guild.
- `0168` invites a player with target AID, inviter AID and inviter CID at offsets 2, 6 and 10 in a 14-byte frame. The inspected parser uses the target AID. Replay checks the exact frame and client permission and input gates.
- `016B` is a ten-byte invite reply with guild ID and answer at offsets 2 and 6. The inspected parser forwards both fields to the membership handler. Replay starts at incoming `016A` and checks accept, decline, duplicate suppression, and prompt preservation on send failure.

Live membership changes, replacement invite ownership, the remaining guild administration and alliance requests, and PK48 independent review remain open.
