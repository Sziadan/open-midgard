# PK16.03 user count and social packets

## PK16.03-who

The selected rAthena `clif_parse_HowManyConnections` reads a two-byte `00C1` request. `clif_user_count` replies to the requester with six-byte `00C2` and a little-endian four-byte count at offset 2. The existing `/who` sender preserves its service gates. The new receiver uses message 178 for the numeric count. The reference's China non-admin path uses the low word and population messages 825–829 at thresholds 1000, 3000, 6000, and 10000. The bundled English table leaves those entries empty, so the port supplies English category text.

The selected whisper-block contracts are `00CF` (27 bytes, fixed 24-byte name and operation), `00D0` (3 bytes, operation), and `00D3` (2 bytes, list request). Operations 0 and 1 are deny and allow. The server bounds a name to 23 bytes and reports duplicate denies as success. `clif_wisexin` sends four-byte `00D1` with operation and result, where 0 is success, 1 is failure and 2 is capacity. `clif_wisall` sends the same shape as `00D2` with results 0 and 1. The selected server's allow-all clears the global deny flag first, or clears the named server list if that flag is already off. `clif_PMIgnoreList` returns `00D4` with an inclusive 16-bit length and 24-byte name rows. The existing chat submission replay covers these frame shapes, notices, and reference local-exclusion side effects. The client keeps those local name/AID effects separate from the server list.

Friends use `0202` (26-byte name request), `0203` (10-byte AID/CID delete), `0206` (11-byte AID/CID/offline byte), `0207` (34-byte invite), `0208` (14-byte AID/CID/u32 answer on the selected registration), `0209` (36-byte u16 result, AID, CID and 24-byte name), and `020A` (10-byte AID/CID delete notice). The selected server sends `0209` results 0 for success, 1 for refusal or stale pending IDs, and 2 for a full list. The reference also handles 3 for the other list being full. The client now displays each recognized result in the reference color and updates the friend list on success. A missing add target uses server text, and a self-add or offline inviter can return silently.

Replay covers the four-byte count, a China population boundary, refusal with a literal name, capacity failure, and unknown friend results.

For PACKETVER 20080910, `clif_wis_message` emits `0097` with a length at offset 2, sender name at offset 4 (24 bytes), and terminated text at offset 28. Admin and sender GID fields are gated to later versions. The client verifies the declared length, sender, and terminal NUL before routing a whisper. Replay checks missing terminator, embedded NUL, and empty sender without changing chat or outgoing metadata.

`clif_wis_end` sends three-byte `0098` with result 0 for success, 1 for offline, 2 for named block, or 3 for global block. An invisible higher-ranked recipient may produce the offline result. Autotrade returns a server-origin `0097` instead of `0098`. The existing whisper replay exercises each result and the reference hidden-acknowledgement branches. Incoming messages preserve outgoing metadata. The reply carries only a result, and off-map replies can arrive later than local ones. When multiple whispers overlap, the current client can attribute a result to the latest recipient. A FIFO would also be ambiguous because autotrade omits the acknowledgement.
