# PK45.03 — map-change receive handlers 0x0091/0x0092

Date: 2026-11-04. Status: client contract traced; server emission and profile parity remain open. No discovery rows closed.

## Client registration and layouts

The active map receive profile assigns `mapChangeBasic = 0x0091` and `mapChangeServerMove = 0x0092` (`src/network/MapSendProfile.cpp`, lines 199–200). Both IDs register to `HandleMapChange` (`src/gamemode/GameModePacket.cpp`, lines 8771–8772); the receive packet-size table lists 22 bytes for 0x0091 and 28 bytes for 0x0092 (`src/network/GronPacket.cpp`).

`ParseMapChangePacket` rejects null data and packets shorter than 22 bytes, and rejects IDs outside the active receive profile. It reads a 16-byte, NUL-terminated map name from offset 2, normalizes it, and reads little-endian x/y u16 at offsets 18/20. For 0x0092 with at least 28 bytes it reads IPv4 u32 at offset 22 and port u16 at offset 26; `hasServerMove` is true only if both are nonzero. Parsing succeeds only for a nonempty normalized map name (`src/gamemode/GameModePacket.cpp`, lines 3768–3797).

## State and follow-up

`HandleMapChange` closes commerce transactions and applies map-change session state. If the destination is already loaded and this is not a server move, it prepares same-map reuse, sends the load-end ACK, records loading/bootstrap ticks, and returns. Otherwise it displays the loading screen. A server-move reconnect failure returns to login; success continues into world-map loading (`src/gamemode/GameModePacket.cpp`, lines 8050–8112). These are client code paths; runtime outcomes have not been replay-verified.

## Selected 20080910 server contract

The available pinned source matches PK01.02 provenance: `src/map/clif.cpp` SHA-256 is `e00eddae72d4569f126efc91ed645cad0d99b4d0b6460790a441354e4b1afa69`, equal to the recorded source hash.

- 0x0091 is `PACKET_ZC_NPCACK_MAPMOVE`, packed fields `packetType`, `mapName[MAP_NAME_LENGTH_EXT]`, `xPos`, `yPos`. `MAP_NAME_LENGTH_EXT` is 16, so the struct is 22 bytes. `clif_changemap` writes opcode, obtains the extended map name, assigns x/y, and sends `SELF` (`src/map/packets.hpp:688–694`, `src/map/clif.cpp:2153–2162`).
- 0x0092 is `PACKET_ZC_NPCACK_SERVERMOVE` for profiles before 20170315, with the same map/x/y prefix plus `ip` u32 and `port` u16; packed size 28. The later domain form is guarded by `PACKETVER >= 20170315` and therefore is not selected by 20080910. `clif_changemapserver` writes the map/position/address/port and sends `SELF` (`src/map/packets.hpp:696–718`, `src/map/clif.cpp:2165–2187`).
- `clif_changemap` call sites include `clif_refresh` and `clif_parse_LoadEndAck` rewarp handling in `src/map/clif.cpp` and two map/session transition sites in `src/map/pc.cpp` (inventory/state refresh after changing the active map; locations 2273 and 7116).
- `clif_changemapserver` is called by `chrif_changemapserverack` after transfer acknowledgment, when that path has not taken the auth-failure branch (`src/map/chrif.cpp:455–466`). The surrounding routine then handles saving/removing the transferred character from the old map-server.

The packet struct sizes, field offsets and SELF routing match the local client packet-size table and `ParseMapChangePacket`: 0x0091 carries map name[16], x/y; 0x0092 carries those fields plus IPv4 and port. The 20080910 compile guard selects the 0x0092 fixed form. The client reconnect failure path returns to login; that client behavior is traced above.
