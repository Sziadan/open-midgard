# PK38.02 inventory item use

The selected rAthena registry maps `0439` to the eight-byte use request, with the inventory index at offset 2 and AID at offset 4. `clif_parse_UseItem` subtracts two from the index and uses the authenticated session. Invalid indices return silently. An ordinary refusal calls `clif_useitemack` with result zero when the item exists. `pc_useitem` sends the remaining stack quantity on immediate consumption and the current quantity when consumption is deferred. `01C8` carries the index, client item ID, actor AID, quantity, and result. Success is broadcast to the area and failure is sent to the owner. `00A8` is the basic reply and carries the index, quantity, and result.

The client now bounds use requests to actual selected inventory slots. It validates both reply layouts before updating inventory. Local `01C8` inventory updates require the current row's item ID to match the reply. Remote use feedback remains actor-scoped. Valid success updates the absolute remaining quantity and refreshes inventory-dependent windows. Matching rejection leaves quantity intact. Card composition uses its own `017A` request and keeps its context across normal item requests and replies. The basic reply does not carry an item ID, and the extended reply cannot distinguish two item instances with the same ID in the same slot.

Production replay covers the `0439` bytes, remote use, malformed result, item-ID mismatch, rejection, partial consumption, and final removal. The mercenary scroll fixture now uses a valid inventory index. The standalone ammunition check compiles the current inventory-category replacement routine and verifies that a normal-list ammo stack stays equipped across the equipment-list refresh. Packet replay, corpse lifecycle, skill-choice lifecycle, world-entry handoff, standalone ammunition, and rendered item-use feedback all passed.
