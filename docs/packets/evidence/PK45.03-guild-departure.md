# PK45.03 — guild departure and expulsion

Date: 2026-11-04. Status: fixed variant framing and membership/session/actor effects traced; selected-server semantics and replay remain open. No rows closed.

The router maps both 0x015A (66 bytes) and 0x015C (90 bytes) to `HandleGuildDeparture`; the handler enforces the corresponding minimum length and reads a fixed name[24]@2. Empty names are ignored. It removes every matching member from `g_session.m_guildWindow.members` and erases each matching account from `mode.m_guildPosList`.

If the name matches the local character name, the handler clears local guild state, guild window and guild skill items; erases the local actor name-list entry; clears player guild ID and emblem version when a world player exists; and records a system message. 0x015C uses the “expelled” message; 0x015A uses “left the guild.” Nonlocal departures do not produce a chat message. No explicit guild-window refresh is called here.

Open work: validate packet variants, the fixed name offset and departure reason mapping against server emitters; verify duplicate/missing member behavior and whether absence of an explicit refresh is intentional; replay local/nonlocal leave and expel, stale guild-position entries and no-world receipt, observing all guild windows/actor caches. No independent fixture or production replay was performed for this leaf.

## Selected server departure/expulsion emitters (2026-11-04)

The pinned 20080910 server branch confirms the legacy name-based variants. `clif_guild_leave` emits `0x015A` with character name[24] and reason[40] (66 bytes total); `clif_guild_expulsion` emits `0x015C` with character name[24], reason[40], and account name[24] (90 bytes total). For PACKETVER before 20100803, the account name is deliberately sent empty. Both are sent with the server's `GUILD_NOBG` target. This supports the client's name-based removal and explains why the 2008 profile does not use newer character-ID variants.

The packet framing and legacy field selection are now source-backed. Exact GUILD_NOBG recipient scope, business-side ordering relative to membership removal, and runtime/reason-text cases remain open; no discovery row is closed.
