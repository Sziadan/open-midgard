# PK50.03 selected quest updates

The selected MAIN 20080910 registry defines `02B3` add at 107 bytes, `02B4` removal at 6, `02B5` objective progress as variable length, and `02B7` active status at 7. The inspected local `clif.cpp` matches the SHA-256 recorded in the [party crosswalk](PK46.02-party-guild-crosswalk.md).

- `02B3` supplies membership state and mission details. The local `clif_quest_add` writes one byte at offset 7 for its documented four-byte start field. The journal leaves start time unknown for an incremental add. The expiry at 11 is intact. The `02B2` snapshot still supplies the full start time.
- `02B5` describes all objectives for one quest in database order. Its count is at offset 4. Each 12-byte row contains quest ID, monster ID, required count, and current count. Matching by slot preserves separate counters for repeated monster IDs. The server substitutes the Poring ID in mission details when an objective has no displayable monster, so that slot also accepts the raw monster ID from progress. The complete update is validated before any counters are applied.
- `02B4` removes membership and mission details. The server uses the same packet for completion and removal. Later progress and status for a removed ID leave it absent.
- `02B6` carries a known quest ID and one-byte desired active state. The request comes through the game-mode action, and the cache updates only from `02B7`. The local server silently discards requests for an unavailable quest. The journal control still needs to call the action and display the confirmed state.
