## Source-backed wire contract

- rAthena `packets_struct.hpp` defines `PACKET_ZC_NOTIFY_POSITION_TO_GROUPM`: 10 bytes total, opcode `0x0107`, signed 32-bit account ID at offset 2, signed 16-bit X at offset 6, signed 16-bit Y at offset 8. The values are map cell coordinates.
- `clif.cpp:8063-8074` broadcasts a member's current AID/X/Y to `PARTY_SAMEMAP_WOS`; the single-recipient emitter sends the same fields during map synchronization.
- `clif.cpp:10153-10164` sends X=-1 and Y=-1 from `clif_party_xy_remove` as the dot removal sentinel. `party.cpp:1365-1370` calls it when a party member leaves the map.
- `party.cpp` also synchronizes both peers' position on same-map party member updates. No server-side client request registration applies; this is S2C data.
- Client `GronPacket.cpp` frames 0x0107 at 10 bytes; the production router currently ignores it. Existing party roster state is keyed by account ID and has map-name, role and health but no coordinates or marker lifecycle.
