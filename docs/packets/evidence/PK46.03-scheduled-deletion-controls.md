# PK46.03 scheduled deletion controls

The PacketVer23 character-selection Delete action opens a Windows dialog shared by the native and Qt entry paths. The dialog names the character and offers scheduling, canceling a reservation, confirming scheduled deletion with a six-digit birth date, and immediate deletion. Close is the default. Both permanent-delete actions require a separate named confirmation. PacketVer22 keeps its immediate-delete flow.

The dialog displays the known absolute deadline in UTC. It also represents a queued character with an unknown deadline. The selected character list omits the deletion timestamp, so the dialog offers the server-backed actions after reconnect even when the client has no local reservation record. The server decides whether the delay has elapsed and whether the birth date matches.

The production action validates the same slot and CID after each prompt. Replay supplies deterministic dialog responses through that action and verifies exact packets, closing the dialog, declining final confirmation, pending request ownership, deadline handling, cancellation and retry after server refusal. The Windows dialog's visual layout and live server deletion remain open.

## Reply recovery

Immediate deletion and scheduled reserve, cancel, and confirm now share the 15-second character-request deadline. A successful send starts the wait. A matching reply clears it, while an unrelated scheduled reply leaves it active. A failed send or unanswered request closes the connection and requires a fresh sign-in. No character is removed locally until a matching success reply arrives. After reconnect, the selected list shows whether the character still exists. The scheduled-delete controls remain available to resolve any reservation that the legacy list cannot display.
