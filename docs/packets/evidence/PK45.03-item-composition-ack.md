# PK45.03 — item composition acknowledgment

Date: 2026-11-04. Status: fixed framing and current inventory/result effects traced; server result semantics and replay remain open. No rows closed.

Opcode 0x017D has a fixed seven-byte registry size and routes to `HandleItemCompositionAck`. The handler requires data and at least seven bytes, reads equipment item index u16@2, card item index u16@4, and result byte@6. Before branching on the result, it resets the current game mode's `m_lastCardItemIndex` to zero when a mode exists.

For result 0, it looks up both inventory entries. Only when both exist and each stored item index is nonzero does it copy the equipment entry, place the card's item ID into the first zero-valued equipment slot (if any), remove one card from inventory, and write back the equipment entry. Regardless of whether those item lookups permit the mutation, it refreshes inventory-dependent windows and emits a success notice. Result 1 emits a failure notice and leaves inventory unchanged beyond the earlier last-card reset. Other result values produce no notice or inventory action. No reply is sent.

Open work: confirm result values, item-index identity and slot insertion/consumption semantics against the selected server/profile; verify full-slot and missing-item behavior and whether success notice should depend on mutation; replay each result value. Coverage ownership remains provisional. No independent fixture or production replay was performed for this leaf.
