## Required transition matrix

| Receive outcome | Pending action | Required result |
| --- | --- | --- |
| Open connection, no complete packet | Any | Stay in map mode; retain the pending action and its existing timeout behavior. |
| Valid packet(s), receive queue drained while open | Any | Dispatch in order; continue map mode. |
| Unknown opcode or invalid variable length | None or pending | Stop framing immediately; discard the malformed stream/suffix through existing disconnect; request Login with a durable malformed-packet status. Do not synthesize an acknowledgement. |
| Ordinary EOF or fatal receive error | None or pending | Stop map processing; request Login with a durable connection-closed status. A pending return or exit request must not be treated as accepted. |
| Accepted return-to-character-select acknowledgement, then terminal receive | Any | Preserve the acknowledgement's already-requested Login transition and session return flag; do not overwrite its status or transition. |
| Accepted exit acknowledgement, then terminal receive | Any | Preserve the accepted application quit; terminal handling must not replace it with Login. |
| Repeated update before mode handoff | Any terminal outcome | Report/transition/cleanup once; perform no further world update. |
| Reconnect | Any previous receive state | `OnConnect` clears the transport error and valid traffic is accepted. |

The open/no-data row must remain distinguishable from terminal EOF. Keep the existing disconnect timeout fallback for an open connection whose acknowledgement simply does not arrive. On terminal failure, clear the pending disconnect request only as part of the established Login transition; never mutate it into a successful acknowledgement. The two acknowledgement rows require the production caller to detect a transition already accepted during the same packet loop.
