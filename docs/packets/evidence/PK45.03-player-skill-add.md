# PK45.03 — player skill-add notification

Date: 2026-11-04. Status: client packet, reused entry parser, and session insert traced. Server semantics and filtering parity remain open. No rows closed.

The client size table fixes 0x0111 at 39 bytes and routes it to `HandlePlayerSkillAdd`. The handler clears `m_isReqUpgradeSkillLevel` before validating the skill record, then decodes the 37-byte record starting at offset 2 using `BuildPlayerSkillListEntry` and inserts/replaces it with `CSession::SetSkillItem`. That decoder reads SKID/type/level/SP cost/range/upgradable from the same offsets as 0x010F. It rejects only null data or SKID 0; unlike the full player skill list, this add path does not apply the `IsPlayerSkillTreeSkid` range filter.

The pass did not validate whether 0x0111 can add non-player skill IDs under the selected server, or whether the shared upgrade flag should clear for unrelated/invalid skill records. Verify the source meaning of this packet, permitted ID range, and ordering relative to full-list/update packets. Replay valid add, duplicate add, invalid/zero ID, out-of-range ID, and delayed add after list replacement. No rows are closed.
