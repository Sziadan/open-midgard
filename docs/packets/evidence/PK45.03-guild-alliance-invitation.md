Both the buttons and Escape/close send the `prompt` action, with Accept encoded as amount 1 and Decline as 0 (`src/qtui/qml/RoCommerce.qml:282-293`).

`Commerce::Dispatch` builds the alliance response as opcode `0x0172`, length 10, prompt ID u32@2, and decision u32@6. If `SendPacket` fails, the prompt remains; on success, `promptKind` is cleared (`src/gamemode/Commerce.cpp:21,143-144`). The selected 20080910 server registry independently records `0x0172`, length 10, parser `clif_parse_GuildReplyAlliance`, fields at offsets 2 and 6 (`PK01.02-server-registry-final.csv`, sequence 133). The incoming `0x0171` branch replaces the singleton prompt kind/ID/name; `CloseTransactions` also clears the prompt. No expiry/timer behavior is established by these paths.

## Selected server prompt/reply correlation follow-up (2026-11-04)

The pinned `clif_guild_reqalliance` emitter defines `0x0171` as inviter account ID u32@2 plus guild name[24]@6, and sends it to the invited session. The `0x0172` parser uses registry offsets 2 and 6 and passes those values as `account_id` and `flag` to `guild_reply_reqalliance`. The client’s prompt ID therefore carries the inviter account ID back to the server; `guild_reply_reqalliance` resolves that ID with `map_id2sd` and checks the stored proposed guild against the inviter's current guild. It treats `flag == 1` as consent and other values as rejection.

The pinned `clif_guild_allianceack` contract documents result flags 0–5 as already allied, rejected, accepted, other guild at alliance limit, own guild at alliance limit, and alliances disabled. The client `0x0173` message table maps these same numeric slots to matching messages. However, the current unpinned `guild.cpp` response routine appears to send ack flag 3 to the inviter on the explicit rejection branch, which conflicts with the documented flag-3 meaning and expected decline flag 1. The routine also checks guild limits and may send paired 3/4 limit notices. Treat this as a stronger-review candidate until the exact intended server revision and response recipients are confirmed.
