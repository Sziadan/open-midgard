# PK24.03 — actor state ordering boundary

> Current disposition — 2026-11-05: Exact numeric review distinguishes EF_HEAL(312) from EF_HPTIME/EF_SPTIME(331/332); the reviewed battle caller is not evidence of a live 331/332 double heal. PK24.05 investigates the remaining exact emitter/Ref authority and ordering oracle before any code change; broader actor/UI work remains open. See [second review](REVIEW-2026-11-05.md).

## Confirmed source behavior

- `ApplySelfStatusUpdate` first writes recognized status values to session state, then updates the live player actor. HP/SP use full-width `u32` fields; base/job EXP now remain unsigned after PK24.02.
- The 0x0284 `HandleNotifyEffect3` path treats local effect IDs 331/332 as HP/SP recovery, advances the legacy shared RNG sequence, and applies `AddVital` directly to both actor and session state before rendering the effect. The path does not cap to max HP/SP and does not branch on active Hallucination status.
- Active status icons, including Hallucination ID 34, are stored separately in session state. That alone does not prove whether 0x0284 values 331/332 are authoritative recovery deltas or display-only amounts under Hallucination.

## Unresolved acceptance risk

The server's generic 0x0284 contract says its final u32 is effect-dependent visual data. The available source did not establish target-profile call sites for effect IDs 331/332 or whether authoritative 0x00B0/0x00B1 resource updates bracket them. Adding these values directly to HP/SP may double-apply recovery, exceed maximums, or let a hallucinated display value change actual resource state. Removing the update may also lose legitimate resource changes if no status packet is sent. Do not change this behavior until the target 2008 sender/reference establishes the relationship.
