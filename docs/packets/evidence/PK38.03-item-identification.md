# PK38.03 item identification

The selected rAthena `clif_item_identify_list` sends a variable `0177` with a four-byte header and one two-byte client inventory index per unidentified item. It emits a list only when it has at least one row. `clif_parse_ItemIdentify` requires an active Item Appraisal menu and accepts the four-byte `0178`. The `-1` cancellation and invalid or already identified rows clear the menu without a reply. `skill_identify` emits the five-byte `0179` result, where zero is success and one is failure. `pc_identifyall` also emits `0179` without a chooser request.

The client rejects malformed, out-of-range, or duplicate list rows before replacing the chooser. It remembers the item ID for each offered slot and revalidates the row at submission. It keeps the chooser available when sending fails. A matching result can update the submitted slot while the item ID still matches. A valid new menu, map change, or game-mode exit retires the pending request. Unsolicited results still update valid inventory rows. The protocol gives only a slot index in `0179`, so same-ID replacement and unsolicited updates cannot be correlated to an individual item instance.

The production replay opens the chooser from `0177`, checks that a failed send leaves it open and a stale row sends nothing, and captures `0178` at slot 101 on double-click. It also checks malformed results, duplicate list rows, a different item replacing the submitted slot, failure, and unsolicited success. Live Item Appraisal and Magnifier, rendered chooser comparison, and a new menu after a silently rejected request remain open.
