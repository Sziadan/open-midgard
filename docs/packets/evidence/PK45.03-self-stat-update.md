# PK45.03 — self stat update

Date: 2026-11-04. Status: client framing and selected-character/player mutations traced; server layout and replay remain open. No rows closed.

The receive router maps 0x0141 to `HandleSelfStatInfo`; the size table fixes it at 14 bytes. The handler reads status type u32@2, base value u32@6, and plus value u32@10. It delegates to `ApplySelfStatUpdate`; when that reports success it logs current player STR/AGI/VIT/INT/DEX/LUK and invalidates status windows.

The helper recognizes attribute types STR=13, AGI=14, VIT=15, INT=16, DEX=17, LUK=18. It stores each plus value in the corresponding session `m_plus*` field. When a selected character record exists, it writes the base value to that attribute, capped at 255. If there is no world player, the helper returns whether a selected-character record exists; thus an unknown type can still report success in that case and trigger log/UI invalidation even though no field changed. With a world player, it stores `base + plus` into the corresponding actor attribute, clamped to u16, and returns false for unknown types.

Open work: confirm field order, type IDs and widths against the selected server's stat-update emitter; validate expected stat ranges and overflow handling; replay all six attributes, unknown types with/without a world player, and large base/plus values while checking character, session plus-stat, actor and status-window results. No independent fixture or production replay was performed for this leaf.

## Selected server self-stat emitter (2026-11-04)

The pinned server `clif_couplestatus` contract confirms the 14-byte `0x0141` payload: status type u32, base/default stat u32, and plus stat u32, sent to SELF. Its six attribute cases pass the corresponding `sd.status` base value and `sd.battle_status - sd.status` derived bonus for STR, AGI, VIT, INT, DEX, and LUK. This matches the client’s separation of base values into the selected character record and plus values into session state; the packet does not represent an absolute combined value.

The numeric status-ID enum is in unpinned `map.hpp`, so confirm those literal IDs against the intended revision before treating them as pinned proof. Client capping of base stats, selected-character-only behavior, status-window refresh, and replay at boundaries remain open. No discovery row is closed.
