# PK25.01 — dialogue and script message scope

## Discovery inventory

PK25 currently owns 21 provisional primary rows: 0x0090, 0x0091, 0x0092, 0x0095, 0x00B4, 0x00B5, 0x00B6, 0x00B7, 0x00B8, 0x00B9, 0x00C5, 0x00C8, 0x0142, 0x0143, 0x0144, 0x0146, 0x0189, 0x01D4, 0x01D5, 0x08B3, and 0x08D6. Historical opcode labels alone do not close their semantics.

## Source-backed message contracts

- Existing S2C dialogue handlers cover 0x00B4 variable say text, 0x00B5 six-byte wait/next, 0x00B6 six-byte close, 0x00B7 variable menu, plus 0x0142 number-input request and 0x01D4 string-input request. C2S replies/choice paths include 0x00B8/0x00B9 and 0x0143/0x01D5; PK25.02 audits indexes, cancel values, length/string bounds, and dialog lifetime.
- Server 0x0144 `ZC_COMPASS` is a packed 23-byte notification: u32 NPC ID, type, X, Y; u8 marker ID; u32 color. Server docs say NPC ID is ignored; type 0 displays 15 seconds, 1 persists until death/teleport, 2 removes; color is 0x00RRGGBB. Coordinates are map cells represented as u32 on wire but originate from u16 map coordinates.
- Server 0x0189 `ZC_NOTIFY_MAPINFO` is 4 bytes: u16 type. Values 0–3 select distinct teleport/map restriction messages; unknown values need a bounded behavior and must not become a bogus choice.
- The selected local rAthena `20080910` profile emits `0144` from `clif_viewpoint`, including `viewpoint` and `viewpointmap` scripts. `Ref/GameModePacket.cpp::Zc_compass` ignores the NPC ID, removes type 2, and replaces the marker record and start tick by ID for all other values. `Ref/GameMode.cpp::DrawCompassOnMiniMap` keeps timed markers through 15,000 ms, blinks on the first 500 ms of each second and draws an 8×2 plus 2×8 cross. PK25.03 owns receive and UI verification.

## Bounded leaves and traps

1. PK25.02 audits message/menu/input/next/close and merchant shop handoffs. Selection indexes must preserve server order; cancellation is not a normal menu index; string input must honor packet-specific byte limits and remain bound to its originating NPC/conversation.
2. PK25.03 implements 0x0144 marker lifecycle using the existing minimap map-cell transform, 0x0189 text notifications, and only proven missing script choice/input paths. Must handle remove, expiry, map change, duplicate IDs, and UI ownership.
3. PK25.04 production framing replay plus dialog/menu/input/close, marker expiry/removal, and map notification UI lifecycle checks. Shop/vending remain separate protocol families. PK48 remains independent review.

No discovery row is closed by this scope checkpoint.
