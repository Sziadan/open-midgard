# PK45.03 — self movement acknowledgment

Date: 2026-11-04. Status: framing, packed-coordinate decode and local actor updates traced; selected-server 0x0087 emitter traced; replay remains open. No rows closed.

Opcode 0x0087 is registered with fixed size 12 and routed to `HandleSelfMoveAck`. The handler returns if data is absent, the packet is shorter than 12 bytes, or the session character GID is zero. It reads a server move-start tick u32@2 and updates the session server time. Six packed bytes at offset 6 are decoded into source x/y, destination x/y and cell x/y using `DecodePos2MoveData`.

For the active session GID, the handler records last-PC identity and recent-seen tick, writes the destination into `m_actorPosList`, and updates the session player position while preserving the current direction. It also sets attack-chase source to the destination, clears the world player's move-ack wait flag when that player exists, then calls `UpdateRuntimeActorPosition` with both endpoints, tick and decoded cell coordinates. This branch does not explicitly send a reply.

Open work: replay tick wrap, source/destination edge cases, and valid/missing-session/malformed packet behavior.


## Selected server 20080910 contract (2026-11-04)

The pinned server defines PACKET_ZC_NOTIFY_PLAYERMOVE as a packed 12-byte record: opcode, u32 movement start tick, and six packed movement bytes. clif_walkok fills the tick from client_tick(gettick()), packs the session current and target cells, and sends 0x0087 to SELF. This confirms map-stage S2C ownership for the local player walking notification. It is distinct from 0x02EC area movement updates for visible actors.

The client contract matches the 12-byte frame and routes 0x0087 to HandleSelfMoveAck; runtime tick wrap and coordinate/replay edge cases remain open.
