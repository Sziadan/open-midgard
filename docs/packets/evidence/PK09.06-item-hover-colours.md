Verified 2026-11-05. Dedicated checkpoint: `packet(PK09.06): restore source-defined item hover colours`. Broader PK09.04 and independent PK48/PK49 remain open.

## Source and implementation

Primary `Ref/Session.cpp::GetItemDisColor` returns `0xFFFFFF00` only for identified items whose raw bind word is 2, `0xFFFFFFFF` for other identified items, and `0xFFAAAAAA` for unidentified items regardless of bind word. Primary `Ref/UIItemWnd.cpp` and `UIFrameWnd2.cpp` pass this into hover-help balloons, rather than using it as a universal list-label colour. `Ref/Mode.cpp::MakeHelpBalloon` explicitly converts BYTE2/BYTE1/BYTE0 into the balloon's native font colour, confirming packed RGB input and the required COLORREF channel conversion. The selected server `clif_item_equip` emits raw bind 0/1/2; value 1 is not already bound. No badge is established by this evidence.

`ITEM_INFO::GetNameColorArgb` now supplies that exact rule. Native inventory/storage hover painters use it through QColor or explicit RGB channel conversion. Their existing native bodies were extracted into `DrawNativeToHdc` / `DrawNativeHoverOverlay`; real native OnDraw/overlay paths delegate to those same methods. This permits actual native captures in the current Qt-force-enabled build without changing its UI-mode policy or substituting a fabricated painter.

The shared ItemHoverInfo carries the colour through inventory, storage, equipment and item-shortcut producers into the real gameplay adapter's tooltip anchor. Skill shortcuts and non-item identity help retain their default white. Equipment's visual token now includes the raw bind word so a bind-only change invalidates its cached presentation. The original native hover-overlay consumers are inventory and storage; equipment/shortcut hover names use the QML anchor path.

Qt commerce rows now carry the same name colour and existing shared hover text. Real Tile mouse enter/exit drives one source-coloured help popup. Names no longer replace unrelated status text in every footer. The popup uses a dark surface, retaining readable exact white/yellow/gray foregrounds on the existing light panels; unrelated list labels, icons, panel palettes and native tooltip backgrounds remain unchanged. Row destruction clears the hovered tile, preventing stale help after authoritative removal.
