# PK45.03 — guild relation list 0x014C

Date: 2026-11-04. Status: variable framing and relation-vector replacement traced; field semantics and selected-server contract remain open. No rows closed.

Opcode 0x014C uses variable-length framing and is routed through `HandleGuildWindowPacket` to `ReadWindowPacket`. The parser selects a 32-byte row stride and rejects packets shorter than the four-byte header or whose remaining bytes are not an exact stride multiple. Only after validation does it clear `state.relations`. Each row appends a relation with hostility flag u32@0 (converted to nonzero/zero), guild ID u32@4 and bounded name[24]@8. A valid header-only packet therefore clears the relation vector; duplicate rows remain duplicates and are kept in packet order.

After successful parse, the outer handler recomputes local position-derived permissions/title if the local member has a matching position. The relation branch itself sends no reply. Coverage routing remains provisional.

Open work: verify row identity, hostility polarity and whether this is a complete snapshot against selected-server evidence; replay empty, aligned, malformed, duplicate and unknown-guild rows and confirm any UI consumers. No independent fixture or production replay was performed for this leaf.

## Selected server relation-list emitter follow-up (2026-11-04)

The pinned `clif_guild_allianceinfo` emitter confirms that `0x014C` is a variable packet with a four-byte header followed by packed 32-byte relation records: relation int32, guild ID int32, and name[24]. It skips entries whose guild ID is nonpositive, copies `guild_alliance.opposition` into the relation field, and sends the resulting packet to SELF. It returns without sending if the session has no guild. This confirms the client's 32-byte stride and replaces its relation vector from an authoritative selected-server emitter. The exact ally/enemy encoding for this field is supported by the separate relation contract (0=ally, 1=enemy); values outside that domain and empty-list runtime behavior still need replay. No discovery row is closed.
