## Source layout and behavior

Selected rAthena `PACKET_HC_NOTIFY_ZONESVR` is fixed 28 bytes: opcode at 0, character ID at 2, extended map name `[16]` at 6, IP at 22, and port at 26. `chclif_send_map_data` writes `htonl(map_server_ip)` and `ntows(htons(map_server_port))`; on the selected little-endian wire the IP bytes are network-order bytes while the port is little-endian. The client removes the `.gat` suffix, stores the endpoint, clears local guild/window state for the new character session, disconnects the character server and transitions to ZoneConnect.

The independent fixture uses character ID `0x10203040`, `prontera.gat`, IP bytes `0a000001` (10.0.0.1), and port bytes `e917` (6121). It sends through `CRagConnection::RecvPacket -> CLoginMode::PollNetwork -> OnNotifyZonesvr` while the char-server socket is open over loopback, then checks the parsed endpoint, stripped map, GID, guild-state reset, connected flag, socket close and transition.
