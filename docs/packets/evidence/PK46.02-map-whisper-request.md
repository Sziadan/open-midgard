## Selected-server whisper routing — PACKETVER 20080910

The selected registry maps variable-length `0x0096` to `clif_parse_WisMessage` with the message-length, target-name and text fields at offsets 2, 4 and 28. The parser runs `clif_process_message`, logs the whisper, and handles NPC-prefixed or channel-prefixed targets before ordinary player delivery.

For an ordinary target, the local map server requires an exact character-name match. A local recipient in autotrade rejects the whisper. `ignoreAll` and per-name ignore checks block senders at or below the recipient's group level; an invisible higher-level target can be reported as offline. If the recipient is not local, the map server sends an inter-server whisper request; with no other map server available it returns target-offline immediately.

On remote delivery, `intif_parse_WisMessage` resolves the exact target character, checks ignore-all and the recipient's per-session ignore list, and either replies with failure or delivers through `clif_wis_message` and replies success. The map-side bounded trace does not establish full char-server routing/fallback semantics or the client-visible response order for each failure class. ## Character-service fanout and result aggregation — 2026-11-05

For remote delivery, the map server sends a character-service whisper request containing an ID, sender group level, sender/target names and message bytes (`src/map/intif.cpp:311-350`). The character service checks the declared payload against its whisper-size bounds, looks up the target name in the character database, rejects a missing target or self-target, and rewrites the destination to the canonical stored name (`src/char/inter.cpp:1167-1210`). It then stores a `WisData` record, fans the request to map servers as `0x3801`, and records the number of expected map replies (`inter.cpp:1071-1087,1211-1233`).

Each map server resolves the exact local target, applies ignore-all/per-name ignore checks and replies with the request ID plus status. The character service decrements the outstanding count and returns a result to the source map when all map servers report failure or any map reports a non-failure status; later replies for an erased ID are ignored (`src/map/intif.cpp:1278-1308`, `src/char/inter.cpp:1235-1253`). A maintenance pass removes expired `WisData` entries after `WISDATA_TTL` without sending a result in that function (`inter.cpp:1113-1127`), so source-side timeout/UI behavior needs explicit replay. This traces delivery routing, not durable message storage. Verify whether a timed-out source request is recovered or left pending, plus multi-map duplicate-target, ignore, offline-target and reply-reordering cases before closure.
