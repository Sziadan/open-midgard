# PK45.04 — party-list boundary source self-review

Date: 2026-11-04. Status: client branch behavior recorded; authoritative malformed-packet policy and replay remain open. No rows closed.

`HandlePartyList` rejects null data and lengths below 28 bytes. Before parsing entries, it caches positive party HP values for existing nonzero AIDs, then calls `CSession::ClearParty`, which clears members, name, master status, and share options. It reads the new party name from offset 4, computes `entryCount = (packetLength - 28) / 46`, parses only that many complete entries, restores cached HP by AID, applies cached HP to visible actors, and refreshes the party UI once after the loop.

There is no exact-modulo check for `(packetLength - 28) % 46`. A remainder from 1 to 45 bytes is silently ignored after the previous party state has already been cleared and replaced by the complete entries. This is source behavior, not evidence that such packets are valid or that replacement is intended for malformed input.

Self-review limits: the client receive profile marks this family variable length, but the selected server registry does not provide an authoritative outbound serialization contract for this client handler. Replay should cover minimum length, one complete entry, duplicate AIDs, HP preservation, and each partial-tail size class, while observing party/UI state. No replay was run and no discovery row is closed.
