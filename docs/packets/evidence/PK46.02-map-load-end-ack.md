# PK46.02 — map load-end acknowledgement 0x007D

Date: 2026-11-05. Status: profile opcode, two-byte frame, map-load send/retry path and selected server bootstrap entry gates are source-traced. Full lifecycle/retry integration remains open for stronger review and replay. No row closed.

`SendLoadEndAckPacket` sends only the active profile's `notifyActorInit` opcode as two bytes. The field is 0x007D in the legacy, PacketVer22 and PacketVer23 map-send profiles. Normal map loading sends after scene/camera preparation, records the send result and transitions to `MapLoading_AwaitActors`. Same-map warp reuse also sends the acknowledgement immediately.

After a successful initial send, the await-actors loop retries when at least 900 ms has elapsed and no synchronization request has arrived. A successful retry changes `m_sentLoadEndAck` to 2 and resets the ack/bootstrap timestamps. A failed retry leaves the state at 1, so later update passes can retry again. If the initial send fails, the retry condition (`m_sentLoadEndAck == 1`) is not met. These are client-side rules; they do not establish the selected server's world-entry transition.

The selected registry assigns fixed two-byte `0x007D` to `clif_parse_LoadEndAck` (`clif_packetdb.hpp:32`). The parser returns when `sd->prev` is non-null; it also clears `connect_new` and returns if the session is inactive or character loading is incomplete. A rewarp clears its flag, sends `clif_changemap`, and returns (`src/map/clif.cpp:10746-10764`). On the normal path it clears `warping`, spawns the player and companions, performs status/visibility initialization, may send guild notice, and eventually clears `connect_new` (`clif.cpp:10766-10818,11042-11112,11180`). This is a broad 437-line lifecycle handler; only the entry gates and bootstrap landmarks are traced here. Stronger review should confirm the full initialization ordering and how client retry/synchronization interacts with these early returns. Replay initial/retry failure, synchronization around the threshold, same-map reuse and actor-bootstrap timing before closure. Primary ownership remains PK47; no row closed.
