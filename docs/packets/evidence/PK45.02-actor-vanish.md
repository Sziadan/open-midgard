# PK45.02 — actor vanish and death transition leaf

Date: 2026-11-04. Status: selected-source wire layout, reason values, emitter scope, and current receive transitions traced. No production replay/UI acceptance in this leaf; no rows closed.

## Selected server packet and emitter

PK01.02 pins effective PACKETVER=20080910. src/map/packets.hpp::PACKET_ZC_NOTIFY_VANISH is packed to 7 bytes: opcode@0 (0x0080), GID@2 (u32), reason@6 (u8). clif_clearunit_single and clif_clearunit_area emit this layout. Source comments define reasons 0=out of sight, 1=died, 2=logged out, 3=teleport, 4=trickdead. Area sends exclude the source except for death; disguised actors also receive a self packet with the disguised GID.

## Current client receive and lifecycle

The receive router registers fixed 0x0080 to HandleActorVanish. The handler requires 7 bytes, reads GID@2/reason@6, and erases position/AID caches.

- Reason 0 removes the runtime actor.
- Reason 1 calls BeginActorDeath; if no actor exists it removes it. The local player death flags are set when the GID is local.
- Other reason values remove the runtime actor.
- The handler clears PC selection, last-monster, and lock-on IDs for the vanished GID.
- RemoveRuntimeActor also erases name caches/request timers and chase targets. BeginActorDeath keeps actors visible for the death transition; monsters receive the dead/fade state, while PCs remain visible until a later remove packet.
