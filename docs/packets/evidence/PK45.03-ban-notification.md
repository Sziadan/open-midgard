# PK45.03 — ban notification disconnect

Date: 2026-11-04. Status: client framing and mode/disconnect effects traced; reason semantics and reset completeness remain open. No rows closed.

The receive size table fixes 0x0081 at 3 bytes and the router maps it to `HandleBanDisconnect`. The handler only checks for a non-null packet and length at least 3; it does not inspect the third byte or distinguish a reason. It calls `ReturnToLoginMode`, which clears the pending disconnect action, clears session inventory items and chat events, disconnects `CRagConnection`, and switches the mode manager to mode 0 with an empty argument.

## Selected server ban/disconnect notification (2026-11-04)

The selected server defines `0x0081` as opcode plus one-byte error code, sends it to the client socket, then marks the connection for EOF. The source documents codes including server closed (1), already logged in (2), timeout/lag (3), server full (4), underaged (5), GM disconnect (15), and several account/PC/IP restrictions (100–110). This matches the client's three-byte packet framing and disconnect transition.

The client currently ignores the reason byte, so it drops server-provided diagnostic meaning. Whether the selected binary should display or log these codes, and whether its broader session/world cleanup is complete, remain open for review and replay. No discovery row is closed.
