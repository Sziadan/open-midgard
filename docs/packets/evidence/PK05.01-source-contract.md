# PK05.01 — source-backed receive-boundary specification

Date: 2026-11-04. Status: source review and contract complete; recovery policy intentionally open for PK05.02/03.

## Baseline and source observations

The current branch is `main`; preceding PK04.04 checkpoint is `fda57947` (`packet(PK04.04): verify raw account-id handshake`). The worktree was clean before this checkpoint. The selected client profile is 23; `GronPacket.cpp` also declares a profile-22 table. The authoritative rAthena source/configuration snapshot remains the hash-pinned, unversioned source recorded by PK01.02, with effective `PACKETVER` and `PACKETVER_SAK_NUM` 20080910; deployed-server binary provenance remains unknown.

`Connection.cpp::CRagConnection::RecvPacket` checks the first two queued bytes against the selected global size table. An unknown table result logs and deletes two bytes before looping. For a table-known variable packet it waits for four bytes, reads the two-byte little-endian length, accepts 4–32767, and on any other value deletes only the first two bytes before looping. Thus both errors rescan bytes from inside the unframed remainder. A payload or the invalid length word can accidentally be interpreted as an opcode; if those bytes match a known length entry, ordinary framing can return them to packet dispatch. This is destructive resynchronization, not safe recovery.

Known packets retain incomplete input and are emitted only when their selected fixed/table length is buffered. A valid length-delimited packet can be followed by a concatenated frame without ambiguity. The receive loop extracts already-buffered frames before socket pumping; EOF disconnects and clears queued data. PK03.02's production loopback captures exercise fragmentation, concatenation, truncation, EOF/reconnect, and explicitly classify unknown/invalid-length tests as baseline behavior to revisit, not desired semantics.

## Authority finding and bounded decision

The selected rAthena source/configuration supplies recognized layouts and emitters. It does not define a universal client recovery rule for unknown opcode bytes or a way to infer an unknown frame's end. TCP is a byte stream and contributes no application packet boundaries. The evidence therefore cannot justify payload scanning, guessed sizes, or silently ignoring an unknown packet. The contract preserves the existing state observations and leaves the recovery/failure policy open for PK05.02/03, where the connection transition and reporting can be specified together. This step makes no runtime change and closes no discovery row.
