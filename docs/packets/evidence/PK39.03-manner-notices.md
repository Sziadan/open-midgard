# PK39.03 manner and colored notices

The selected map server uses six-byte `014A` for a 32-bit result, and 27-byte `014B` for a one-byte type followed by the giver's 24-byte name. The selected client reference shows `014A` results 0, 3, and 4. Result 5 is quiet and the follow-up `014B` supplies the name. The reference displays type 0 and consumes type 1 quietly. The installed message table confirms entry 854 for result 0. The other displayed branches use English fallback wording. `014A` and `014B` affect presentation. Server status packets own the actual chat restriction.

`clif_changemanner` emits 12-byte `01AB` to nearby clients with the actor AID, parameter 4 (`SP_MANNER`), and signed value. The client applies the value at offset 8 to the matching player actor. The secondary reference confirms that `SetHonor` takes the value rather than the AID. Actor entry and movement snapshots carry signed 16-bit honor and now decode it with the same sign.

`02C1` carries packet length, speaker AID, a Windows COLORREF, and message bytes. The existing chat path already filters ignored actors, converts the color, displays a speech bubble, and logs chat when configured. The handler now checks the declared length before dispatch. Replay verifies result branches, a full-width giver name, signed actor honor, an unrelated parameter, and the ignored and visible colored-chat paths.

Live mute and unmute, localized wording, and rendered colored-notice verification remain open.
