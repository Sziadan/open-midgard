# PK46.02-PLAYER-EMOTION

Source chat aliases route through message 47 and then 33. The production client sends three bytes, opcode `00BF` and the emotion ID at offset 2. The selected map server registers `clif_parse_Emotion` for that frame. It applies its basic-skill, action block, forbidden mute emote, and integer-second flood checks. Successful handling emits `00C0` with the actor ID and emotion. The server can roll the dice again. Its emotion enum extends through 87, while this client supports 0–80. Player emotion and the separately owned `01A9` path have different senders.

The reference client sets the request flag before attempting transport and guards requests at exactly 2500 ms. The port retains that cooldown, records it after a successful send, and checks elapsed time with unsigned subtraction. A missing reply expires after five seconds when the player next requests an emotion. Selected rAthena's skill-failure notices can be suppressed by configuration. This timeout lets emotion input recover without automatically repeating any request.

The production chat replay exercises the aliases, exact frames, exact cooldown boundary, a failed local send, and missing-reply recovery. The production receive router clears pending state for a recognized local `00C0` or the selected basic-skill failure `0110`. Replay checks local actor message 21, an unrelated actor ID, and an unsupported emotion ID. Live sprite rendering and server-side skill, dice and rate-limit policies remain open.
