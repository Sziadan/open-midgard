# PK02.03 — Independent synthetic byte fixtures

Date: 2026-11-03
Status: completed for the initial seven applicability/boundary contracts; six have applicable fixed/raw wire fixtures, and cross-stage framing is explicitly a state-machine case with no fabricated packet bytes.

## Fixture derivation

`tools/build_packet_fixtures.py` constructs bytes from source facts in the hash-pinned server manifest and final active packet registration offsets. It does not import or call client serializers/structures. Values are synthetic. Fields are packed little-endian at server-derived offsets; padding is zero. The 20080910 pet fixture omits the later guarded job field. The raw character handshake is represented as four bytes without an opcode.

Six fixtures cover the raw handshake, map S2C 0x01F2 guild status, map S2C 0x01A2 pet status, and map C2S 0x0190, 0x007E, and 0x0437 requests. Each has a separate `.hex` file, SHA-256, explicit contract link, stage/direction/profile, field slices, decoded synthetic values, and source basis in `evidence/PK02.03-fixtures/PK02.03-fixtures.json`. The full output JSON references the PK02.02 manifest SHA-256 so a stale manifest invalidates the link.

Command: `python tools/build_packet_fixtures.py --self-test`. Result: six unique fixtures passed fresh-manifest link, stage/direction/profile, contract length, complete field schema/offsets, digest, bounds, overlap, byte slices, opcode bytes, source basis and synthetic-data validation. Seven negative mutations (stale manifest, metadata mismatch, missing field, wrong length, wrong opcode and missing/empty suite) were rejected.

## Interpretation and limits

These are independent byte expectations from server parser/packed-layout facts, not production-path tests or proofs of feature reachability. Request padding is zero-filled solely as synthetic fixture data; no claim is made that server semantics require a particular padding value. Account, character, target and status values are synthetic. The 0x007E text example is short NUL-padded ASCII, not a general encoding/truncation claim. No rejection/min-max cases are added where semantics are not yet approved. The independent strong reviewer approved this bounded infrastructure at PK02.04; that approval is not runtime or feature-semantic certification.
