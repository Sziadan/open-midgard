## Bounded leaves and transaction invariants

1. PK32.02: implement inbox refresh/list, pagination/new-mail notification, and read state. Reject malformed variable lists atomically; stale mail IDs must not open another record.
2. PK32.03: implement attachment/zeny/item claim requests and results. Make claims idempotent; handle denied, full inventory, partial grants, and duplicate result packets without duplicating items or currency.
3. PK32.04: implement delete/return and complete compose/send/result lifecycle. Prevent duplicate send, retain drafts on denial/cancel, enforce recipient/body limits from source, and preserve the 0248/0249/024A variant identity.
4. PK32.05: production replay for each request/result and denial/stale/duplicate/full-inventory/cancel path, plus inbox/composer lifecycle and reconnect cleanup. PK48 remains independent review.

## Current client gap

Targeted searches found no dedicated mail UI/session model and no production handlers/framing for the legacy family except a 0x0249 fixed-size ignore registration. Composer-only support does not establish inbox, claim, delete, or return parity. Do not accept claims locally without their server result. No discovery rows are closed by this scope checkpoint.
