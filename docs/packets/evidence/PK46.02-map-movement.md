# PK46.02 — map movement request wire trace

Date: 2026-11-04. Status: one source-backed request path traced; profile/deployed-runtime evidence and packet-specific replay remain open. No discovery row is closed.

## User action to sender

- `src/main/WinMain.cpp` forwards `GameMsg_LButtonDown` and `GameMsg_MouseMove` through the mode manager.
- `src/gamemode/GameMode.cpp::CGameMode::OnMessage` handles left-button down, sets the held-move target from the screen point, and immediately pumps a move request. Mouse movement updates the target while held; `CGameMode::OnUpdate` pumps held movement while the button remains down.
- The request path is `PumpHeldMoveRequest` → `TryRequestMoveToCell` → `SendMoveRequestPacket`. The serializer encodes coordinates only when each is in 0..1023; it packs 10-bit X/Y into three bytes.

## Client wire layout and profile gate

For `PacketVer22` and `PacketVer23`, the current client selects map opcode `0x00A7` and emits `PACKET_CZ_REQUEST_MOVE2`, 8 bytes total: opcode at 0, padding at 2..4, packed destination at 5..7. `FillPacketPadding` initializes all three padding bytes. The separately configurable `Legacy` profile emits opcode `0x0085` and a 5-byte `PACKET_CZ_REQUEST_MOVE_LEGACY` with destination at 2..4.

## Selected server contract

The pinned source/config snapshot in PK01.02 sets effective `PACKETVER=20080910`. In `src/map/clif_packetdb.hpp`, the applicable `PACKETVER >= 20070108` registration is `parseable_packet(0x00a7,8,clif_parse_WalkToXY,5)` (line 836); later selected 2008 non-renewal sections do not replace this opcode. `clif_parse_WalkToXY` reads packed X/Y through `packet_db[RFIFOW(fd,0)].pos[0]` and `RFIFOPOS`, so the registered position is byte 5. The three-byte coordinate encoding matches the current modern-profile serializer.
