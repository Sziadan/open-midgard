# PK43.01 selected buying store, search and party booking inventory

## Buying stores and store search

MAIN 20080910 has no registered buying-store request in the `0811`, `0815`, `0817`, or `0819` family. The open parser begins in the 20100303 block. The close, click, and trade parsers begin in the 20100420 block. The selected `battle.cpp` startup code disables buying stores below 20100427. `buyingstore.cpp` checks the resulting feature setting before preparation, creation, browsing and trade.

`0810`, `0812`, `0813`, `0814`, `0816`, `0818`, `081A`–`081C`, and `0824` are later S2C buying-store notifications. The existing client recognizes the lengths of the `0814` board and `0816` removal and drains them through explicit ignore registrations. Both are absent from the effective selected registry. Later emitter names and layouts alone do not establish that the configured server can create or send a board.

The `0835` search request needs MAIN 20100817, RE 20100706, or Zero. The pagination, close and click parser registrations begin in the 20100608 block. The selected startup code disables the feature below 20100803, and the search parsers and emitters check the feature setting. The historical `0836` list, `0837` failure, and `083A` open frames belong to this later family. Legacy vending remains a separate feature.

## Party booking

The block commented 2009-12-22 uses the literal guard `PACKETVER >= 2009122`. The literal evaluates true for the selected profile. Keep it distinct from the correctly dated 20091229 block.

- `0802` is a selected 18-byte C2S register request. The parser reads level and map as 16-bit values at 2 and 4, and reads the low byte of each of the six job words at 6, 8, 10, 12, 14 and 16. The server interprets job byte `FF` as -1. It keys ads by character ID.
- `0803` is the selected 4-byte register result, with a 16-bit result at offset 2. The current callers emit 0 for newly registered and 2 for already registered. The documented result 1 has no selected caller in the registration function.
- `0804`/8 and `0808`/4 are length-only entries. The 14-byte search and update parsers require 20091229. `0805` is a registered variable S2C search response whose sole caller is the inaccessible search path.
- `0806` is the selected 4-byte delete request. The parser ignores its payload. It removes the character's ad if present and then attempts to acknowledge with `0807`. The selected registry has no `0807` length. Insert and delete also call the `0809` and `080B` broadcast functions with zero selected packet lengths. `080A` is the later update broadcast. These source calls do not supply frames on the selected wire.

No booking window or command producer surfaced in the selected client source or original reference. PK43.03 should account for the reachable registration result and the delete request's lack of a selected acknowledgement. Establish a usable client entry point and how it communicates the server's limited booking behavior before exposing actions. Preserve the early registry widths and leave the inactive later search/update paths outside selected routing.
