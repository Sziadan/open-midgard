# PK47.04 — Legacy negotiation and later map notices

## PK47.04-LEGACY-ENCRYPTION

`Ref/dhxj/packet.h:3359,8365` identifies `01C6` as `CS_REQ_ENCRYPTION` with two count bytes after the opcode, and `01C7` as the two-byte `SC_ACK_ENCRYPTION`. The selected original recognizes the acknowledgement in the login and gameplay receive loops (`Ref/LoginMode.cpp:3041`, `Ref/GameModePacket.cpp:1787`). Both paths display the unsupported-encryption error. This establishes the two client receive contexts. An acknowledgement branch alone does not establish that either context initiates negotiation.

The selected map registry retains the four-byte request and two-byte acknowledgement with null parser pointers (`src/map/clif_packetdb.hpp:218–219`). The selected login, character and map sources have no parser or sender for these opcodes. The coverage dispositions apply to the selected configuration. Historical request stage and other profile applicability remain open.

## PK47.04-LATER-MAP-NOTICES

The following checks use the selected main 20080910 configuration and the actual call sites in rAthena. A sender without an explicit packet date guard can still be unreachable in the selected profile.

- `0440` is Millennium Shield with AID, shield count and state. Both the area sender and the single-observer snapshot are gated at 20081126 (`clif.cpp:1525,19712`).
- `08FF` is an EFST entry snapshot with target ID, status index, duration and three values. Its sender starts at 20111108, and the header changes to `0984` at 20120618 (`clif.cpp:6564`).
- `0908` carries inventory index and favorite flag. `clif_favorite_item` requires 20111122 (`clif.cpp:19926`).
- `0979` carries 24-byte world and character names. Its only caller handles `0978`, which has no entry in the selected final parser table (`clif_packetdb.hpp:1644`, `clif.cpp:19980–20000`).
- `09B2` starts a bargain sale with item ID and seconds remaining. `09B3` ends it with an item ID. Both require `PACKETVER_SUPPORTS_SALES`, defined from 20131223 (`clif.cpp:21560,21574`, `src/config/packets.hpp:89`).
- `09CD` sends a localized message ID and color from 20130807 (`clif.cpp:10424`). The selected server's active numeric-value message uses `07E2`.
- `0A28` replies to opening a vending shop from 20141022 (`clif.cpp:7714`). `0A47` reports a stylist result from 20151104 (`clif.cpp:22849`).
- `0AB2` sends an AID and life-state flag from main 20170524, renewal 20170502, or Zero (`clif.cpp:8116`).
- `0B9A` is emitted by the enchant window path from main 20220330 or renewal 20211103 (`clif.cpp:24490`). Both `ZC_UI_OPEN_V3` and `ZC_UI_OPEN2` definitions retain that numeric header. The classification covers the selected emitter; historical layout variants remain open.
- `0C0C` sends a GM checker result from main 20240502 (`clif.cpp:25600`).

## PK47.04-FASTMOVE

`08D2` is a ten-byte `ZC_FASTMOVE` containing actor ID and two coordinates (`clif.cpp:19942`). The table first registers its length under 20111005. Monk Snap uses `0117` before that date (`skills/acolyte/snap.cpp:16`). Fallen Angel and All in the Sky can call `clif_snap` without that guard, so the Snap guard alone does not determine whether the packet reaches the client. `packet_db` starts zeroed (`clif.cpp:25830`) and the selected final registry has no `08D2` length. Every `clif_snap` output branch passes that length to `clif_send`. The area and self paths enqueue no bytes for length zero, and `WFIFOSET` explicitly returns without advancing the FIFO (`src/common/socket.cpp:846`). This establishes selected wire inactivity even for an unguarded caller.

## PK47.04-LEGACY-EFFECTS-AND-PK

The selected registry retains `021E` (6), `021F` (66) and `0220` (10) at `clif_packetdb.hpp:480–482`. The original headers at `Ref/dhxj/packet.h:3471` identify the map S2C reduced-effects flag, PK information and killer flag. The corresponding structures at line 8788 give a 32-bit Boolean, a PK record with two point counts, two names and a FILETIME, and an AID plus 32-bit Boolean, respectively. The original dispatches `021F` and `0220` to the PK UI handlers (`Ref/GameModePacket.cpp:2087`).

The selected source has no sender for any of these three. The active `021D` request stores the reduced-effects preference server-side without acknowledging it (`clif.cpp:19030`). Preserve that request and the separate client minimum-effects preference.
