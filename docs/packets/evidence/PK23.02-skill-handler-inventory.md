## Damage and result routing

- `HandleSkillDamageNotify` selects the extended or short layout from the active receive profile, with different damage width and level/count/action offsets. `DeliverSkillUse` sends message 37 to the source actor or source skill unit. It selects monster action data or sends the mode announcement. Extended-only extras require both actors and cover skill 141 with level `-1` and skill 662 with a distinct target. `ReplaySkillDamageExtendedExtra` covers those extras. The Bash, Double Strafe, and Fire Bolt fixtures include the short layout. Confirm the selected `01DE` path with ordinary, missing, and unit sources, target resolution and signed damage/count/level fields.
- `HandleSkillDamagePositionNotify` validates the compatibility opcode and uses signed cells, signed short damage and the common message-37 path without the extended extras. `ReplaySkillDamagePosition` creates a source unit and checks the resulting queued hit. Keep that fixture as historical receive coverage.
- `HandleGroundSkillNotify` requires a world and an active-profile frame. A resolved source gets message 38. The monster branch uses monster action data. The nonmonster branch reaches the existing announcement route, with Arrow Shower skill 47 and wave behavior for skills 362/369. `ReplayGroundSkillWave`, `ReplayGroundArrowShower`, `ReplayMissingActorGroundSkill`, `ReplayMonsterGroundSkill`, and `ReplayLordOfVermilion` split those branches. Verify signed level sentinels and cell positions through the downstream action and wave owners.
- `HandleSkillNoDamageNotify` parses signed level/heal and the result flag. Skill 244 from the local source has a homunculus closure branch. `DeliverUseSkill` handles zero or unresolved source, explicit action for 249/8220, monster motion or mode message 99, the wedding target argument, and the no-cast-motion exceptions. Destination selection uses packed cells for the `UseSkillFacesCell` list, a skill unit for 124/131, and actor lookup otherwise. Success gates `ApplyUseSkillEffects`. Replay existing Heal and no-damage fixtures and verify failure preserves that gate while ordinary, missing, self, ground and unit targets keep their own dispatch rules.

## Cast and rejection

- `HandleSkillCastAck` resolves the source before applying any state. A zero-time local announcement waits for the result. Skills 57 and 62 set the specific motion, freeze and end tick. Other skills start effect and cast-bar messages 85 and 82. Monster jobs consult monster skill action data and may scale skill 193 motion speed. Other jobs send mode message 99, with a destination argument only for 334/335, through the existing head-bubble path. Verify the announcement and motion branches with `ReplayCastAnnouncements` and `ReplaySkillCastAck`. [Announcement checkpoint](PK23.05-cast-announcement-repair.md)
- The same ACK handler handles a resolved actor target distinct from the source. It gates the target marker by object type, companion job, beneficial skill and PK/siege mode, faces the target, and sends the target effect message. Skill 490 also positions effect 539. Destination zero faces the requested cell and creates `CGroundScope`, whose lifetime is managed by its world-object owner in `src/world/GroundScope.cpp`. A missing or self actor target bypasses this target presentation. Skill 401 has a forced action and effect 402, skill 268 has a timed forced action, and skills 261 and 1015 have a fixed forced action. Replay the target gates, unresolved and self IDs, ground scope cleanup, and forced-action branches individually.
- `HandleSkillCastCancel` gates on a live world and a resolved actor, then sends messages 84, 87 and 83 to end the begin effect, target effect and cast bar. It clears the raw motion freeze and returns to idle only from casting or cast-loop state. `ReplaySkillCastCancel` is the entry point. Verify local, remote and unresolved IDs, noncasting state, and cancellation of ground scope through its owning lifecycle.
- `HandleSkillFailAck` first routes to the existing commerce receiver. The local raw motion freeze releases for any result. Result zero can stop the listed local attack/cast states, clear a pending emotion for basic-skill reason 1, and emit notices through `ResolveSkillFailNotices`. Cause zero has basic-skill reasons 0–8, skill-specific cases 27/50/52, and a settings-gated generic failure. Causes 1–10 have fixed messages and settings gates for 4 and 10. Unmapped causes currently produce no notice. `ReplaySkillFailAck` covers the legacy result/cause paths. Selected cause 71 passes quantity and item ID, exposing the current combined u32 read and the missing notice branch. Compare the selected result semantics and test that rejection leaves the blade-stop claim intact when releasing the raw motion freeze.

## Skill units, text and duration

- `HandleSkillUnitSet` accepts the fixed basic frame and initializes visible to 1 as in Ref. `RememberVisibleTrap` tracks the creator and duplicate unit ID. `PlaceSkillUnit` reuses the existing unit or creates a job at least `0x2D`, registers new instances in both world lists, and forwards unit identity, cell, job and visibility through message 45. `CSkill` owns per-job effects and models under WP4/WP5. Verify selected dummy-job and reveal behavior, duplicate delivery and creator-specific state. `ReplaySkillUnitLifecycle` and `ReplayTrapRevealLifecycle` cover synthetic lifecycle cases, with separate model-backed fixtures.
- `HandleSkillUnitSet2` branches on the message-present byte. The message path copies 79 text bytes and appends NUL, creates and registers `CGraffiSkill`, then dispatches identity and text/position. The no-message compatibility path uses basic placement. Verify selected Graffiti text and repeat or replacement of the same unit ID with `ReplayGraffitiLifecycle`. Asset-backed glyph drawing belongs to the ground-unit owner.
- `HandleSkillUpdate` resolves only a skill unit and sends message 119 for jobs 139–153. `ReplayAnkleSnareTriggerLifecycle` covers the trigger, and `ReplayTrapRevealLifecycle` covers synthetic hide/reveal. `HandleSkillDisappear` passes the unit ID to `CWorld::RemoveSkill`. Verify job-range boundaries, unknown and repeat deletion, both world lists, and attached effects. Duration comes from per-job `CSkill` and effect lifetime or the server's deletion event. The six-byte update carries the unit ID.
- `HandleTalkboxChatContents` resolves the unit and passes the fixed text field to message 7. `ReplayTalkieBoxTriggerLifecycle` covers text, presentation lifetime, and follow-up look change. Check bounded copying and the actual chat presentation. The `01D7` look-change handler has a unit-only `LOOK_BASE` branch that sends message 47. Its actor and wire contract belongs to [PK24](PK24.01-resource-state-scope.md).
