# PK44.04 — Exercise character-select widget actions headlessly

Date: 2026-11-04. Status: production mouse-handler and widget-message mapping verified in a headless harness.

## Replay

`tools/tests/check_select_char_actions.py` extracts the current production bodies for `UISelectCharWnd::HandleQtMouseDown`, `HandleQtMouseUp`, `SendMsg`, and the selected-slot/create/delete action methods, compiles them with a minimal window/rendering stub, then exercises the input handlers. Cases verify:

- primary action on an occupied slot emits `LoginMsg_SelectCharacter` with the character index;
- primary action on an empty slot emits `LoginMsg_RequestMakeCharacter` with the selected slot;
- delete on an occupied slot emits `LoginMsg_RequestDeleteCharacter`, while delete on an empty slot does nothing;
- cancel emits `LoginMsg_ReturnToLogin`;
- hidden-window and outside-panel clicks do not send a mode message.

This verifies widget-handler geometry/action routing and message identities. It does not create a `QGuiApplication`, synthesize native Qt events, exercise the live `CModeMgr` connection, or validate visible rendering. Those broader lifecycle claims remain open; the headless boundary does not block independent packet work.
