# PK45.03 — item identification acknowledgment

Date: 2026-11-04. Status: fixed framing and inventory/UI result effects traced; selected-profile ownership and replay remain open. No rows closed.

Opcode 0x0179 has a fixed five-byte registry size and routes to `HandleItemIdentifyAck`. The handler requires packet data and at least five bytes, reads an item index u16@2 and a result byte@4, and treats exactly zero as success.

On success, if an inventory item with that index exists, the handler copies it, sets `m_isIdentified` to 1 and writes the updated item back. Whether or not the index resolves, it refreshes inventory-dependent windows and emits a green system notice. A nonzero result leaves inventory untouched and emits a red failure notice. The handler sends no reply and does not verify the opcode locally; routing supplies the packet context.

Open work: confirm result polarity, item-index identity and packet direction/profile against the selected server; determine the intended notice/refresh behavior for unknown item indices; replay success/failure with present and absent inventory entries. The coverage ledger marks source-family routing provisional and server/profile reachability unresolved. No independent fixture or production replay was performed for this leaf.
