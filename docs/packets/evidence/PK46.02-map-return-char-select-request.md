# PK46.02 — return-to-character-select request

Date: 2026-11-05. Status: menu action, pending-send behavior, selected server branch, client acknowledgements and timeout fallback are source-traced. Live map-to-character-server transition and UI lifecycle replay remain open. No discovery row is closed.

`UIChooseWnd` sends `GameMsg_RequestReturnToCharSelect` from its return-to-character-select menu entry. The client builds the same three-byte `0x00B2` restart packet as the save-point path, but sets type byte 2 to one. Before sending it begins a pending-disconnect action; duplicate requests are rejected with a chat notice. A failed send clears the pending action and posts an error; a successful send records the send tick. The menu closes only when the message handler reports success.

The selected 20080910 server registers `0x00B2` as three-byte `clif_parse_Restart`, reading type at byte 2. Type one requests character selection only when the server's invisibility-status checks and `prevent_logout` timing permit it; the allowed branch calls `chrif_charselectreq`, while the denied branch sends a disconnect acknowledgement. Thus a successful client socket send is not evidence that the character-select transition succeeded. The pending state/ack timeout and full map-to-character-server lifecycle were not replayed; no independent byte fixture or UI lifecycle acceptance was performed. No discovery row is closed.

## Client disconnect-ack and timeout follow-up

The client frames `0x00B3` as three bytes and `0x018B` as four (`src/network/GronPacket.cpp:97,203`); handlers are registered at `GameModePacket.cpp:8958-8959`. A `0x00B3` result byte of 1 is accepted only for a pending ReturnToCharSelect action; the handler clears pending state, sets `g_session.m_pendingReturnToCharSelect=1`, disconnects and switches to LoginMode (`GameModePacket.cpp:8020-8023,8036-8054,7911-7918`). A four-byte `0x018B` result of 1 clears a pending action and reports refusal; result 0 is treated as success only for ExitToWindows and is ignored for ReturnToCharSelect (`GameModePacket.cpp:8009-8018,8056-8085`). The pending action also has a 15-second timeout; after the receive queue is drained, timeout fallback clears it, preserves the return-to-character-select flag and switches to LoginMode with a timeout status (`GameModePacket.cpp:84,7930-7939,7984-8001`; call from `GameMode.cpp:10347`). This is source state flow, not verification that the selected server emits the expected response on each branch or that the character server restores the intended list. Keep transition, timeout and refusal replay open.
