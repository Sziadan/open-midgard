# Selected relationship packets

The selected rAthena checkout uses PACKETVER 20080910. `clif_divorced` sends 26-byte `0205` to each online former partner from `pc_divorce`. Offset 2 holds a 24-byte former partner name. `Ref/GameModePacket.cpp::Zc_Divorce` formats message 836 with the local and former partner names. The rebuilt receiver substitutes both names as literal text.

`pc_try_adopt` calls `clif_Adopt_reply` for three failures. Its six-byte `0216` writes a 32-bit result at offset 2. Result 0 means a parent already has a child, 1 means a parent is below level 70, and 2 means the candidate is married. The reference uses message IDs 899, 900, and 916 and COLORREF 10198015. Other eligibility failures can return silently. Production replay covers all three notices, an unknown result, and a split divorce frame followed by coalesced replies.

`01E6` is a 26-byte area notification from `clif_callpartner`, reached by `WE_CALLPARTNER`. Its fixed name can be empty. Reference code stages the name for the associated skill text. `01EA` is a six-byte area notification from `clif_wedding_effect` with actor GID at offset 2. The marriage command and registered script builtin can emit it. The reference plays effect 347 when effects are enabled and the actor is present. `01F8` has an inbound size-table entry without a selected-server outbound emitter.

`01F9` sends a six-byte adoption request with candidate account ID. On eligibility success, the server stores the inviting parent's account ID on the candidate and sends a 34-byte `01F6` with the initiating parent's account ID at offset 2, the other parent's account ID at offset 6, and the initiating parent's fixed name at offset 10. `01F7` replies with the same account IDs and a 32-bit answer at offset 10. Zero clears the pending invite. Acceptance requires both parents online, the initiating account matching the stored invite, and the server's eligibility checks. The reference prompts the candidate before sending.

PK30.02 feeds the bounded recall name into the existing skill 336 overhead text and clears it on an empty update or map reset. The name is transient because the area packet does not identify the caster. Wedding notifications launch effect 347 on the addressed local or remote actor and honor the effects setting. Replay covers a full-width literal recall name, empty update, disabled effects, and missing wedding actor.

PK30.03 implements the reference two-stage consent. The first prompt names the parent. Accepting it opens the consequences message, and the final answer sends both parent account IDs. Declining either prompt sends zero. Replacement restarts consent, map reuse and exit clear it, and a failed send leaves it available for retry. The shared dialog expands for the longer warning in both renderers.

Reference player menu action 36 offers adoption to a visible eligible party member when the local character is at least level 70 and the skill list establishes parent eligibility (skill 336 present and 409/410 absent). The rebuilt native and Qt menus use the same candidate check and send `01F9` with the candidate account ID. Server-side relationship, rings, level, and candidate eligibility checks remain authoritative. The selected server does not emit the historical `01F8` skill-arm packet.

Production replay checks the eligible and ineligible request paths, both consent answers, replacement, and map teardown. Independent and live verification remain open.

For successful adoption, `pc_adoption` calls `pc_jobchange` with the baby job, then restores job level and experience. The selected `sendLookType` in `packets_struct.hpp` is `01D7`, with two 16-bit values. The client applies LOOK_BASE to the actor and local character snapshot using the first value and preserves both values for equipment. `00B0` restores the job level and `00B1` restores job experience. The separate party job update is gated to later versions.

The selected server grants the child skills 408, 409 and 5065, and grants each parent skill 410. The existing `0111` receiver accepts these grants. The `010F` receiver now retains 5065 on a full skill refresh after re-entry. Replay checks the baby job on local and remote actors, restored progress, and retention of all three child skills. Live adoption and rendered UI checks remain open.
