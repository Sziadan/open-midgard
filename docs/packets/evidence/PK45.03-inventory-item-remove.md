# PK45.03 — inventory item removal acknowledgment

Date: 2026-11-04. Status: client layouts and session update traced; selected 20080910 server variant and zero-count drop failure now source-traced. Extended variant semantics and replay remain open. No rows closed.

## Client packet handling

The current receive profile maps basic 0x00AF and extended 0x07FA to `HandleItemRemove`; the packet-size table assigns fixed sizes 6 and 8 bytes. The basic form reads item index u16@2 and amount u16@4. The extended form reads item index u16@4 and amount u16@6, leaving the two bytes at offset 2 uninterpreted. If the removed index matches `m_waitingItemThrowAck`, the handler clears that pending throw index, then calls `CSession::RemoveInventoryItem`.

The session method finds the first inventory item with that index. If amount is nonpositive or at least the stored stack count, it erases the row; otherwise it subtracts the amount. A missing index is a no-op. No UI-specific message is sent; inventory consumers read the session list.

## Open behavior

The selected PK01.02 source/config uses PACKETVER=20080910. At this version `clif_delitem` selects its pre-20091117 branch and calls `clif_dropitem`; that emits the 6-byte 0x00AF packet with client index at 2 and count at 4. The selected `clif_parse_DropItem` failure branch also emits 0x00AF with count zero (`src/map/clif.cpp:12040-12071,2893-2927,2915-2928`; PACKET_ZC_ITEM_THROW_ACK at `src/map/packets.hpp:810-815`). Therefore zero count on the basic 0x00AF path means rejected drop, not removal. The client now clears a matching pending throw but does not mutate inventory for this response. The 8-byte 0x07FA form is selected only by the later clif_delitem branch (`PACKETVER >= 20091117`); its extended field semantics and unrelated correction cases still need review.
