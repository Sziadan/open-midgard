# PK45.03 — spirit effect packet 0x01D0

Date: 2026-11-04. Status: fixed framing and literal actor/effect operations traced; job mapping, effect-state meanings and packet semantics need stronger review. No rows closed.

Opcode 0x01D0 is registered at fixed size 8 and routed to `HandleSpirits`. The handler returns unless data exists, length is at least 8, packet ID matches, and `g_session.m_isEffectOn` is enabled. It reads actor AID u32@2 and resolves it with `ResolveSkillPacketActor`; an unresolved actor returns.

For a resolved actor, it selects effect ID 504 for job 4038, 629 for job 24, otherwise 228, then sends actor message 109 with that effect ID. A zero AID returns after that message. Otherwise it checks the actor effect state for the burrow or hiding masks. If either is present, it sends message 109 with the same effect ID again and returns. For a non-hidden actor, it launches the selected effect at zero offset; if launch succeeds, it sends effect message 14 with `vector3d{float(s16(packet+6)), 0, 0}`. No reply or logical spirit counter update occurs here.

Defer the meaning of job-to-effect mapping, repeated message-109 calls, hidden-state masks and effect message 14's signed-X payload to stronger review. Confirm the eight-byte server layout and whether trailing/unknown conditions are valid; replay hidden and visible actors across supported jobs and effect-on/off states. No independent fixture or production replay was performed.

## Selected server 0x01D0 spirit-count packet (2026-11-04)

The selected server defines `0x01D0` as an eight-byte packed `ZC_SPIRITS` record: actor ID u32 and count u16 after the opcode. The emitters `clif_servantball` and `clif_abyssball` populate the actor ID from the character and the count from the corresponding servant/abyss-ball field; when no target is supplied, they default to the character, and otherwise use the caller's target/scope.

This confirms framing and field widths, but the client treats this packet as an effect trigger with job-based effect IDs rather than an obvious count update. The client/server semantic pairing, callsite recipient modes, and effect/message lifecycle require stronger profile review and replay before asserting equivalence. No discovery row is closed.
