# PK27.03 capture result ownership

Selected rAthena `clif_parse_CatchPet` reads the target DWORD from `019F`. Every outcome in `pet_catch_process_end` sends one `01A0` result. That response has one outcome byte and carries no target or request ID.

The client allows one outstanding capture request per map connection. The connection tracks the reply even if the first prompt closes or the game mode changes on the same socket. A newer prompt stays available and can send after the older reply arrives. The handler applies an outcome only to the prompt that submitted the outstanding request. An orphan reply drains the outstanding request without updating a newer prompt. Transport close clears the pending reply.

The Ref binary routes any result to the currently open prompt. The client now filters unassociated results to prevent a late reply from changing a different prompt. It preserves the Ref first-click latch and animation when a send fails, and records an outstanding reply only after a successful send.

The production replays exercise exact request bytes, failed send, malformed results, delayed reply after prompt deletion, duplicate results with no outstanding request, a fresh capture after the earlier reply drains, and connection reset while awaiting a result.
