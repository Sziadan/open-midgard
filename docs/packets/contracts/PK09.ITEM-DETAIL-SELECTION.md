# PK09.ITEM-DETAIL-SELECTION — select, toggle and forced update

Owner PK09.11. Primary item-detail message24 behavior; full PK09.04 and independent PK48 remain open.

## Source decision

Primary `Ref/UIFrameWnd2.cpp:9335–9349` closes/deletes the singleton detail window when the incoming complete raw `m_itemName` string, refinement and all four card words match, unless val2 is nonzero. Any nonzero val2 continues into assignment/update. Index, owner, type, identification, damage, quantity, price, wear/location, bind word and expiry are not part of that predicate. The raw name is the stored item-identity string, not its parsed numeric ID, localized display name or resolved producer label. Comparing only the declared socket count is incorrect; all four words participate even for unidentified items.

Current native inventory, storage, equipment, shortcut and card-slot callers, plus Qt inventory/cart/merchant/trade/equipment description actions, are right-click selections. They retain the default `ItemInfoAction::Select`. `ItemInfoAction::ForceUpdate` expresses source val2!=0 for callers that update instead of selecting. `UIItemInfoWnd::SetItemInfo` remains the assignment operation; maintenance refreshes do not become selections.

Primary right-clicks pass an ITEM_INFO snapshot, without cursor coordinates. MakeWindow shows the window before message24; item changes retain default or stored placement. Primary close button135 deletes window12 (`Ref/UIFrameWnd2.cpp:9316–9322`); the manager clears the singleton and queues the old object (`Ref/UIWindowMgr.cpp:1232–1251`). The rewrite uses its established immediate owned-window deletion mechanism and stores current logical placement before deletion. Legacy fixed-size rectangle validation and default screen geometry are separate from this modern window's style/placement acceptance.

## Implementation and lifetime

The manager checks selection equality and **pre-open visibility** before MakeWindow can show a retained hidden instance. A matching visible selection stores placement, deletes the owned detail and returns. A hidden retained view reopens instead of toggling; it represents a fresh source window in this framework. Forced updates bypass the close predicate, assign current data and preserve the requested source namespace. User close also stores placement and deletes the owned window. The next selection can construct a new detail with saved logical position.

Keep inventory/cart/storage live binding and offer/remote/card snapshot isolation from PK33.05 and PK37.06. A forced update can explicitly change the owner binding. Source equality is independent of that owner: selecting an equal raw key in another container still toggles the currently visible detail closed. Callers must reacquire the global window pointer after selection/close; no pointer to a deleted detail may be dereferenced.

## Remaining caller work

The force path is tested at the production C++ API boundary. Current NPC shop/catalog/buy/sell windows have no detail entry points matching their primary right-clicks or selected-item fallbacks, so this leaf does not claim those gestures are implemented. Their source val2=1 fallback is coupled to legacy row/list actions, not a new arbitrary refresh gesture. Current UIItemShopWnd uses source/catalog rows; UIItemPurchaseWnd and UIItemSellWnd use selected/deal rows. Trace the right record and post-hit current selection before connecting those actions. Do not expose an unreviewed Qt force command or reuse a same-index inventory/cart row.

No packet format, discovery classification, full NPC transaction state machine, legacy geometry/asset/locale, historical profile or deployed acceptance is closed by this detail-selection checkpoint.
