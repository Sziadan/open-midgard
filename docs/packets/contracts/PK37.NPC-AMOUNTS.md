# PK37.NPC-AMOUNTS — exact NPC prices, quantities and display

Owner PK37.08; selected 20080910 C6/C7 records and the current NPC row UI. Broad PK37 requests, transaction results and independent PK48 remain open.

Both price words in C6 and C7 are unsigned 32-bit fields. Preserve base and secondary values without narrowing through signed int. C6 discountPrice and C7 overcharge are the actual quoted unit price, including zero. Do not treat zero as a missing value or fall back to base price. The server always populates both words; rental sale quotes can be zero.

Store quoted unit prices as u32. Multiply after widening and accumulate exact 64-bit totals; neither signed row multiplication nor INT_MAX aggregate saturation describes the quote. With a 16-bit list length, C6 has at most5957 rows and C7 at most6553. Even6553 * UINT32_MAX *30000 is below INT64_MAX. This bound covers packet-derived rows and production quantity adjustments, not arbitrary injected vectors.

Retain the source MAX_AMOUNT=30000 stack limit. Sell availability is the copied inventory count, clamped to the stack limit; zero/negative availability cannot create a deal. Buy lists have no stock field and use the existing30000 local ceiling. Require Buy/Sell mode and widen old quantity plus signed delta before clamping. Positive changes at the ceiling are no-ops; negative changes through zero remove the row. Keep deal quantity and copied ITEM_INFO.m_num synchronized. Nonstackable eligibility, per-type UI prompt limits and stale inventory revalidation remain separate transaction work.

Native labels format widened unsigned values. Qt source prices, row amounts and totals are decimal strings, including the QString total properties. A numeric JavaScript projection cannot preserve every integer above2^53. Keep these strings through QML Text; do not parse them back to Number. Amount columns must fit the full15-digit per-row bound; item names may elide. Footer totals have room for packet-bounded aggregate values.

No money or inventory mutation is inferred from a displayed quote. This leaf changes no C8/C9 sender, CA/CB result handling, retry/send failure, server funds/weight/capacity eligibility or transaction rollback. Primary Win32 arithmetic is not evidence that signed overflow or truncation is an accepted result. Extreme wire values and generated many-row totals exercise representation boundaries, not valid shop prices, item legality, locale/assets or deployed-server acceptance.
