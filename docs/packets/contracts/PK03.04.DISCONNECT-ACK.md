## Exact wire contract

1. `0x018B` acknowledgement header: opcode `uint16` at byte 0, little-endian; fixed total size 4.
2. Result: `uint16` at byte 2, little-endian. rAthena's `clif_disconnect_ack` writes the opcode to `WFIFOW(fd,0)` and result to `WFIFOW(fd,2)`.
3. Result `0`: accepted quit/disconnect for request `0x018A`; the server flushes the reply and may close the socket.
4. Result `1`: disconnect refused. The server emits this for a restricted `0x018A` request and for a restricted `0x00B2` type-1 return-to-character request.
5. rAthena does not emit result `0` from the successful `0x00B2` type-1 path: that branch calls `chrif_charselectreq`; refusal calls `clif_disconnect_ack(sd,1)`. Therefore response meaning must be combined with the pending client action.

Server sources:

- `src/map/clif.cpp:11427-11462`: `clif_disconnect_ack` and `clif_parse_QuitGame`; server result meanings and allow/deny branches.
- `src/map/clif.cpp:11837-11854`: `clif_parse_Restart`; type 1 is return-to-character, and only its restricted branch emits result 1.
- `src/map/chrif.cpp:775-791`: `chrif_charselectreq` sends the character-select request to the character server on the successful return path.

Independent source-derived acknowledgement bytes:

- result 0: `8b 01 00 00`
- result 1: `8b 01 01 00`

The client requests already built by `GameMode.cpp` are `0x00B2` type 1 (`b2 00 01`) and `0x018A` type 0 (`8a 01 00 00`). These expected bytes are literal fixtures derived from packet IDs, field offsets, values, and fixed lengths above, not from client packet structs.

## Behavioral contract proposed for review

Pending actions are `None`, `ReturnToCharSelect`, and `ExitToWindows`.

- A return-to-character action sets `ReturnToCharSelect` before sending `0x00B2` type 1; failed send clears it and does not change mode. A result-1 `0x018B` clears the pending action, keeps the map session active, and displays the server-refusal message.
- An exit-to-Windows action sets `ExitToWindows` before sending `0x018A` type 0. It must not disconnect or quit before the acknowledgement. Failed send clears the pending action and does not quit.
- Result 0 with `ExitToWindows` disconnects and quits, matching Ref. Result 1 with either pending action clears it, leaves the client in the map session, and displays the refusal message.
- An acknowledgement with no pending action, result 0 paired with `ReturnToCharSelect`, or an unknown result is unexpected: log it, clear stale pending state, and do not disconnect, quit, or switch modes.
- A second local exit/return request while any disconnect action is pending is rejected without sending another packet. The selection menu closes only if the request was sent.
- Clear pending action on send failure and game-mode teardown. A socket loss before acknowledgement must not cause a quit-to-Windows transition; whether a broader reconnect/session transition is required is outside this packet contract and remains a separate open lifecycle question.
- Preserve the existing `0x00B3` route unchanged in this leaf. The current rAthena source does not establish it as the `0x018B` acknowledgement; any correction to its separate semantics requires its own source contract.

Ref evidence:

- `Ref/dhxj/GameModePacket_2.cpp:912-914` routes `HEADER_ZC_ACK_REQ_DISCONNECT`.
- `Ref/dhxj/GameModePacket.cpp:5746-5761` handles result 0 by disconnecting/quitting and result 1 by showing the cannot-exit message.
