## Call path and selected-profile result

In `src/map/clan.cpp`, `clan_member_joined` calls basic-info and online-count senders (lines 113-136); successful join is gated by clan lookup, matching account/character IDs, no current clan and the configured instance restriction (`clan_member_join`, lines 158-177). `clan_member_left` updates membership/count and sends online-count; successful leave validates IDs/current membership and instance restriction, clears the session clan fields, then calls leave acknowledgement (`clan_member_leave`, lines 140-202). `clan_recv_message` resolves the clan then calls the message emitter; `clan_send_message` requires clan membership, forwards to inter-server/local recipients and logs (lines 205-222). These call paths demonstrate later-feature semantics, not active emission under the selected date. `clif_packetdb.hpp:1677-1686` places the `0x098D` registration in the 20131223 block.

For `PACKETVER=20080910`, the 20120716 header-enum guard is false for `0x0988/0x0989/0x098E`; the 20130626 main guard is false for `0x098A`; and each clan chat/count/leave emitter body is compiled out by its 20131223 guard. The `0x098D` parser registration and parser body are also compiled out. Thus the pinned source configuration has no clan wire emission or clan-chat parser for this family. This proves only source-config inactivity, not that a deployed binary was built from this snapshot.
