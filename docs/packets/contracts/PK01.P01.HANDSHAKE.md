# Contract PK01.P01.HANDSHAKE — character account-ID prefix

Status: **APPROVED_FOR_APPLICABILITY_ONLY**. Owner: PK04. Review dependencies: PK44 for character-stage transitions; PK47 for historical/discovery reconciliation. Strong reviewer: `/root/pk01_p0_review`; approval checkpoint subject: `packet(PK01.03): approve P0 applicability identities`.

## Identity and applicability

- Stage: character-server connection.
- Direction: S2C.
- Profile: raw handshake before ordinary character-server framing; server source snapshot uses PACKETVER/PACKETVER_SAK_NUM 20080910, while client send profile 23 remains a separate setting.
- Wire identity: four raw little-endian account-ID bytes; **no packet opcode**.
- Discovery parents: AUDIT-0x8482 and AUDIT-0x8483 are client fake-opcode rows and both map to this one handshake child; their map-stage hint is wrong.

## Source-backed scope

Server `char_clif.cpp::chclif_parse_reqtoconnect` reads the account ID from the 17-byte 0x0065 request at offset 2, consumes the request, then sends four bytes containing that ID at lines 850–853 before running-state/authentication rejection. The server does not restrict the echoed numeric value at this point. Client anchors are `LoginMode.cpp:1676–1696,1902,1935–1936` and `GronPacket.cpp:323–324`.

## Open feature contract and verification

Implementation must explicitly expect four raw bytes on a fresh character connection, accumulate arbitrary fragmentation, compare the full value against the account ID sent, transition exactly once to framed traffic, and reset on reconnect/return-to-character. Fixtures must include mismatch, EOF, coalesced prefix plus refusal/list, repeat request, and IDs whose low word resembles fixed or variable packet headers. These transition details and independent byte fixtures remain implementation gates; this applicability approval is not permission to omit them.
