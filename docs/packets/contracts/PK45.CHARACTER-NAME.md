## State and ownership

`CGameMode::ResolveCharacterName` reads a dedicated CID-to-name cache. A miss uses the active request builder. A successful send starts the CID's retry timer; failed sends retain no pending timer. Calls within 2500ms of a successful send emit nothing; unsigned subtraction supports tick wrap. Expiry permits retry without inventing a display name. The 2500ms cadence follows the primary Ref character-name timer helper; the decompiled Ref function labelled GetActorNameByGID has a timer body, so it does not prove a complete original sender implementation. The selected server defines the wire identity.

A valid nonempty 0194 reply populates only the character cache and removes only that CID's pending timer. Unsolicited valid replies are allowed: selected `clif_updatestatus` also sends the local character identity through `clif_solved_charname`. Zero-ID/empty names are ignored. They do not erase a good name or reset a pending timer. Distinct out-of-order CIDs remain independently keyed. Map initialization, mode exit and loaded same-map reuse clear character names and pending lookups alongside the existing lifetime boundaries. The normal reconnect/map handoff reaches those boundaries; a full transport-generation redesign is outside this leaf.

The selected PacketVer23 gameplay profile owns this exact C2S layout. Other gameplay profiles keep zero/disabled character-lookup layout fields until separately audited; do not infer their whole protocol from shared receive IDs.
