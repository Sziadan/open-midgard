## Server transaction and checks

The handler validates source slot `< MAX_CHARS`, feature enabled, remaining moves unless unlimited, source contains a character, destination `< MAX_CHARS` and `< sd.char_slots`. An occupied destination is rejected unless `char_movetoused` is enabled, in which case the server swaps the two character slot numbers in an SQL transaction; an empty destination updates the source character's slot. Finite move counts decrement and are persisted. Success sends reason 0 and then resends the character list. Failure sends reason 1 and current moves. Several response branches can be configuration/database dependent; a SQL update failure rolls back and replies failure.

## Security finding requiring PK48

`chclif_parse_moveCharSlot` calls `chclif_moveCharSlotReply(fd, sd, from, 1)` when `from >= MAX_CHARS`. That helper unconditionally reads `sd.char_moves[index]` using the supplied index. Therefore an out-of-range client-controlled `slot_before` reaches an unchecked array read before the reply is sent. The source trace establishes an out-of-bounds read path; impact/exploitability and the correct bounded fix require PK48 security review. Keep this request unsafe to implement/replay with hostile values until that review. This does not block independent PK44.03.010 source research.
