## Reachability and selected-profile result

The feature table default is enabled and `conf/battle/feature.conf:81` says `feature.achievement: on`. However, `battle.cpp:9454-9458` forcibly disables it whenever `PACKETVER < 20150513`; this selected build has `PACKETVER=20080910`. `pc.cpp:2484-2493` requests achievement data only while the feature flag is true. `intif.cpp:2219-2220` sends the list/update after an achievement-data response; because the old-profile login path does not request that data, this callback is not reached through normal server flow. Achievement mutation/reward callers in `achievement.cpp` likewise depend on the disabled feature path or on the absent `0x0A25` parser. The title request parser is absent, and its result sender is compiled out by the same date guard.

Thus these three parents are inactive for the selected source configuration even though several emitter functions are present in `clif.cpp` without local date guards. The decisive evidence is the forced feature disable and absence of active request registration/data-load path, not a declaration-only search. This proves source-config behavior only; the deployed server binary/config is not matched.
