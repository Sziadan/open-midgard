# Contract PK08 — ground skill request with text

Status: selected-profile source contract; implementation PK08.02–PK08.04. Server-source applicability baseline is PACKETVER/PACKETVER_SAK_NUM 20080910. Historical variants are not generalized from this record.

## Wire identities

The selected request is map-stage C2S `0x007E`, 102 bytes, `clif_parse_UseSkillToPosMoreInfo`, active registration `clif_packetdb.hpp:868`, parser offsets `5,9,12,20,22`. Fields:

The selected registration is guarded by `PACKETVER >= 20050509`; for effective 20080910, final registry resolution selects this 102-byte entry. The server's `0x007E` TickSend entry is an earlier assignment and is overridden for this configuration. The final assignment and parser offsets, not the first matching line, establish the selected contract.

`0x0190` is a distinct selected-profile 19-byte ActionRequest (`target ID` at 5, action at 18). `0x0437` is a distinct 7-byte ActionRequest used by the client profile-23 ordinary action path. Neither is a text-skill request. Historical packet databases contain other MoreInfo opcode/layout variants (for example 0x0113/110, 0x007E/114, or newer opcodes); PK47 owns historical applicability. The client profile-23 receive table's six-byte 0x007E entry is a receive-direction entry and does not define this outbound C2S layout.

## Server decode and action branches

`clif_parse_UseSkillToPosMoreInfo` first returns for a null session, `pc_cant_act`, or sitting. It reads level/skill/X/Y/text pointer via the effective registry offsets and calls `clif_parse_UseSkillToPosSub`.

The shared sub-handler requires a ground skill; rejects `PCBLOCK_SKILL`; routes homunculus and mercenary skills to separate handlers before player text-copy behavior (their MoreInfo argument is currently unused); rejects blocked progress; updates configured idle timers; rejects `skill_isNotOk`; for a player text request, sitting emits `clif_skill_fail`, otherwise `safestrncpy(sd.message, text, MESSAGE_SIZE)` copies the text. `MESSAGE_SIZE` is 80, so the destination is bounded and NUL-terminated, with at most 79 bytes retained. Subsequent checks cover active skill timer, can-act interval (except matching skill-item use), costume option, non-Renewal Basilica restriction, and menus: taming/Star Gladiator feel menus are cleared; Auto Spell is allowed; other menus reject. It then removes invincibility, uses the skill-item level when matching, or clears stale skill-item state, checks learned player skill level, clamps requested level to known level, and calls `unit_skilluse_pos` only when level remains nonzero. Graffiti/Talkie Box later copy `sd.message` into the skill unit string.

Text is not applied in the homunculus/mercenary early-return branches. No additional meaning is assigned to padding or text bytes. UTF-8/legacy encoding conversion is not established by these sources; caller encoding must be inspected before choosing a new conversion policy.

## Client call path and bounded implementation

Current client declares `PACKET_CZ_USESKILLTOPOSINFO` as 90 bytes and profile 23 sends it under `0x0190`, which conflicts with the active server's 19-byte ActionRequest registration. `BuildActiveUseSkillToPosInfoPacket` allows text up to 80 bytes, returns false for non-profile-23 sends, and writes skill/level/X/Y/text at the compact 0x0190 struct offsets. The `CGameMode::SendSkillToGroundWithText` action method currently has no caller in the repository. Thus the wire fix must not be described as a reachable UI feature until a user action is found or added under an approved implementation leaf.

PK08.02 selects the server's 102-byte 0x007E contract and separates it from both action requests. PK08.03 implements the production serializer and replaces the client-derived 90-byte test oracle with independent server-derived fixtures, including bounds and field offsets. PK08.04 self-reviews source branches, replay and call/UI reachability. Do not generalize to profile 22 or newer server packet variants without applicability evidence. Do not close AUDIT-0x007E or AUDIT-0x0190 solely because bytes serialize.
