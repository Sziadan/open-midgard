# PK20.NPC-CLASS-LIFETIME — selected 0x01B0 continuation decision

Strong source/design review, 2026-11-05. See [implementation evidence](../evidence/PK20.02-npc-class-change.md) for current coverage and [provenance](../evidence/STRONG-UNBLOCK-2026-11-05.json) for the design checkpoint.

Selected `clif_class_change` emits 11 bytes: opcode u16@0, GID u32@2, type u8@6 (zero), class u32@7. It rejects PC class IDs. Ref `Zc_NpcSpriteChange` resolves the existing actor and invokes its virtual class/resource setter; Ref `CNpc::SetSprJob` changes resource names in place. Unknown actors are ignored. Do not combine this operation with the distinct 0x01D7 appearance record.

## Implementation decision

1. Preserve the existing actor allocation, GID, world membership, position, master/child links and attached effects. Normally spawned NPC/monster actors already use CPc as their render carrier (`ApplyRuntimeActorState`, `ShouldUseSpriteBillboardActor`). Do not allocate a replacement merely because the job changes. Do not invoke generic base-to-CPc assignment/promotion: copying owning pointers is outside this reviewed path. If a placeholder lacks the required carrier, handle that case explicitly through the spawn lifecycle and test it separately.
2. Capture the old representation before writing the new class. Release the GID's old GR2 instance when changing representation. `Gr2Monster.cpp::ReleaseGr2Monster` erases an instance; global assets/pending loads are shared and must survive. Rendering already replaces a GR2 instance when its asset changes, but bounds and motion queries can observe the stale instance before rendering. GR2-to-sprite is especially important: the destructor tests the *current* job and otherwise misses the old instance.
3. Invalidate the billboard/resource cache through ownership-aware actor methods. ACT/SPR fetched from `g_resMgr.GetAs` are borrowed. `ReleaseActorBillboardTexture` deletes a texture only when its ownership flag says it is owned; expose a narrow method if needed instead of directly deleting borrowed resources. `CPc::InvalidateBillboard` clears job-dependent borrowed pointers and owned aura textures. Force the next render to resolve the new job; failed lookup must not display the old job's sprite or stale bounds. `EnsureBillboardTexture`/World's render-entry failure already supply a useful fail-closed path.
4. Refresh class-dependent bounds and picking without replaying spawn side effects. In the selected executable, the NPC vtable slot called by `01B0` resolves to `CNpc::SetSprAct(job, 0)`. The setter leaves position, motion, visibility flags and dimensions alone. The class-111 size adjustment belongs to `CNpc::SetState`. Keep attached effects whose owner is the actor.

## Required acceptance

Replay the production packet route for sprite-to-sprite, sprite-to-GR2, GR2-to-sprite, GR2-to-GR2, repeated same class, unavailable/pending resource, class 111, unknown GID, despawn and map exit. Assert stable actor address and links, absence of old GR2 bounds/instances, no stale sprite on failed load, and no shared resource deletion. Add a rendered check for changed appearance/picking. A model-only job assignment does not complete PK20.02.
