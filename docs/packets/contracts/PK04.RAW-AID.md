# Contract: PK04.RAW-AID

Status: IMPLEMENTATION_VERIFIED; independent PK48 review pending. Discovery parents: AUDIT-0x8482 and AUDIT-0x8483 (false numeric-opcode identities aliased to this one non-opcode handshake). Owner: PK04; cross-review PK44/PK47.

## Identity and authoritative exchange

- Stage: immediately after a fresh character-server TCP connection; direction S2C raw handshake, then ordinary framed S2C character-stage packets.
- Selected source profile: rAthena effective `PACKETVER=20080910`, `PACKETVER_SAK_NUM=20080910`. Server revision and deployed binary provenance are unknown because the source snapshot has no Git metadata.
- Client sends `PACKET_CA_ENTER` (`0x0065`) as 17 bytes: opcode u16@0; AID u32@2; login ID 1 u32@6; login ID 2 u32@10; unused u16@14; sex u8@16. All integer values are little-endian on the selected x86 wire layout.
- `src/char/char_clif.cpp::chclif_parse_reqtoconnect` reads the 17-byte request, initializes the session, then writes exactly four raw bytes containing `account_id` before running/auth rejection checks. The return is a little-endian u32 with no opcode or length. The following refusal is framed `0x0081`; success continues with framed character-stage traffic.

## Verified client behavior

`CLoginMode::OnChangeState(ConnectChar)` arms `CRagConnection::ExpectRawAccountIdEcho(g_session.m_aid)` after a successful connection and before sending `0x0065`. `CRagConnection::RecvPacket` waits until four bytes are buffered, compares the full decoded u32, consumes the prefix once on match, then applies the ordinary selected receive table to the remaining bytes. Mismatch closes and clears the connection before any suffix is delivered. EOF closes/clears through the existing socket path. Connect/close callbacks clear handshake state, so reconnect cannot inherit the previous expectation. Account-server and map-server paths do not arm this policy.

Fake receive-table entries for `0x8482` and `0x8483` and their silent LoginMode cases were removed. Those values were attempts to model possible low words of an AID as fixed-size packets; the server does not emit either as an opcode. They now map to this canonical raw-handshake contract as `ALIAS` discovery rows. No other numeric opcode is implied.

## Independent production replay

Evidence: `evidence/PK04.03-raw-aid-replay.md` and `.jsonl`. The local mock-char-server path captures the exact `0x0065`, sends literal AID bytes, then a framed empty `0x006B` and observes production character-list status/CharSelect. Twelve cases cover AIDs `0x12345678`, `0xA1B2006C` (fixed-opcode low-word collision), and `0xA1B20069` (variable-opcode low-word collision) at split positions 1–4. Each asserts no early packet, byte-exact suffix preservation and one-shot policy clearing. Additional records cover full-value mismatch, EOF with 0–3 bytes, ordinary framed reconnect, and removal of both fake size entries. Fresh deploy-off MinGW build passed; focused CTest passed 1/1. No live service or credentials were used.

## Limits

The mismatch record asserts connection close and suppression of any coalesced suffix. It does not instantiate the complete `CLoginMode::OnUpdate` frame that displays the existing generic char-server disconnect status. Visible Qt/UI behavior, deployed-server provenance, and independent PK48 review remain open. No broader character-list compatibility or deletion result is certified by this handshake contract.
