## Layouts and profile guards

Both variants use the same packed five-byte prefix: signed `int16` opcode `0x0B8D` at offset 0; signed `int16` packet length at offset 2; and `uint8 success` at offset 4. The sender writes `success=true`. Each entry is 16 bytes: `uint64 type` at entry offset 0 and signed `int64 points` at entry offset 8. In a list, entries begin at packet offset 5, and total length is `5 + 16*count`; count is therefore derived from packet length rather than carried as a separate field. In the single update, the one entry begins at offset 5 and total length is 21 bytes. These multi-byte fields are copied from packed structs; the snapshot does not establish the deployed binary's architecture/byte order. Exact maximum list count/buffer-capacity behavior is not proven by the sender trace.

Both emitters are guarded by `PACKETVER_RE_NUM >= 20211103 || PACKETVER_MAIN_NUM >= 20220330` (`clif.cpp:24256-24257` and `:24275-24276`). The selected effective MAIN value is 20080910; no RE or ZERO branch is active, so both sender bodies are compiled out for this configuration.
