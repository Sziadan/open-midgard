# PK09.CARD-NAME-ASSEMBLY — selected generic card name composition

Owner PK09, leaf PK09.08. Profile source-selected 20080910. Implementation checkpoint remains pending independent PK48 review. This extends [ordinary name contexts](PK09.ITEM-NAME-CONTEXT.md).

## Primary source contract

`Ref/ItemInfo.cpp::ITEM_INFO::InitItemInfoTables` populates `s_cardDescMap` from the card-item, card-illustration, prefix and postfix tables (5083–5177). Postfix table loading moves the loaded prefix label into the postfix field and clears the prefix. Reading `GetPrefix` alone without this initialization gives an incorrect dual-prefix/postfix interpretation.

For an identified generic equipment-like item, `ITEM_INFO::GetItemName` emits refinement, then enters generic card composition only if slot zero exists in `s_cardDescMap` (2294–2330). Unidentified items bypass composition. Other special sentinel branches remain separate required work.

`GetPrefix` (3581–3715) and `GetPostfix` (3448–3576) traverse four slots in order. A nonempty label groups later equal **card IDs**, never equal label strings. Prefix output is `[repeat-word ]label `; postfix output is ` label[ repeat-word]`. Counts two/three/four use localized Double/Triple/Quadruple. Unknown or empty descriptors contribute no label; no card-item-name/numeric fallback is invented.

Source-extracted English fixture examples on Knife1202 (four sockets):

- Slots 4001/4001: `Double Lucky Knife`.
- Slots 4001/4006: `Lucky Lucky Knife`; the IDs share label Lucky but remain separate groups.
- Slots 4014/4014: `Knife of Champion Double`. Postfix metadata cleared that card's prefix.
- Slots 4001/4014/4002/4014, refine seven: `+7 Lucky Vital Knife of Champion Double`.
- Unidentified state suppresses all those affixes and refinement: `Dagger`.

Shared hover names omit computed socket suffixes per PK09.07. Existing list label defaults retain the suffix at the base name, before postfix labels. This leaf does not independently certify every list context.
