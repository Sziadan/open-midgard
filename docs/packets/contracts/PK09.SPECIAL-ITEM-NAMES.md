# PK09.SPECIAL-ITEM-NAMES — created/forged and named-pet display

Owner PK09.09; source-selected 20080910. IMPLEMENTED_PENDING_REVIEW. [Character-name dependency](PK45.CHARACTER-NAME.md) owns the CID request/reply/cache. Independent PK48 and deployment remain open.

## Source and field interpretation

Primary `Ref/ItemInfo.cpp::ITEM_INFO::GetItemName` 2198–2427 establishes identification and marker precedence. Selected server `clif_addcards` (`clif.cpp:2755` onward) copies forged/created words verbatim, but normalizes pet eggs: words zero/one become zero, word two is intimacy (`stored card[3] >> 1`), word three is the renamed flag (`stored card[3] & 1`). `item_data::isStackable` and the list emitters send pet eggs through the non-stackable/equipment wire category. This is independent of their **Other** inventory tab; primary `UIItemWnd::Sort` 1374–1388 places type seven there.

All four transmitted card words are u16 LE in the selected normal/equipment records. Created marker is 254, forged marker 255. Producer CID combines unsigned words two and three as low/high halves. It is a character ID; use `ResolveCharacterName`, never actor lookup. Forged word one's low byte carries element 0 normal, 1 Ice, 2 Earth, 3 Fire, 4 Wind; high byte values 5/10/15 select one/two/three star-piece prefixes. Other high bytes contribute no star label; unknown low bytes contribute no element separator. Those unknown combinations are synthetic source-branch tests, not claims of valid production forging recipes.

## Name assembly and precedence

1. Unidentified items use their unidentified base name and suppress producer, refine, star and pet markers.
2. The primary bare named-pet pattern is words `0,0,0,1`, evaluated before the item-type switch. It prefixes the named-pet message and ignores refinement.
3. **Selected-server extension:** words zero/one zero and renamed flag one keep the named marker when intimacy is nonzero, independently of the normalized item-type byte. The selected emitter adds that field unconditionally. Requiring the old third-word zero would lose the rename flag's visible meaning on real selected-server eggs. All raw words remain intact.
4. Marker 254 applies before item-type classification **only when word one equals zero**, including its high byte. Compose optional `+N `, producer, normal manufactured separator and identified base name. Do not generalize this branch to nonzero elements or star bits.
5. Marker 255 is inside the primary equipment-like type switch (4/5/8/9/11–15/19), after generic card-descriptor detection. Compose optional `+N `, star prefix, producer, element/manufactured separator and identified base. Non-equipment types do not acquire a forged name from marker 255.
6. Ordinary card names retain PK09.08 behavior. Hover names omit computed socket suffixes; existing list/detail label defaults retain their suffix at the base name. This checkpoint does not certify all such label contexts.

The nine message values come from positional `msgstringtable.txt` indices 450–454, 459–461 and 756. Primary English rows include literal apostrophe/space separators and `Very Strong ` variants. Index 756 is exactly `Beloved`, with **no trailing space**; it is concatenated literally. No cosmetic separator is invented. Missing message resources use those source-derived English fallbacks; configured empty entries stay empty. Numeric MSI indices are cross-checked with the secondary enum header, while the primary name routine and primary GRF message bytes define behavior and text. Full locale/encoding parity remains separate work.

## Visible behavior and lifetime

Qt raw-type-seven compatibility rows now match the primary/native Other tab; actual selected pet eggs arrive normalized as type four and stay in Equipment. Pickup announcements use the same primary GetItemName semantics without a list-only socket suffix.

A nonempty character-name reply invalidates inventory, storage, equipment, item info and shortcut native surfaces. Names are recomputed from retained item words plus the CID cache. A stationary native/Qt hover and a retained detail model update without another item packet. Replacement names recompute similarly; item snapshot removal removes the corresponding item/name delegate.
