## Identity and selected layout

Map-stage server-to-client packet `ZC_PROPERTY_PET`, opcode `0x01A2`. Effective server defines are `PACKETVER=20080910` and `PACKETVER_SAK_NUM=20080910`; the selected `PACKETVER` is defined. `PACKET_ZC_PROPERTY_PET` in `src/map/packets_struct.hpp` is packed. For this profile it is 35 bytes:

| Offset | Width | Field | Meaning |
|---:|---:|---|---|
| 0 | 2 | `PacketType` | opcode `0x01A2` |
| 2 | 24 | `szName` | pet name |
| 26 | 1 | `bModified` | modified/rename indicator |
| 27 | 2 | `nLevel` | level |
| 29 | 2 | `nFullness` | hunger/fullness |
| 31 | 2 | `nRelationship` | intimacy |
| 33 | 2 | `ITID` | accessory item ID |

The packed integer fields use the selected source's native integer declarations; the client wire convention is little-endian. `job` at offset 35 is present only under `PACKETVER >= 20081126`, producing a distinct 37-byte variant. Do not include that field in the active 20080910 decoder. The packet carries neither pet actor ID nor class in this selected layout.

## Emitter and branch behavior

`clif.cpp::clif_send_petstatus(const map_session_data&, const pet_data&)` zero-initializes the packet, assigns header and bounded name, sets `bModified` to zero when `battle_config.pet_rename` is enabled and otherwise copies `pd.pet.rename_flag`, copies level/hunger/intimacy, narrows equipped item to the packet field type, and sends to `SELF`. Its callers include map-load/status initialization, pet load/hatch, pet menu status requests, rename accept/reject, evolution, and atcommand/script/status paths. Those events produce status snapshots; they do not define pet creation/disappearance lifecycle. PK27 owns that lifecycle and actor association.

The client now declares `0x01A2` as 35 bytes in `GronPacket.cpp` for selected profile 23 (the audited 20080910 profile). PK07.02's production receive replay verifies a literal 35-byte status frame followed by a 3-byte fixed packet remains aligned. `ro::pet::ReadStatus` validates exact size and opcode, decodes the fixed name and signed fields into a temporary value, then commits the snapshot to session state through production dispatch. No actor ID is created. Profile 22 retains its prior 37-byte framing pending separate date/layout verification; neither that retained behavior nor the guarded 37-byte source variant is newly certified. Broader UI and owner/actor lifecycle remain PK27.
