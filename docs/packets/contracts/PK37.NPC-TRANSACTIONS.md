# PK37.NPC-TRANSACTIONS — selected legacy NPC request and reply ownership

Owner PK37.09; selected 20080910 C5/C8/C9 and CA/CB. This is a bounded client implementation checkpoint. Broad PK37, PK46.02, independent PK48 and deployed acceptance remain open.

## Wire and validation

C5 is seven bytes: NPC ID@2, type@6. Validate the entire GameMsg argument as0/1 before narrowing. Require a nonzero NPC ID, a live player and a current choice context; suppress repeated C5 while its list is pending. Successful queueing hides the retained chooser; a rejected/disconnected send preserves it. C6/C7 establish the source quote and clear the pending choice.

C8 is header4 plus repeated amount.W/itemID.W; C9 is header4 plus index.W/amount.W. The server packetLength fields are signed16: require a positive length at most32767, so the largest aligned request is32764 bytes/8190 rows. Validate every row before serializing any bytes. Reject empty/wrong-mode/dead-player actions, quantities outside1..30000, IDs outside1..65535, invalid sell indices, oversized frames, duplicate buy item IDs and duplicate sell indices. Do not clamp quantities or mask identifiers into another request. The selected source quote must still contain each item and its quoted unit price/type must match the deal. A sell also requires the current unworn inventory slot, enough quoted/current count and matching item identity, location, identification, damage, refinement, card words, bind/ownership and expiry metadata. Quantity and price are not part of the metadata identity comparison.

## Counts and input

Use the server stackability predicate: types4/5/7/8/12 are nonstackable, others stackable. Selected C6 projects pet eggs/shadow gear to4/5; raw7/12 are defensive classification boundaries. Session adjustment and submission enforce one nonstackable item. Delay-consume11 and the other default stackable types can use the count prompt. Existing100/1000 prompt ceilings remain a separate primary-UI provenance boundary; the underlying stack ceiling is30000.

An old count prompt must not target a replacement list by row ordinal. C4/shop close, a valid replacement C6/C7, successful submission, local cancellation and storage transition hide the shop quantity prompt and clear its callback. Only a GameNumberPrompt for RequestShopAdjustDeal is affected by the quantity-specific helper; other script number prompts retain their own lifecycle.

## Submission, results and local close

Primary submission closes the shop panes immediately and clears the deal. Current code performs that transition after SendPacket accepts the frame, preserving editable state on immediate send failure. Queue acceptance is not a server commit. Hide the NPC dialog/shop/count input, clear editable quotes/deals and release the conversation lock; preserve description snapshots. Never optimistically deduct inventory or zeny from CA/CB or send success.

CA/CB carry no transaction ID. Keep expected reply families in send order, independently of editable NPC context. A later C4/C6/C7, local shop cancel or storage opening must not replace an older expected reply. Consume only the matching front family, once. Known selected normal-shop CA0/1/2/3 and CB0/1 retain their result messages; an unknown matching code finishes that receipt without an invented message. An unsolicited/wrong-family reply does nothing. Result processing must not close current panes, clear current quotes or release a newer conversation lock. Map init/exit and character/session reset clear receipts. This models ordered replies on the selected connection; it cannot identify arbitrary duplicated same-family application replies without protocol IDs.

Primary shop cancellation is local: close NPC dialogs/shop/count input, clear editable deal/choice state and release the lock. Do not send an empty C8/C9, script-close0146 or later-profile09D4. Empty C8 is a real failing transaction; empty C9 is a real zero-value sale. Older queued transaction receipts remain expected after a later local cancel. Cancellation needs no live transport; an inactive shop cancel does not close unrelated dialogs.
