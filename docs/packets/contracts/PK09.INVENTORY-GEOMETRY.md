# PK09 inventory rectangle and mini lifecycle

Primary source: Ref/UIItemWnd.cpp message34 (4368-4387), resize message14 (4248-4291), mini message6/136 (4219-4246), and StoreInfo (11513-11528); Ref/UIRectInfo.cpp ItemWndInfo::IsValidInfo (485-506), MakeDefault (1255-1270); Ref/UIWindowMgr.cpp startup override (10909-10915), MakeWindow case8 (5021-5047) and registry save (12908-12917). Ref remains read-only.

The inventory manager record owns x/y, width, current height, original expanded height, tab and radios. A missing UI record defaults to0/120/280/120/original120/tab0/All3,3,4. Warm startup overwrites x/y/width/current height/original height/tab with744/514/280/134/134/1, retaining the radio inputs. Existing disk geometry and tab do not survive this override. INI [UIWindows] presence maps the reference registry-key presence; missing optional radios retain initialized All. This preserves PK09.12 startup selection.

On each new window attachment, validate the entire stored record: x/y nonnegative and fully containing stored width/current height in the logical viewport; tab0..2; radios0..3/0..3/0..4. Failure defaults the entire record, including tab, rather than clamping x/y independently. Source validation does not require positive dimensions, limit originalHeight, or require a particular current/expanded height pair. Wide containment arithmetic avoids overflow; accepted dimensions are normalized before any allocation or display. Synthetic negative-dimension tests document this source branch without claiming a valid emitted packet or user-generated setting.

Initialization first resizes from stored width and originalHeight: clamp width to232..320 and requested height to102..240, then use width=280+32*((width-280)/32), height=38+32*((height-38)/32), with signed division truncating toward zero. Store the normalized live height as the restore height. Compare the original stored height and originalHeight; if they differ, collapse. Finally apply the stored position and tab. The default record thus produces a280x102 live window while its manager record still has height/original120 until StoreInfo. Warm startup produces280x134. Lower input width232 normalizes to248; maximum320 normalizes to312. Do not replace the truncation with floor division or add a premature record writeback.

Mini message136 toggles current height17 and the captured full height, retaining current width. Entering mini captures the live height; expanding does not independently clamp position. A stored mini record at y600/h17/original134 is valid in a720-high viewport; expanding can extend below it. This is a deliberate source rule. Whole-record validation occurs on recreation, not on shared tab reads or resize. Explicit native/Qt close deletes owned inventory windows and stores their record; unowned stack fixtures hide without being deleted. Existing hide/reuse paths retain the same object. Map visibility/recreation beyond these explicit paths remains a separate acceptance requirement.

The manager retains this record within the process. StoreInfo writes ItemWndX/Y/Width/Height/OrgHeight/Tab/Radio1/Radio2/Radio3 into the private/current INI. Native and Qt input share the same setters. Native and Qt drag release persist the record; resize commands use the same normalization as initialization. Storage geometry/tab remains independent.

Qt retains its modern palette and controls while using a17-pixel inventory header, vertical tabs,32-pixel item cells and native dimensions/coordinates. Mini hides the body and item delegates. Inventory avoids a second QML-only position clamp, so rendering and native geometry agree. Other commerce panels retain their layouts. QML resize and mini controls perform presentation actions only, with no packet construction or authoritative inventory mutation.

Accepted here: inventory rectangle initialization, normalization, whole-record fallback, mini/restore, explicit close/recreation, persistence and actual native/Qt controls at100% scale. Detail-window geometry/default placement, complete map/show restoration, broad item/status/delta/context acceptance, scale transitions, locale/art, PK47 and independent PK48/49/deployed provenance remain open. No discovery row is closed by this leaf.
