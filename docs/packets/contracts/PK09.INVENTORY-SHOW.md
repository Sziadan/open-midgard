Inventory's remembered-open bit belongs to the manager, separately from the live m_show flag and geometry. Both missing-record defaults and the warm startup override initialize it false. In particular a saved ItemWndShow=1 must not make inventory appear at process startup. Snapshot startup state once; later records/disk writes do not reinitialize it.

MakeWindow inventory reuses an existing hidden instance without reapplying saved geometry or resetting its tab/mini/scroll state. Creating an absent instance follows PK09.13's complete-record validation, quantized full rectangle and optional17-high mini initialization. Both paths show the instance and set remembered-open true. Explicit deletion clears remembered-open; normal StoreInfo writes geometry/tab/radios without changing it. A raw SetShow(0) stores/hides the instance but retains the bit, matching the distinction between window presentation and an explicit source close.

The basic inventory button and Alt-E take the source DeleteWindow-first branch, including an existing hidden owned instance. Deleting stores its current rectangle/tab/mini state and clears remembered-open; pressing again creates from that record. Do not emulate this user close solely by hiding and retaining the same object. The local unowned stack-fixture compatibility path can only hide safely and must clear remembered-open when used as an explicit close.

Bulk teardown is different: StoreInfo and destroy every owned window while preserving remembered-open. Clear native capture/edit/hit pointers through the existing deletion machinery. Do not route bulk inventory destruction through the explicit-close flag update. At basic UI construction, reopen inventory if remembered-open is true; otherwise leave it absent. The factory validates the saved complete rectangle before recreation, then shows the new instance and marks it open. Repeated basic construction only shows/reuses the existing inventory. Invalid saved geometry falls back as PK09.13 specifies; live MakeWindow ends open even if validation resets the intermediate default bit.

Production OnInit/OnExit already perform bulk window teardown; FinishMapLoading constructs basic UI. Thus open inventory returns on the next basic-UI construction, preserving valid in-process position/full height/mini/tab, while explicitly closed inventory stays closed. This does not preserve server item rows or transaction state: PK09.05's actual map reset remains authoritative, and fresh packets repopulate rows. Storage and readonly main/card details remain separate lifetimes.

The INI adapter writes ItemWndShow when the remembered state changes and continues to ignore it at fresh startup, following the source override. It never treats arbitrary record inspection or geometry persistence as an open request.
