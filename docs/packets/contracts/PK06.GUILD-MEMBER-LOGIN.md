## Server behavior and branches

`guild_recv_memberinfoshort` updates the matching guild member's prior/current `online` flag and only calls `clif_guild_memberlogin_notice` when `oldonline != online`. The notice emitter sets AID, CID, and status. If the member's session pointer is available, it fills gender/hair fields and sends with `GUILD_WOS`; otherwise it fills those three fields with zero and sends with `GUILD` to an available guild session. Thus duplicates with unchanged status do not emit this notice, and zero appearance values are valid on the no-session branch.

Do not claim the server sender's login/logout classification is exhaustive beyond this call path. The transport contract only establishes the bytes and these branches.

## Current client gap and implementation boundary

Initially, `src/network/GronPacket.cpp` registered `0x016D` at size 14 but had no `0x01F2` entry. `ro::guild::ReadWindowPacket` and the production guild router supported only `0x016D`; an incoming `0x01F2` therefore closed the connection under PK05. PK06.02 adds exact 20-byte framing and production decode/dispatch for 01F2 while retaining the legacy 016D identity. The QML guild list displays each member's `online` field; propagation and visible update remain PK06.03.

- PK06.02: completed exact 20-byte framing for `0x01F2`, atomic decode, matching-member state update, appearance retention, and production dispatch. Malformed 01F2 status values are rejected; no member is synthesized from a notice. Legacy `0x016D` remains distinct.
- PK06.03: propagate member status and appearance changes to UI models and guild/map lifecycle, including missing member and stale/disappearing session cases. Do not create a phantom member from a notice alone unless authoritative evidence establishes that behavior.
