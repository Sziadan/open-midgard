## Source and selected server

Source `CGameMode::SendMsg`5833A0 message158 builds CZ_RENAME_PET01A5/26 bytes: opcode followed by24 raw name bytes. A source name of24 or more bytes is copied then field byte23 is overwritten with NUL. Shorter names include their NUL; remaining source stack bytes are undefined. The port defines those bytes as zero. No charset conversion, UTF-8 repair, name validation or optimistic state mutation belongs to this sender. Null source pointer is outside defined source behavior and is rejected in the port.

Message163 builds CZ_COMMAND_PET01A1/3 bytes, with the low byte of its argument at offset2. It does not clamp or reject unknown action values. Source callers own confirmation, local state and window lifetime. Failed immediate sends report failure without changing caller state.

Pinned server `clif_packetdb.hpp`190/192 and `clif.cpp`14712/14768 agree with these lengths and offsets. Hashes of the current local `clif.cpp` and `pet.cpp` match the selected baseline. `pet_menu`1422 requires an extant pet with nonzero pet ID, positive intimacy and non-incubated state. Actions0/1/2/3/4 request status/feed/performance/return egg/unequip accessory. `pet_change_name`1460 requires pet data and respects the rename flag unless the server override allows another rename, rejects control bytes/DEL, then forwards to inter-server rename. These are server decisions; the request sender must not duplicate or guess them. This source inspection is not a live server test.
