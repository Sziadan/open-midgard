## Primary filter and controls

Primary `Ref/UIItemWnd.cpp::UIItemWnd::Sort`1362–1444 and `UIItemStoreWnd::Sort`1273–1355 define the three visual tabs. With initialized All selectors, Usable accepts types0,1,2,18; Equipment4,5,8,9,11,12,13,14,15; Other3,6,7,10,16,17. All other values are excluded from every tab. Unknown types must not fall through to Other. Tab membership does not rewrite the item type or decide whether a packet uses normal/equipment records.

Initialization messages34 set the internal subtype fields to3,3,4 (`Ref/UIItemWnd.cpp:4117–4119`, `4375–4379`). Constructors initially zero those fields; filtering acceptance uses the initialized window. The saved inventory subtype fields are overwritten with All on initialization; storage saves geometry only. Switching tabs does not reset these fields. `ItemWndInfo::MakeDefault` (`Ref/UIRectInfo.cpp:1257–1269`) sets the default tab to0; initialized inventory restores the saved tab, so the constructor's transient tab1 is not the user default. Saved-tab persistence beyond the existing map preference check is not accepted by this leaf.

The subtype predicates are present in Sort, but normal primary inventory/storage have no connected subtype radio UI. `UITab::OnLBtnDown` (`Ref/UIControl.cpp:7457–7478`) selects one of three tabs and sends parent message22. Its constructor initializes three tabs; normal window OnCreate uses this widget. Searches of the primary field accesses show only constructor and initialization writes, Sort reads and inventory StoreInfo. UIRadioBtn's generic message6 path does not establish a control or update of these fields in item windows. Preserve the actual three-tab interface with All selectors; do not add guessed subtype labels or dead radio options based on dormant branch values.
