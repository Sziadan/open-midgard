C2S `0x0A1E` length 3 is also null-parser and has no corresponding sender found in this trace.

S2C identities and layouts are confirmed by emitters in `clif.cpp`: `clif_roulette_open` (`20855-20877`), `clif_roulette_info` (`20892-20918`), `clif_roulette_generate` (`21018-21034`), and `clif_roulette_recvitem_ack` (`20948-20960`). The same numeric opcodes also have separate null-parser C2S framing registrations in the later profile. `0x0A22` therefore has both a C2S ignored-input framing identity and an S2C item-result identity; retain both directions beneath the discovery parent.

The selected 20080910 source has no active `0x0A19/1B/1D/1F/21` parser registrations. The two non-parser open callers are also gated: `ACMD_FUNC(roulette)` in `atcommand.cpp:11298-11316` rejects `PACKETVER < 20141022`; `BUILDIN_FUNC(open_roulette)` in `script.cpp:26450-26469` likewise rejects older dates. Those are the only direct call sites of `clif_roulette_open` found besides the gated request parser. The info/generate/item-result emitters are reachable only from the absent later request parsers. `clif_roulette_recvitem_ack` additionally compiles its send body only under `PACKETVER >= 20141016`. These gates prove that this source config has no reachable roulette packet emitter/parser path, even if `feature_roulette` is enabled.

## Client and Ref comparison

The 20080910-generated packet inventory reports no client framing size/receive handler for these parents.
