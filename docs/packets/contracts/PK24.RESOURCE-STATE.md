## Authoritative local resources and stats

- `00B0` and `00B1` are eight-byte frames with parameter u16@2 and signed dword@4. `clif_updatestatus` sends HP/max HP/SP/max SP, weight, levels and combat values with `clif_par_change` (`00B0`). Its selected branch uses `clif_longpar_change` (`00B1`) for Zeny and base/job EXP and their next values. Selected `client_exp` caps the encoded value at `INT32_MAX`. Keep the client resource owners full width and interpret combat and weight values according to their signed domains. Legacy character-card fields can have a separate bounded representation. The `0ACB` long-long parameter frame is outside the selected EXP branch.
- `0141` is 14 bytes with stat ID u32@2, base s32@6 and bonus s32@10. `clif_couplestatus` sends the six primary stats, with bonus equal to battle stat minus base. Decode the two signed dwords independently. Add them in widened arithmetic before narrowing to the actor's nonnegative `u16` stat field. The selected status summary can rebuild the actor from a new byte-sized base snapshot and the current signed bonus.
- `00BB` is the five-byte C2S stat-increase request with stat u16@2 and amount byte@4. `00BC` is the selected six-byte acknowledgement with stat u16@2, success u8@4 and result u8@5. `00BE` is the five-byte point-cost update with stat u16@2 and cost u8@4. Use the existing request, ACK and cost owners. [Request evidence](../evidence/PK46.02-map-status-increase-request.md)
- `00BD` is the selected 44-byte `clif_initialstatus` snapshot. Points u16@2 are capped to `INT16_MAX` by that emitter. Bytes@4–15 are six interleaved unsigned base-stat/cost pairs in STR, AGI, VIT, INT, DEX, LUK order. Fourteen signed words@16–43 carry attack/refine, max/min MATK, item/bonus DEF, base/bonus MDEF, HIT, FLEE/bonus FLEE, critical, raw attack motion and bonus ASPD. The emitter follows the snapshot with full-width `0141` updates. Preserve signed combat fields and the existing raw-motion conversion for the ASPD display.
- `0214` is the 42-byte `clif_check` GM inspection reply. It carries six inspected-character base/cost pairs@2–13 and fourteen combat words@14–41. ASPD is already in display units. `Ref/GameModePacket.cpp::Zc_Ack_Status_GM` formats five chat lines using signed combat values and never writes local status. The current handler shares the self-summary mutation path, so route the GM response to chat in PK24.02 and assert local state isolation.
