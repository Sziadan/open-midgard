# Contract: PK44.CHAR-RAW-AID-HANDSHAKE

Status: SOURCE_BACKED; PK04 implementation verified; independent review deferred to PK48. Owner step: PK44.03.003. This non-opcode sub-contract cross-reviews primary package `PK04` and applicability contract `PK01.P01.HANDSHAKE`; canonical implementation evidence is `PK04.RAW-AID`.

## Server exchange

The source snapshot and effective config are the PK01.02 hash-pinned local rAthena source (`PACKETVER=20080910`, `PACKETVER_SAK_NUM=20080910`; no Git metadata, deployed provenance unknown).

On a fresh character-server connection, the client sends the 17-byte `CA_ENTER` / `0x0065` request: opcode `u16` at offset 0, account ID `u32` at 2, login ID 1 `u32` at 6, login ID 2 `u32` at 10, unused `u16` at 14, sex `u8` at 16. The server's `chclif_parse_reqtoconnect` waits until 17 bytes are present, consumes them, initializes the session, then unconditionally writes the 4-byte account ID back at offset 0 (little-endian server wire representation) before checking whether the server is running or validating the auth tuple. The echo therefore precedes either successful character-list output or the rejection response. It is raw bytes, not a framed packet and has no opcode.

The server does not validate the account ID's numeric value before echoing it. Authentication then compares account ID and both login IDs against the auth node; on failure it asks the login server to authenticate or rejects if that connection is unavailable. An already-authenticated session's repeat request is discarded after the initial 4-byte echo.

## Client receive behavior

Before PK04 implementation, `CRagConnection::RecvPacket(std::vector<u8>&)` interpreted the first two bytes as an opcode. Fake IDs `0x8482`/`0x8483` had four-byte packet sizes and were silently ignored; other account IDs lost two bytes to unknown-opcode recovery. PK04 removed those assumptions. The current ConnectChar path arms an expected AID, waits for the complete four-byte prefix, validates it before framing, and clears the one-shot policy on match/close/reconnect. The canonical contract `PK04.RAW-AID` and production replay `evidence/PK04.03-raw-aid-replay.md` establish the fixed and variable low-word collision cases, all prefix splits, mismatch, EOF, suffix preservation, and reconnect reset.

This handshake now passes the bounded selected-source production replay. The replay verifies transport close on mismatch; the full `CLoginMode::OnUpdate` frame and its visible generic disconnect notification remain outside this contract.

## Scope and limits

`AUDIT-0x8482` and `AUDIT-0x8483` are now `ALIAS` rows mapped to `PK04.RAW-AID`; they are not server opcode registrations. The source trace and local loopback do not certify original-client behavior, deployed-server provenance, visible UI behavior, or full character-stage semantics. PK44 downstream character behavior beyond this four-byte prefix remains separately owned.
