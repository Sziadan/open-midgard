# PK22.TIMED-STATUS-043F — selected source applicability

Decision, 2026-11-05: map S2C timed status 0x043F is **INACTIVE_FOR_SELECTED_SOURCE_CONFIG** (PACKETVER/SAK/MAIN 20080910). This is a source-configuration decision, not a claim about the deployed server or every historical 0x043F identity. See [probe and hashes](../evidence/STRONG-UNBLOCK-2026-11-05.json).

`src/map/packets_struct.hpp` declares `status_changeType` as 0x0983 from 20120618, 0x043f from 20090121, and `sc_notickType` (0x0196) earlier. The selected `packet_status_change` is nine bytes. Its timed fields are guarded out. `packet_status_change2` is separately declared as a 25-byte 0x043f structure: Left u32@9, val1/val2/val3 signed i32@13/17/21. Declaration is not an emitter.

`clif_status_change_sub` in `src/map/clif.cpp` uses those same version branches: selected 20080910 always sends the untimed 0x0196 record. The later branches use 0x043f/0x0983 only for enabled status plus display timers; disabled status uses 0x0196. A complete `src` search finds no use of `status_change2Type` beyond its declaration. The compiled header probe independently reports selected 0x0196 size 9 and alternate 0x043f size 25; the printed gate is a preprocessing check, not compilation/execution of the entire emitter.

`clif_packetdb.hpp` first registers 0x043f as eight bytes at 20081113 (RE 20081112), later changing to 25 at 20090114 (RE 20090121). The effective selected registry has no 0x043F entry. The eight-byte historical identity must not be merged with this timed-status structure just because its opcode matches.
