# Source mismatches

Pre-filled list, with the resolution already chosen, is section 9 of `docs/SKILL_SYSTEM_1TO1_IMPLEMENTATION_PLAN.md`. New disagreements found while implementing:

- `CRagEffect::OnProcess` and `CRagEffect::OnProcess2` are both annotated in `Ref/RagEffect.cpp` as decompiled from `0x5E6E50`. The function body that actually dispatches effect ids 0–299 and 374–490 is `HighPriest.exe.c` `CRagEffect::OnProcess`. `OnProcess2` in `Ref/RagEffect.cpp:10606` is the 300–373 tier. The handler index follows that split.
- `m_skillAttackedEffectIdTable` index 0 is assigned with `*table._First = 0` in `Ref/Session2.cpp`, not `_First[0]`. The generator treats a star-assign as index 0. The decompiler's `for` loop that writes `_First[i - 1] = -1` is the -1 fill, not an extra entry.
- `LaunchSkillSpecialEffect` skills 540 and 469 are decompiled as storing `tActor->m_gid` into `pos.y` before `SendMsg(14)`. Every other `SendMsg(14)` in that function copies a world position, and message 14 writes `m_deltaPos`. The port copies `tActor->m_pos` for those two skills as well.
- `CArrowEffect::SendMsg` in `HighPriest.exe` takes a fourth integer, the monster job that selects the bullet sprite. This client's `CGameObject::SendMsg` has three parameters. `MakeArrowEffect` stores the job on the arrow with `SetSpriteJob` before message 14. Message 64 (skill 47) always uses `skel_archer_arrow`, matching the 2008 function, which ignores that argument.
- `Ref/dhxj/GameActor.h` `WBA` is larger and puts `attackedSpeedFactor` later than byte 32. The 2008 stack frame is 40 bytes and message 27 writes the float at offset 32, so the port follows that layout. `targetGid` stores the attacker's gid, which is what `Am_Skill` assigns from `this->m_gid`.
- Resolved 2026-10-25: the earlier claim that `GetForceAnimEndTick` is absent was incorrect. It is `Ref/Session2.cpp:2912`, with the setter at :7899. Both are ported, packet `0x01D2` is framed/routed, and skill 272 now uses the stored duration (missing AID returns unsigned -1, as Ref).
- Message 132 (`Ref/GameActor.cpp:4878`) creates a `CMsgEffect` of type `0x16` for the running total. That message type is not ported. Messages 130 and 133 still emit damage kind 22 through message 88.
- `Am_Skill` / `Am_Action` fall back to `CWorld::GetSkillByAID` when the target gid is not an actor. `CSkill` is WP4, so a missing actor uses the mirrored position instead.
- The miss path for local-player effect states 19 and 104 sends message 127 (`Ref/GameActor.cpp:3987`). `IsExistEffectState` is not ported, so that miss uses message 89.
- `Am_Groundskill` `PlaceEffect` is a world-anchored `CRagEffect` kept alive for `durationTable[id] + 10` frames. The original uses `CDummyEffectLauncher`, which is not ported yet.
- Falcon message 29 has no handler on `CMsgEffect`. Skills 129, 381, and 130 still send it, and the falcon does not move until that case is ported.
- `SetAttrState`'s last block forces the local player invisible on every call and bumps `g_FirstEffect` toward `CPlayer::ReLaunchBlurEffects`. That hide is not applied. `IsMasterAid`, emblem windows, and `Delete99LevelEffects` are not in src, so those branches are skipped. Messages 105 and 106 are sent for chicken and star, but the 2008 `SendMsg` decompile has no top-level case for them.
- `Zc_Notify_Skill` sends `CGameMode` message 99 for a non-monster. There is no case 99. The decompiler casts the packet buffer to `CPlayer`, so the port passes skill id, source actor, and level, the same arguments `Zc_Use_Skill` uses. Monster motions use `CSession::GetJobName`; the 2008 client indexes `m_jobNameTable`, so a name that does not match the monster-skill XML leaves the action at -1.
- `CSkill` message 7 creates a `UITransBalloonText`. The balloon class is not in src, so message 7 falls through to `CGameActor::SendMsg`. `ShowModel` deletes the `C3dActor` it owns; the 2008 function unlinks it from `SceneGraphNode` and drops the pointer. The process loop that deletes a unit when `OnProcess` returns 0 also erases it from `m_skillList`. The 2008 loop erases the actor list only.
- `CGraffiSkill::OnInit` creates the text texture as `PF_A1R5G5B5`. The port uploads `PF_A8R8G8B8`, which is the format `CTexture::Update` samples. The decompiler leaves the space width in the same register as the string length; a space advances 32 pixels, the step the word-wrap lookahead already adds per character.
- `Zc_Notify_Act` also rolls pet speech and `GetMonsterTalkInfo` before message 11. Neither call exists in src, so the port sends message 11 only. `Zc_Notify_Act_Position` (`Ref/GameModePacket.cpp:16833`, opcode `0x008B`) reads a 23-byte body and forces `attackMT` 432 and `attackedMT` 288. `packet_ver` 23 and eAthena 2011 keep `0x008B` at length 2 and do not send it (`clif.c:15960`), so that handler is not registered.
- `CRagEffect::Init` indexes `durationTable` with no range check. Effect ids outside 0–709, including the map-portal ids `50001`–`50003`, are not in the 2008 table. Those keep a fallback duration instead of reading past the table.
- `CGameMode::OnUpdate` stores `GetSkipFrameCount()` in `g_isSkipFrame` and calls `ProcessActors` that many times, or once when the count is 0. This client already steps the world from `m_worldProcessCarryMs`. `g_isSkipFrame` is that step count, so the effect gate matches the steps that actually run. The per-id `OnProcess` switch is still the handler enum except the `OnProcess2` cases listed in the parity log. `OnProcess3` is not a separate function yet. `RenderCloud` is ported for `flag[2] == 11` (heal sparks) and `flag[2] == 10` (the thunder particle burst). The other `RenderCloud` cases are not used by these effects. `RenderWind` places the 1/21 texture strip on U. The 2008 `RenderTeiRect` used by that prim places the strip on V. `WarpZone2` orbit sparks draw with the soft-disc billboard. The 2008 launch calls `SetSprName` and `SetActName` for that prim. `ForestLight`, `Portal2`, and the other `OnProcess2` helpers still launch prim types this client does not process.
- `HandleActorStateChange` no longer calls `RefreshActorEffectStatePresentation`. `SetAttrState` owns visibility. Sight still launches effect 601 from the packet handler because `SetAttrState` only plays the sight wave. `Zc_State_Change` also writes session body/health/effect, sends equip-window message 60, and clears merchant items. Those session fields and that window message are not in src.
- The monster-action check in `Zc_useskill_ack` is decompiled as a float compared with `NAN`. That comparison cannot succeed. The port uses `act != -1`, the same test as the other `GetMonsterSkillInfo` callers. Message 99 is still absent, so a non-monster cast does not open the skill-name window.
- `Zc_Use_Skill` skills 124 and 131 face the unit from `GetSkillByAID` and launch effects 100 and 111 on it. Skill 131 then sends message 29 to `m_birdEffect`. Falcon message 29 still has no handler. Skill 244 deletes the homunculus info and skill windows and clears `m_homunAlive`; those windows and that field are not in src. The actor still faces the target. `CGameMode` message 99 is sent for a non-monster, and there is still no case 99.
- Three `Zc_Use_Skill` sites (skills 0x23C–0x23F, 0x176, and 0x18C) are decompiled as storing the target gid into `pos.y` before message 14. Message 14 writes `m_deltaPos`, and every other message 14 in the function copies a world position. The port aims those three at the target position. Skill 61's `400 * HIDWORD(beginEffectId)` is the unclamped signed level: the effect tree writes that level over the `GetSkillActionInfo` begin-effect slot before the switch.
- `Zc_Ack_Touseskill` prints `MsgStr` ids and, for cause 0, sends window message 3. `MsgStr`, `m_isSkillFail`, and window message 3 are not in src. The handler still uses `ResolveSkillFailMessage`. Causes 4 and 10, and cause 0 for skills other than 1, 27, 50, and 52, return without text when `m_isSkillFail` is not 1; the port does not have that flag.
- Resolved lifecycle 2026-10-25: message 84 removes the begin-spell attachment and sends 24. The world retains ownership until its next sweep; `OnProcess` now returns 0 immediately for a missing master, and destruction detaches its primitives for world reclamation.

## Continuation findings — 2026-10-25

- The plan originally asserted 733 dispatch labels, including 456 in the main dispatcher. Structural extraction of `HighPriest.exe.c`'s `switch(v6)` gives 416, `Ref/RagEffect.cpp` OnProcess2 gives 73, and OnProcess3 gives 204: total 693. - `Ref/RagEffect.cpp` contains two definitions named `OnProcess2`: the first is annotated `Original Signature: OnProcess`, the second `Original Signature: OnProcess2`. Index extraction now selects the matching signature annotation and records file-absolute lines.
- The old generator gave a five-field TSV row a four-field header and carried pending cases past `goto` exits (e.g. Coin 10 also acquired Endure 11; case 1 acquired Hit3 instead of the shared Hit2 target). The replacement indexes shared labels, includes inline-only cases, and excludes nested level cases and gate switches.
- `Zc_Sound` and `ProcessPlayWave` use **player minus actor**, with y zero; preserve this source-specific sign despite the common effect-minus-player convention in plan section 1. The first sound of repeat action 1 is at (0,0,0); subsequent sounds use the linked actor. Cancellation deletes the first matching name regardless of AID and does not stop an already playing sample.
