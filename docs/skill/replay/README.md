# Skill packet replay fixtures

Each scenario is UTF-8 TSV with three columns: packet opcode (integer, `0x` prefix accepted), raw packet bytes as hex, and a human-readable comment. Blank lines and lines beginning with `#` are ignored. The opcode is repeated in the row so the runner can check that the metadata matches the little-endian packet header.

`actor_action.tsv` is a 29-byte `0x008A` framing/router fixture used by the standalone smoke test to exercise production `TryReadPacket`, `CGameModePacketRouter`, and `HandleActorActionNotify` logic against lightweight doubles, including malformed and unknown packet rejection.

`bash5.tsv` is a 31-byte `0x0114` skill-damage packet for skill 5 with source AID 1, target AID 2, level 5, one hit, and action 5. `double_strafe46.tsv` is another 31-byte packet for skill46, with damage200, level5, div2 and action9. `fire_bolt19.tsv` carries skill19, damage100, level5, div1, and action4. `heal28.tsv` is a 15-byte `0x011A` no-damage notify packet for Heal28 and value199; it checks effect7 and message88. `sonic_blow136.tsv` uses action9 and division4, checking four target hits plus three self animation WBAs. `asura_strike271.tsv` checks action4's immediate target presentation (WBA field message39, effects0/−1) and the attacker's state2 transition. The production-linked runtime tests instantiate the real game mode, world, session, player, and target actor, register the client's default packet routes, dispatch raw packets, poll `ProcessWillBeAttacked` at nominal 24 ms intervals, and compare runtime logs. Delivery assertions use elapsed `timeGetTime` from the same clock as WBA scheduling and allow one measured polling interval plus clock granularity.

These are the first six WP2 skill scenarios. The remaining three WP2 scenarios and richer actor/cell/job fixtures remain pending. Replay-only event traces capture `LaunchEffect`, `PlaceEffect`, `PlayWave`, `SetState`, `SendMsg88`, and `UnportedEffect` calls; WBA logging also covers message108 events that do not use `HandleAttacked`.
