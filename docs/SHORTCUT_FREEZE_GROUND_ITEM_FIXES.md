# Shortcut rows, frozen animation and ground items — 2026-11-01

Shortcut row identity is now fixed: row1=slots0–8, row2=9–17, row3=18–26. Previously both hotkeys and double-click activation changed the session's selected page before using a page-relative slot. The native and Qt row mappings then displayed `(selectedPage + row) % 3`, rotating every row. Both activation routes now send an absolute index, the receiver looks it up as absolute, both renderers map rows directly, and wheel events no longer rotate banks. Drag/drop, tooltips and configured hotkeys use that same slot identity.

Frozen enemies already receive `m_isMotionFreezed=1` in `SetAttrState` and `CRenderObject::ProcessMotion` respects it. However, the billboard selectors independently derived their motion from time or walking distance. `ResolveTimedMotionIndex`, `ResolveSpriteMotionIndex` and the player walk selector now preserve/clamp the actor's current motion when frozen; the movement-state animation update also respects the freeze flag. Source anchor: Ref/GameActor.cpp (`CRenderObject::ProcessMotion`), whose finished/frozen gate preserves the current motion. Death/status transitions retain their existing state handling.

Ground-item label picking previously projected `m_pos`, whereas rendering projected ground height plus the drop offset. Added `CItem::GetBillboardPosition`, shared by rendering and picking/labels. Bounds now use the texture's opaque sprite rectangle instead of transparent composition padding. Qt's item label uses `centerX`/`bottomY`, measured by the actual QML text, replacing the generic cursor-style +12/-26 offset.

Ground-item flash evidence: `HighPriest.exe.c:400251` and `Ref/Item.cpp:57` (`CItem::OnProcess`, address0x5ce5e0) compute `double(timeGetTime()-m_stateStartTick)*0.041666668` and enable single color when the integer tick modulo92 is90 or91. Ref/Item.cpp constructor sets single color to -256 (0xFFFFFF00). `HighPriest.exe.c` CRenderObject::RenderBody uses the single-color value for the sprite color. Restored this exact cadence in the item processor and yellow vertex-color override in its render path. This is a brief repeating color flash, not a guessed scale/bob animation. Existing drop-motion behavior was left unchanged.

Focused validation: `PresentationRegressionTests.cpp` compiles the production timed/distance sprite selectors, item processing and render-position helper, item screen rectangle helper, and shortcut indexing/activation. Checks cover frozen frames across several timestamps/moving flags, normal animation after unfreezing, frame clamping, drop-offset/opaque item bounds, two complete flash cycles, 27 fixed slots with repeated activation, and collapsed-row bounds. All pass; removing the freeze guards makes the regression fail. Additional source checks verify Qt mapping, absolute hotkey dispatch and centered label wiring. MinGW Qt build succeeded. Full parity test configuration has the pre-existing actor-lookup extraction problem documented in earlier validation notes; no full-suite claim. Runtime appearance and combat acceptance remain with the user.
